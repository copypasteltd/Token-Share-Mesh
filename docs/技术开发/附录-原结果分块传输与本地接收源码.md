# 原结果分块传输与本地接收源码细则

R026 CODE_FIRST / DC-001—045。以下是已写入活动目录的生产与测试**源码**，未编译、测试、迁移或运行。此保存点不代表全量代码开发完成，不开放测试门槛。需求仍沿用原 C2C 合同、NB04 设计、56 个任务和 222 个未收口子项。

该档仅用于 **PLAINTEXT / STANDARD** 已完成文本结果。平台能解密内容；提供方推理期间也可接触内容。平台数据库与买家缓存的磁盘加密属于静态存储保护，不能冒称平台盲转或硬件保密。公开模型请求继续遵守 OpenAI Chat/Responses 或 Anthropic Messages；下述控制和内容辅助协议不作为新的私有模型调用格式。SDK 入口、提供方持续接单与自动交付编排、独立可信计量生产端、E2E 和媒体仍待完成。

## 角色、边界和使用顺序

1. 原提供方通过已有批准清单、签名租约和共资源监督器完成一次推理；原结果落入任务级加密缓存。读取完整 EOF 时记录原输出字节 SHA-256、长度、数量候选、完成原因和原设备签名声明。设备报告的 token 数量仍不是可信计量。
2. 宿主持原 `PreparedExecution` 显式调用 `PublishResult`。先通过既有原交付报告接口登记声明，再重新读取**同一个缓存结果**分块上传。此方法不调用 Start/Submit，不开新模型，不续租或延长 GPU 锁。当前未接成自动接单守护进程，不把库入口当成完整产品入口。
3. 平台 `Begin/Put/Seal` 锁定原订单、任务与交付身份；每块加密保存。Seal 逐块解密并核对完整 UTF-8、总长、连续序号和整段摘要，成功后标 READY。读取、上传完成均不自动签收或扣费。
4. 原买家在 React/Taro 或 React/Vite 的原订单任务页显式获取读取授权。服务绑定当前买家账户、会话、版本、角色、原卖家及唯一结果，签发最多 5 分钟的只读凭证。页面仅在内存显示；小程序仅在用户点击后复制。页面不自动安装/运行程序，不传递账号 Cookie、账号 token、上游密钥或提供方私钥。
5. 买家把读取包保存到本项目 `runtime/` 内的明确文件，交给 `p11-buyer receive`。接收程序只做固定 GET，最多四块并行，完整核对后写入原有 AES-GCM 本地缓存，再导出用户明确指定的结果文件及六字段核对回执。导出文件包含明文，属于用户主动导出；回执不包含输出正文或读取秘密。
6. 买家实际查看结果，将回执粘回原任务页后明确接受或拒绝。接受仍走既有版本竞争、原声明摘要及唯一接受事务；本地回执是核对元数据，不是防篡改用户证言、独立计量、E2E 签名或支付资格。

## 使用说明（仅说明源码入口，当前不运行）

平台可选配置 `P11_RESULT_CONTENT_KEYS_FILE` 指向本项目 runtime 内的私密钥环文件；profile 为 `P11_RESULT_CONTENT_KEYS_1`，字段 `current_key_version` 与 `keys`，每钥为32字节随机数的无padding base64url。不要把文件、真实钥、读取包、输出或凭证提交到仓库。与独立计量/身份/设备签名配置分别管理；未配置时相关接口503，不制造默认可售能力。

集中验证阶段编译原生 `client/cmd/p11-buyer` 后，使用示例（示例中的文件由用户明确提供，不包含可用凭据）：

```text
p11-buyer receive --packet runtime/buyer/read-packet.json --cache runtime/buyer/cache-one --output runtime/buyer/result.txt --receipt runtime/buyer/review.json --format raw
```

从项目根或其子目录执行；cache须新建空目录，已有遗失钥密文不复用；output/receipt须新文件。`--format protocol` 是默认值，只按原清单渲染既有协议及其有界上限；`--format raw` 导出原文本。结果先完成整段核验，再写明确导出文件；导出失败不生成成功回执。恢复只读原远端结果，不触发推理。UI签收窗口仍遵守原任务期限与完成后120秒的原规则，30分钟内容保留或5分钟读取权不能延长签收窗口。
