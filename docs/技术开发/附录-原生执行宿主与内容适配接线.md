# 原生执行宿主与内容适配接线

R020在R019受限交付库之上增加持久原生宿主：独立公钥和原订单/本机内核批准、网络之前落盘的原领取命令、有界内存输入票据、原执行收件箱的一次提交接线、原清理凭证投影。它是可嵌入的原生Go库及初始化/状态命令。真实模型适配器、tokenizer、输出回传、可信usage、执行ACK/续期、完整守护进程和SDK调用监听仍待实现。

当前仅支持已实现的三种文本profile及`PLAINTEXT/STANDARD`。元数据加密不等于正文E2E，也不能使设备所有者看不到内容。NB04五张约束图、React/Taro小程序优先、React/Vite Web、具体手机型号、GPU小时和输入/输出分别M token继续适用。本轮不改变95项权威操作中37项HTTP注册，不新增平台PostgreSQL迁移。

## 状态、存储和调用顺序

| 宿主阶段 | 已持久事实 | 后续允许动作 |
| --- | --- | --- |
| CLAIM_PENDING | 原编号、设备、capability、设备version | 只复用原claim，等待/恢复；不得另开同能力命令 |
| CLAIMED | 原lease元数据 | 获取同一原manifest并完成独立批准与验签 |
| VERIFIED | 原lease与通过验证的manifest | 受限获取输入并形成内存票据；尚无原生Receive |
| SUBMITTING | 进入原执行收件箱前的持久意图 | 原收件箱决定是否还有唯一首次Submit权；未知只查原号 |
| SUBMITTED | 本地原后端映射已记录 | 监督原进程/原请求停止清理，不表示平台ACK、结果接收或计费 |
| CLEANED | 原执行RECEIVE/inbox精确清理凭证投影 | 禁止再Prepare原命令；保留历史，才可开始同cap下一命令 |

`state.enc`新增可选host锚点；旧节点不配置宿主仍可打开，旧执行DDL不变。新`host-schema.sql`独立包含metadata/configuration/commands三表及cap/phase索引，原字段为hint，密文中的相同字段才是经认证事实。不是平台65表模型的一部分。

库调用顺序：

```text
Open enrolled node → OpenExecution → InitHost/OpenHost
  → Begin(original claim) → Prepare(original manifest + bounded input)
  → NewSupervisor(trusted exact HostKernel)
  → node.RunSupervised(ctx, supervisor, safeStatusCallback) / wait Ready
  → ticket.Start(ctx, supervisor) → ticket.Close
  → cancel supervised loop / wait completion → ReconcileCleanup(original command)
  → Host.Close → node.Close
```

实际集成前先恢复父节点原待定控制写，核对当前控制身份及非DRAINING/REVOKED，再允许新的Begin/Prepare。`RunSupervised`负责将控制撤权/排空和终止错误传给监督循环；终止后禁止不经状态重核重新运行。库中的裸`Supervisor.Run`仅是隔离执行监督入口，单独使用不能替代控制生命周期。正常长期运行的宿主循环/任务批次编排仍待实现。

未开始的监督器也须用已取消上下文Run一次，让其完成原owner恢复/退出并关闭Done；不能创建后静默丢弃再换登记。若Run/RunSupervised返回未完成清理，保留原盘状态及失败证据，恢复同一原适配器，不重新提交原正文。本轮宿主测试单独使用Run验证合成后端；父节点控制撤权耦合由既有`TestNodeControlDrainStopsSupervisedOriginalOwner`验证，不将两者冒称完整生产守护进程组合通过。

## 配置来源与本机使用

先由提供方完成原有init/enroll和execution-init。CLI配置文件放忽略的`runtime/`内，含公共issuer pin与显式原订单/内核规则，不含issuer私钥、上游token、Prompt或模型内容。公开仓库不提供可冒用的生产批准/资格文件。

```powershell
Get-Content -LiteralPath 'runtime/host-approved-orders.json' -Raw -Encoding utf8 |
  & '.\runtime\bin\p11-node.exe' host-init --state 'runtime/node'
& '.\runtime\bin\p11-node.exe' host-status --state 'runtime/node'
```

上述路径由用户在本项目runtime下选择；命令不自动创建或下载配置文件。`--state`须与原enroll/execution-init为同一目录。host-init已经成功或中途写入锚点后，不重复初始化；用host-status或原命令恢复，文件缺失时保留并处理故障。提供方不能仅凭修改这一配置为平台生成设备资格、模型许可或资金授权。

配置顶层为`profile_id / issuer_ed25519_public_key / approved_orders`；每条含`physical_resource_digest`和`original_approval`。后者字段如下：

| 字段组 | 字段名与含义 |
| --- | --- |
| 原交易与主体 | order_id、route_id、seller_id、device_id、resource_id、capability_id、contract_hash |
| 模式与内核 | mode=PLAINTEXT、privacy=STANDARD、kernel_environment_ref、kernel_environment_digest、engine_kind、engine_release、model_digest、recipe_digest（可空） |
| 协议上限 | request_spec={protocol_profile_id、public_model、max_output_tokens、stream}、input_token_limit；protocol_profile_id须为P11_CHAT_TEXT_NATIVE_1/P11_RESPONSES_TEXT_NATIVE_1/P11_MESSAGES_TEXT_NATIVE_1，不能填任意端点或别名 |

准确JSON字段以[Approval](../../dev/src/client/protocol/devicecontrol/delivery.go)、[HostConfig](../../dev/src/client/node/host_policy.go)和[三文本协议常量](../../dev/src/gateway/core/types.go)为准；strict JSON拒绝重复/未知字段。规则更新需要后续受审核变更流程；当前不提供覆盖已有批准/锚点的命令。
