本附录承接KE端点密钥和IC原密文托管。当前补齐的是账户/设备对公开端点元数据的登记、发现、轮换、撤销和客户端原请求恢复。它不把现有PLAINTEXT/STANDARD路由、准备或执行租约放开为E2E。

## 1. 模块与信任边界

| 模块 | 责任 | 不获得的权限 |
|---|---|---|
| shared/endpointwire | 原公钥bundle、旧身份签名轮换、JCS/域分离/Ed25519验签 | 不引入vault、sodium、私钥、解密器或模型内核 |
| shared/endpointdirectory | 当前目录Record/Page及公共请求DTO | 不是独立信任pin、内容私钥持有证明或业务授权 |
| internal/endpointregistry | 当前账户角色/设备绑定、事务与原历史 | 不解密内容、不收付款、不签执行租约 |
| HTTP EndpointDirectory | 六个独立控制接口及同DB宿主装配 | 不复用旧/recipients的另一套JSON含义 |
| node及directory CLI | 从原本机钥库取公有数据、AEAD持久原意图再发布 | 不自动造钥、换端、重签轮换、开启内容端口或启动GPU |
| 原端点vault/crypto gateway | 原OS秘密根、独立核验、实际密码用途和本地撤销 | 不将平台注册成功当作独立核验完成 |

平台公钥目录只证明“某个当前登录账户或逐请求签名设备有权登记这些公开字段”。自签名bundle证明身份私钥对元数据的签名，不证明X25519内容私钥实际持有，更不证明该设备能执行模型。下一阶段E2E授权必须另做独立端点核验、内容钥使用/执行组合验证和当前资金/合同/资格检查。

原端侧Bundle/PublicKey/Transition改为公共类型别名；签名字段、JCS字节和两个签名域保持原值。公开SigningMessage只返回待签公开元数据，不是签名服务，也不暴露私钥。各用途和跨轮换版本的旧ID/公钥/指纹复用会被拒绝。历史已有正确签名的具体互通向量仍须在集中验证阶段实测。

## 2. 公开元数据协议

| 对象 | Profile | 上界与强制内容 |
|---|---|---|
| Bundle | P11_ENDPOINT_PUBLIC_1 | JCS≤8192字节；owner、endpoint、role、规范十进制版本、not_before/expires_at、三个分用途公钥字段及身份签名 |
| Rotation | P11_ENDPOINT_ROTATION_1 | JCS≤12000字节；previous_bundle_hash、完整next_bundle、recorded_at、旧身份签名 |
| Directory Record | P11_ACCOUNT_ENDPOINT_DIRECTORY_1 | recipient_id=content key ID，原bundle/hash、当前状态、必要的前驱/原rotation/hash、independent_trust_required=true、replayed |
| Page | 同目录Profile的Record数组 | 固定每页2条、单回复≤65536字节；next_cursor字符串或null |

BUYER须拥有独立身份Ed25519钥、内容X25519 sealed-box接收钥及receipt Ed25519钥。SELLER只携带身份和内容两种钥，不能带buyer receipt。公钥固定32字节无填充base64url，指纹是解码后公钥SHA256；签名是64字节无填充base64url。

签名有效窗使用严格规范UTC字符串，最长90天。新登记/新轮换须在数据库当前时刻有效。完整签名时间的纳秒值保留在原字节中；数据库expires_at只存向下截断至微秒的投影，读取时重新核对。SQL的时间转换允许最多1微秒解析舍入差；该结构性比较不代替Go对原纳秒时间的检查。

目录状态并不代表执行资格：

| 保存状态 | 含义 | 后续新授权处理 |
|---|---|---|
| ACTIVE | 当前最新登记且未显式撤销 | 仍须检查原时间、独立核验、原合同及其他授权 |
| RETIRED | 已有连续签名的后继 | 不能作为新请求当前钥；旧任务若使用须另有明确原授权 |
| REVOKED | 指定版本已明确撤销 | 不得复活或退回旧版本 |
| EXPIRED | 查询时对有效窗的计算投影 | 不写回替换历史；不能当作当前钥 |

公开hash只用于公钥元数据和密文对象的完整性，不新增prompt或生成内容的公开明文摘要。

## 3. 账户、角色与设备规则

| 操作主体 | 允许范围 | 必须复查 |
|---|---|---|
| BUYER当前账户session | 本人BUYER端点登记/轮换/查询/撤销 | 当前用户版本、session、BUYER角色、scope及owner |
| SELLER当前账户session | 本人SELLER目录查询及明确版本撤销 | 当前用户/session/SELLER角色；不能代设备首次登记或轮换 |
| 原设备逐请求证明 | 本人SELLER且endpoint_id=该device_id | 当前用户/SELLER角色、卖家状态、原设备auth指纹、请求nonce及scope |
| SDK API key | 不管理本目录 | 不能冒充买家本机端点配对或设备身份 |
| 原订单当前BUYER session | 指定原卖家/原设备公开端点发现 | 原buyer、合同hash、实际seller、原设备集合与当前身份 |

新SELLER登记/轮换要求卖家APPROVED。公开身份/内容用途不得复用本设备控制认证公钥，按已核验设备auth指纹检查；读取原记录也重核这一分离。设备查询/撤销允许现有身份体系认可的APPROVED/EXITING，不修改设备行。当前有SELLER角色的账户session可以撤销本人指定版本，以便设备遗失或退出时切断后续公钥使用。

目录不处理重装/转让后身份自动继承。原设备认证指纹变化时不能把原轮换链嫁接到新认证身份。旧钥过期、丢失或额度用满的显式独立恢复流程仍待实现；当前失败关闭，不允许清空历史后重新version1。

## 5. 事务、幂等与锁序

1. 严格解码公共请求，验证公钥自签名和角色形状；不得接收private_key、prompt、回调URL或模型正文。
2. SQL事务内先锁当前用户/凭据，再核当前角色。设备直接取SHARE并保持现有用户→角色→卖家→设备锁序，不先SHARE后升级设备写锁。
3. 当前授权检查发生在幂等记录查询之前，旧幂等结果不能绕过撤销session/设备/角色。
4. 锁原幂等记录及owner advisory后检查原端点、容量、数据库时间和状态。
5. 首次登记同事务保存recipient、原bundle和全部用途claim。新version1不能替代已有端点；完全相同原bundle可查回原号。
6. 轮换锁原前驱，核旧身份签名及完整next；先标旧RETIRED，再插入唯一原后继及claim。任意冲突整事务回滚。
7. 已有后继时只接受同原transition/hash和同原next；不再造新钥、不分叉。原幂等号或另一恢复号都不能改证明。
8. 指定版本撤销核expected_bundle_hash，原recipient和目录REVOKED/时间同事务提交；不隐式撤整链。
9. 幂等安全结果只保存recipient_id引用。提交后按当前授权重新读取原公钥状态，再回应replayed；不会将曾经ACTIVE的快照带回。

事务内无HTTP、内核或模型调用。遇到未知提交，调用方保留原对象与原号；不能认为失败后新造替代端点。数据库声明和历史验签链最多32层，所有服务查询都对本人或原订单严格定界。

## 6. 原C2C订单发现

原订单查询仅允许真实当前BUYER账户session。必须核对订单buyer、seller不自购、原contract_snapshot/hash、E2E/PLATFORM_BLIND、原deadline，以及WAITING_PAYMENT/READY/FULFILLING/DELIVERY_PENDING中的当前状态。

目标公开端点必须属于原seller且为SELLER。device_id同时出现在原DeviceIDs与原Bindings中，不能用其他个人卖家、其他手机号设备、同卖家未确认的新设备替换。复查原seller的ACTIVE账户、当前SELLER角色、APPROVED卖家及原设备认证指纹；撤销/隔离/退役或身份更换都失败关闭。

该查询可供付款前公开身份发现；它不校验或消费付款、不预留GPU、不放行执行。平台返回的自签名公钥仍需买家通过独立渠道核验。目录把历史RETIRED/REVOKED/EXPIRED事实如实返回，并不允许使用这些版本创建新E2E授权。

## 8. 客户端原请求发布

客户端共享原node的OS保护master和进程级单写者锁，不增加虚拟化。管理在可变控制loop/Host/租赁会话启动前进行，不能并发调用Step。它不调度GPU或加载模型。

publish只接受原本机钥库中本人SELLER的bundle_hash。版本1发布初始bundle；更高版本读取OriginalLocalRotation保存的原公共证明和原前驱content ID，自动使用rotations接口，绝不再调用RotateLocal造新证明。

先把ENDPOINT_REGISTER/ENDPOINT_ROTATE/ENDPOINT_REVOKE、resource_id、原正文及随机原幂等号写入既有node AEAD pending；保存未知不能继续发送。网络错误、超时、权限变化、坏的成功回复或未确认结果都保留pending。通用recover和directory-recover重新签设备nonce，同时保持原正文、URI及幂等号。

成功回复需要完整公开bundle验签/hash及原owner/SELLER/device/recipient绑定。撤销还核REVOKED及原expected hash。只有确认后再保存pending清除；本地保存未知仍需重开查原状态。原请求重放若已过期/退休/撤销，会带回其当前事实，不能据此自动重新发布或启用内核。

| CLI | 标准输入（元数据） | 目的 |
|---|---|---|
| directory-publish --state 原绝对路径 | {"bundle_hash":"原crypto-public返回的bundle_hash"} | 初始或原证明轮换发布 |
| directory-revoke --state 原绝对路径 | {"bundle_hash":"明确原版本hash"} | 撤销平台指定公开版本 |
| directory-get --state 原绝对路径 | {"recipient_id":"原content-key-id"} | 当前本人指定记录 |
| directory-list --state 原绝对路径 | {} 或 {"cursor":"上一页原cursor"} | 本机设备自己的有界列表 |
| directory-recover --state 原绝对路径 | {} | 仅恢复当前原目录pending |

上述是使用说明，当前未执行任何命令。crypto-public增加公开bundle_hash方便选取，未添加秘密字段。推荐顺序为原设备登记→crypto-init一次→crypto-create SELLER→crypto-public→directory-publish；轮换先crypto-rotate保存原证明，再crypto-public选新hash并directory-publish。网络结果未知时先recover，不新造钥或丢弃pending。

目录撤销只对明确公开版本生效。若本机也要停用私钥，须调用既有crypto-revoke并完成其活动使用取消/实际join；公开目录确认不能冒充本机清理或密钥销毁。撤旧RETIRED版本不会自动撤其后继；需分别明确处理。
