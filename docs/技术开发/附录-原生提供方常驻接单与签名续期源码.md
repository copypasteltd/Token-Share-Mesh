## 1. 范围与真实入口

增加 `p11-node host-run --state <已登记的私有状态目录>`。配置只从有界标准输入读取；运行前必须已完成原设备登记、execution-init、host-init 和独立内核/原订单批准。入口不自动初始化、不下载/更新可执行文件，不将 PAIRED 设备改为 ONLINE，不办理支付或卖家资格。

本分支运行 Windows/Linux 的 LLAMA_CPP_NATIVE 文本常驻环境，使用现有受控管道 worker、真实 GPU 身份核对、共享物理门闩和加密结果托管。当前只接 PLAINTEXT / STANDARD；LM Studio、ComfyUI、LMA 的对应常驻业务编排、E2E 盲转和实时 SSE 继续作为同一完整范围内的待办，不从该分支推导已完成。

## 2. 持续运行与低开销约束

`RunNativeProvider` 在启动控制循环前打开原 Host、校验完整安装和本地主人批准，使用同一物理资源的 MAINTENANCE 代次预热模型。预热不需要先领取一项执行任务，避免领取后才加载模型耗尽 45 秒首租约；独立的原订单批准仍是必需条件。原生 READY 必须匹配 UUID、PCI、模型、模板、环境和资源。未知预热保留原 owner。

一个 Host 同时只有一个原生常驻环境和一个监督器。任务结束保留模型驻留，清理针对原任务上下文；只有显式关闭会话才卸载该环境。没有第二份模型、内存盘、公共本机内容 HTTP 服务或虚拟化层。运行周期、内存及显存均尚未测量。

`NewResident` 冻结已安装的环境/能力到后端的映射。后续任务必须由 Host 再核对原批准和有效原租约，才能把其 manifest 摘要登记到同一后端。登记不创建执行 guard；`Receive → BeginSubmit → SubmitInput` 仍负责一次提交和双围栏。没有环境通配、后端替换或来自任务的可执行路径。原 `New` 精确登记模式不自动获得扩展能力。

动态 manifest 登记使用读写锁，最多 4096 项，满额拒绝新登记，保留原清理映射。Host 命令日志原有上限为 4096，结果适配器原有元记录上限为 1024，原生 worker 的自身上限继续生效；达到任一上限须保留原状态并停止准入，不驱逐旧记录绕过一次性约束。自动归档/容量轮换和崩溃遗留目录回收仍待补齐，不声称无限期连续运行。

## 3. 控制心跳与接单

只有一个 goroutine 调用可变的 Store 控制方法。协调器通过有界通道消费状态副本，不并发读取 `Store.Status()`。结束时先取消并等待控制循环，再关闭原生会话和原 Host，最后释放节点钥、数据库和 OS 单写锁。

关闭的 10 秒是发起停算/关闭的等待预算，不能充当生命周期已经结束的证据。监护循环把原提交的元数据阶段和实际适配器调用都纳入 owner 计数；禁止新调用与开始等待共用同一把锁，只有全部原调用返回才关闭 `Done`。提供方协调器同时等待真正的 `runDone`、Run 包装 goroutine 和原生管道/进程 `Join`，覆盖 Close 抢先启动取消态监护循环的竞争情形。Host 单独关闭也执行同样的真实 join。适配器违背取消约定时保留原 OS 锁、账本和钥，不能为了准时返回释放它们；这不生成 STOPPED、CLEANED 或资源 FREE。

普通 `run` / `heartbeat` 仍只报 UNKNOWN。`host-run` 的资源状态来自实际运行的同一会话和原本地账本：监督器就绪、当前环境仍存活且已登记资源全部 FREE 时才报 IDLE；任何受管理的本机自用、维护、租赁、任务或未知 owner 都报 BUSY 或 UNKNOWN。该状态不检测平台外任意进程的全部 GPU 活动，不等于硬件资格、ONLINE 转换、清锁或可信用量。

原心跳在发送前持久化。响应未知时重发完全相同的序号、资源状态、正文和幂等键，每次生成新设备证明 nonce；不会重新采样后改写该条心跳。控制暂时失联暂停新准入，不能延长执行租约；当前撤权、DRAINING、REVOKED 或永久控制错误触发停止与收尾。

新 claim 的键、设备版本和能力先写入认证加密日志。没有任务的领取 404 只在尚未领取过租约的 CLAIM_PENDING 上视为原空轮询，保留该键继续查询；不作为授权证明。其他授权错误仍关闭准入。设备版本改变不会改写原 claim，也不自动生成替代键；对应显式版本恢复/原空 claim 退役流程仍待补齐。

原任务验证失败不改选卖家、不更换设备、不降低模式。正文仍只在 RAM 票据中，使用后清零。SUBMITTING 一旦持久化，重启或回复未知只能查询原收件箱、结果状态和清理，不再次调用 Start。

## 4. 进度、签名续期及日志顺序

每项原命令保留一个有界进度槽：原写入、当前回执、是否应用、固定处置码、最近实际应用的签名租约。原 claim 的 Lease/Manifest 字节不被续期覆盖。进度正文不含 prompt、输出、stop 字符串、内容钥或本机路径。

| 顺序 | 持久事实 | 允许的下一动作 |
|---|---|---|
| 1 | 冻结原 lease/fence/正整数 sequence/phase 与固定键 | 发送原请求；未知只重发此项 |
| 2 | 回执经形状核对；续期经独立 pin、原清单及原 owner 核对 | 保存该原回执，仍不能凭形状执行 |
| 3 | 验证当前时间、原 live guard、递增 revision、原资产/环境/硬截止和双围栏 | 对原 Hold 调用持久 Renew |
| 4 | Renew 独立回执及当前元数据提交 | 保存 RENEWED / RECORDED 等应用状态 |
| 5 | STOP、本机失败/取消、过期或 live guard 丢失 | 撤销原执行权；等待真实停算和清理 |

进度键由域隔离的原 command ID 和 sequence 派生，避免最长原 ID 加后缀超限。序号为规范正整数，最大 9223372036854775807，满额关闭、不回绕。未知 RUNNING 回执不会因调用者后来要求 FAILED 而改写；先恢复原写入，下一次调用才能发送新阶段。

续期严格保留原 job/attempt/order/seller/device/resource/资源代次/能力/manifest/环境/合同/输入资产/envelope/not_before/硬截止/job 围栏。签名回执写入和续期应用之间崩溃时，只能重放同一续期键；重启后的账本没有原内存 guard，不能用旧回执复活执行。过期、未来尚未生效或无法应用的签名续期记为 NOT_APPLIED 并停止原任务。

STOP 只撤销执行权，不释放 GPU。FAILED/CANCELED 在发网络请求前即请求停止本机原 Hold，即使平台回复未知也不继续算。STOP 和本机终止状态不能通过再次报告 RUNNING 开放准入；结果补传保持独立授权。

## 5. 原接收摘要与续期摘要

原 `CommandStatus` 把 inbox 当前摘要与 RECEIVE 摘要视为相等，合法 Renew 改写 inbox 后会导致原清理恢复失败。现在分别返回：

| 字段 | 定义 | 用途 |
|---|---|---|
| MetadataHash | 最初 RECEIVE 的不可变摘要 | 对照原 Host.Lease、原接单和原清理 |
| CurrentMetadataHash | 当前 inbox 签名租约字节摘要 | 核对当前元数据及其独立 RENEW 回执 |
| Revision | 当前签名租约 revision | 元数据恢复显示，不授予执行 |
| CleanupHash | 原实际清理凭证摘要 | CLEANED 时必须存在 |

当前原文摘要必须吻合；如果不同于初次 RECEIVE，必须存在同 lease、同当前摘要的 RENEW 回执且 revision ≥ 2。没有修改原 DDL、旧回执或数据库 source 元数据，也不将读取状态视为重新签发 guard。

## 6. 输出、清理与缓存回收

一次 Start 后启动一个有界生命周期的输出发布协程：读取原加密结果托管，生成原签名交付声明，上传分块并核对总摘要和结束信息，最后取得 READY。网络未知重试同一原结果，不重新生成 result ID、签名或推理任务。

协调器同时维护原任务进度和清理。原计算停止后，监督器只凭同 owner/generation 的真实停止、撤权、工作区清理凭证完成本地 CLEANED；原设备再补传签名 cleanup。平台进入 WAITING_BUYER 后发来的 STOP 不取消已合法存在的输出传输。输出完成不会自动签收、产生可信 usage、完成卖家结算或释放退款预算。

`DiscardPublished` 必须同时看到原结果 READY、原 CLEANED、cleanup ACK、签名原清单和原 RECEIVE 身份后，才销毁本任务结果缓存钥及原文件并记下 `local_result_retired`。不会向当前 GPU 新 owner 发 Cancel/Cleanup；远端原结果和买家读权不受此本地回收影响。删除失败保留配额，关闭准入；正在关闭的 reader 等待原句柄退出，不宣告已回收。

进程重启丢失本地临时结果钥时，只能查询原远端内容状态：已 READY 可以恢复原状态；不完整内容、未确认旧进程、未知 owner 或丢失缓存不能转换为成功，也不能重跑。跨重启完整旧进程托管恢复、历史导入和崩溃遗留密文目录的安全回收仍是开放项。
