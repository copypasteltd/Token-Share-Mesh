# 原生宿主内核接线与输入驻留绑定

状态：R025 源码增量。承接 EH、NK、RC、NF、GI，覆盖 Windows 原生 llama.cpp 宿主库的受控装配和正文交接。本轮没有新增公开模型监听、平台操作或 SQL 迁移；节点 CLI 内容执行仍关闭。真实硬件验证与合成订单/签发/付款夹具分开登记，不能由局部通过推导完整平台交付。

| 编号 | 需求/约束 | 开发行为与验收边界 |
| --- | --- | --- |
| NH-001 | C2C 原合同 | 保持原卖家、订单、路由、设备、资源、能力、模式和隐私档；不由宿主替换卖家或提高执行权限。 |
| NH-002 | 配置决定权 | 提供方通过独立本机配置选择包、模型、模板、显卡及资源参数；买方只提交原合同允许的请求。来单不提供路径、下载地址、命令行或后端实例。 |
| NH-003 | 装配入口 | `Host.OpenNative` 接收独立的 `NativeInstallation`，拥有原生适配器、加密结果仓与同一宿主监督器；通用 `HostKernel` 仍仅供可信嵌入或合成夹具使用。 |
| NH-004 | 包与环境 | 先核验 PACK_1、完整文件白名单、独立包摘要及 ENV_2。损坏/未批准的包在模型启动和资源预占前拒绝。 |
| NH-005 | 批准规则 | 对同环境/能力的全部本机规则复核原资源、物理摘要、引擎类型及真实发行版、模型、模板、模式、隐私和上下文预算；不能忽略冲突规则。 |
| NH-006 | 显式整卡 | 宿主当前只接收显式 GPU 层数大于零的 NVIDIA 整卡 UUID/PCI 选择；CPU 独立适配器测试不构成本宿主 GPU 批准或降档兜底。 |
| NH-007 | 原命令先行 | 预热前必须已有持久准备命令，重验原签名与独立批准。过期历史元数据只支持原命令恢复，不恢复新提交权。 |
| NH-008 | 一个驻留会话 | 每个 Host 同时只拥有一个原生会话和冻结监督器；并发挂载或已有其他监督器时拒绝，不静默接管。多显卡并行、换模与完整安装器另行实现。 |
| NH-009 | 预热独占 | 模型加载前，对原物理资源取得 `MAINTENANCE` 代次；同卡 LOCAL/JOB/其他模式占用时拒绝，TTL 不能释放它。 |
| NH-010 | 原生启动 | 启动自有 worker，执行 PIPE_4；不调用现有 LM Studio、ComfyUI 或其他用户进程。Windows Job Object 与受控管道约束继续适用。 |
| NH-011 | 实际 READY | 原 PID、引擎/上游、环境、模型/模板、资源/能力、所选设备/层数、实际 UUID/PCI 和物理摘要必须全部匹配，才发布会话。 |
| NH-012 | 结束初始化 | READY 前从未提交 JOB、正文或推理上下文。只对同一预热 owner 执行停止/ABSENT/清理 CAS，结束初始化代次；不把它当作模型卸载、显存归零或推理清理证明。 |
| NH-013 | 预热未知 | 启动或 READY 不明，宿主关闭准入，保留原维护占用；关闭/重启/进程退出均不自动清除。明确恢复手续仍待完成。 |
| NH-014 | 驻留内存 | 模型在会话内复用，工作完成后释放原推理上下文及工作授权；模型本身可继续驻留，显存仍被占用。切换引擎或归还驻留内存须显式关闭会话；不承诺其他引擎同时享有全部空闲显存。 |
| NH-015 | 启动监督 | `NativeSession.Run` 运行原监督器，等待 `Ready`。未运行、正在关闭、已结束或其他 Host 的票据不得 Start。 |
| NH-016 | 原票据一次 | `PreparedExecution.Start` 先持久 SUBMITTING，再经原 inbox、资源门闩及双围栏提交。重复、未知或重启只查原号，不再投递正文。 |
| NH-017 | 后端不能换绑 | 活跃原生会话只接受该会话自己的结果后端、原物理资源和相同 Host；不能另注册通用后端绕过绑定。 |
| NH-018 | 输入两种摘要 | 清单 `input_ciphertext_digest` 始终是原加密资产摘要；它不是解密后正文的 SHA-256。禁止覆盖该字段或拿它比较明文。此条修正旧 NK-026 的混用表述。 |
| NH-019 | 内容信任起点 | PLAINTEXT/STANDARD 的正文来自配置好的认证平台 origin，服务端已经执行原 AES-GCM/AAD、版本化 HMAC 和 Preflight。客户端原始签名验证清单，未增加“签名明文摘要”的主张。 |
| NH-020 | 驻留校验凭据 | 已接受的 `AcceptedDelivery.BindPlaintext` 对至多 256KiB 的原始输入再检查期限、长度、协议、模型和参数，用有界私有副本生成 `PlaintextBinding` 并清除副本。 |
| NH-021 | 精确正文 | 凭据私有字段绑定原 Verified lease、原清单摘要、正文长度及正文 SHA-256；不能由任务 JSON 填充。原正文被同长度替换也必须拒绝。 |
| NH-022 | 不持久明文指纹 | 凭据只在本机调用 context 内传递；不加入 HTTP、SQL、任务表、内容地址、索引或日志。普通 JSON 序列化输出空对象，诊断格式固定脱敏，不公开摘要 getter。 |
| NH-023 | 跨监督上下文 | Supervisor 自己从已接受交付创建凭据，再显式移入其独立拥有的调用 context；不能只依赖调用方 context 值，因为实际执行上下文由监督器另行构建。 |
| NH-024 | 两次入口检查 | 结果后端 `CheckInput(ctx,...)` 与原生 `SubmitInput(ctx,...)` 均检查原租约、当前有效期、原清单及精确正文；缺失/零值/取消/异租约/异清单全部关闭。 |
| NH-025 | 权限不扩张 | 驻留凭据只是内容保管一致性检查；不授予资源锁、预算、付款、续期、重新执行或 E2E 身份。高级本机内存读取仍不在该凭据的防护范围。 |
| NH-026 | 发行标签语法 | 发行版本允许受限点分标签，如 `llama.cpp-v0.8.0-8642541b`；拒绝路径、空白、首尾点、连续点及超过128字符。通用业务 ID 语法保持不变。 |
| NH-027 | 后端编号语法 | 内核任务编号使用 `native_` 加有界会话/序号编码，满足原监督器字母开头的 ID 约束；不放宽 `ids.Valid`，私有管道仍视其为不透明标识。 |
| NH-028 | 原清理事实 | 实际 worker 同步停止、撤销任务并清理工作上下文后，才允许对原 owner/双围栏生成清理凭证；新模型进程不能为重启前 UNKNOWN 任务补造证明。 |
| NH-029 | 结果独立寿命 | 原显卡工作清理后，原票据可继续读取已保管结果；不能借后续显卡 owner 读取旧结果，也不能凭结果权限重新执行。 |
| NH-030 | 结果保管 | 会话拥有 RC 原结果仓：默认16项、每项8MiB物理上限、五分钟保留、独立随机钥与 AES-GCM 分帧；密钥不落盘，丢钥不能重跑。 |
| NH-031 | 协议交付 | 原生实际文本进入同一原结果仓，再由 textoutput 输出 Chat Completions、Responses、Anthropic Messages 的 JSON/SSE 六组合。停止原因、token上限、UTF-8 和有界写入保持原规则。 |
| NH-032 | token 是候选证据 | 本机计数和交付回执不自动成为可信 usage、最终 ACK、计费完成或卖家结算；这些生产链路另行验证。 |
| NH-033 | 显式关闭 | `NativeSession.Close` 关闭准入、排空原监督器、等待自有 worker 退出并撤销会话结果仓；Host 在关闭数据库前调用该生命周期。 |
| NH-034 | 未知不能释放 | 关闭失败、硬截止、kill 或进程退出不构成原任务清理；保留 UNKNOWN 占用，防止下一任务借旧状态释放。 |
| NH-035 | 不增加模型副本 | 不采用虚拟机、RAM盘、第二模型副本或本地 HTTP 明文最后一跳。Go 缓冲有界，额外输入副本最多256KiB且及时清除；性能/内存数字仍须独立实测。 |
| NH-036 | 常规回归 | 本轮增加宿主独立批准、会话、原票据、旧代次清理、发行标签及正文防替换测试；常规测试不启动实际 GPU 模型。 |
| NH-037 | 真实硬件范围 | 独立标签验证 Windows RTX3060/Qwen0.5B 原宿主到六协议组合、关闭等待/结果撤权及 busy/未知预热保留。签发、订单、付款、批准均明确为合成夹具，不能称完整交易联调。 |
| NH-038 | 失败留存 | 每次失败冻结原始事件、当时源、包元数据与自有 worker 摘要；修正后新编号重跑，不覆盖旧失败，不通过延长原提交/清理期限获得通过。 |
| NH-039 | 数据和展示 | 22份已发布 SQL 原字节保持；NB04、新售小时与输入/输出 M token双价、具体手机型号及个人卖家关系不变。当前没有新增产品页面或宣称小程序已连接真实推理。 |
| NH-040 | 未完成范围 | 生产签发/资金/可信usage/ACK/SDK/网络结果通道/崩溃恢复、Linux实机、LM Studio完整隔离、ComfyUI、LMA、E2E/LP/PE及性能仍分别开放；56任务/222子项和80/96完整验收不因本轮局部通过而完成。DEV-55延后。 |

本机正文的链路为：原受签清单与独立批准 → 认证 origin 原始输入 → 有界驻留校验凭据 → 原持久提交与双围栏 → 自有 worker → 原加密结果仓 → 原票据 JSON/SSE。这里没有平台盲转或买卖双方端到端内容钥；当前加密仓只保护本机落盘结果。

相关源码为 `dev/src/client/node/host_native.go`、`client/protocol/devicecontrol/plaintext.go`、`client/supervisor/supervisor.go`、`client/adapters/llamaworker/`、`client/results/`。验证入口见 [本轮编号与全部待办](../../dev/progress/R025-本轮实现与完整待办.md) 和 [范围化证据](../../dev/tests/evidence/R025-验证报告.md)；链接存在不等于验证通过，以报告状态及原始摘要为准。
