## 成熟JWS实现与一次凭证

| 编号 | 约束 |

| RN-011 | 选用[golang-jwt/jwt v5.3.1官方发布](https://github.com/golang-jwt/jwt/releases/tag/v5.3.1)，固定Go module sum及MIT原文（仅去掉末尾空行，原始/保留版SHA及处理说明均入锁）；锁见[rentalaccess/dependencies.lock.json](../../dev/src/client/protocol/rentalaccess/dependencies.lock.json)，实现见[access.go](../../dev/src/client/protocol/rentalaccess/access.go)。已下载依赖源码，未编译/测试；POC-10/安全资格仍未通过。 |
| RN-012 | 当前源码profile为`P11_RENTAL_ACCESS_EDDSA_1`，compact JWS、EdDSA/Ed25519；protected header只允许`alg=EdDSA`、`typ=p11-rental-access+jwt`、受信`kid`三项。拒绝none、HMAC混用、重复/大小写别名/未知字段、crit/jku/x5u和外部取钥。独立配置最多16个受信公钥，不能从回包自取信任。 |
| RN-013 | 整token不超过4096字节；header解码不超过512、payload不超过3072、签名恰64字节；base64url无填充且必须canonical。先严格JSON/字段/时间/上下文校验，再由成熟库验证签名与claims。所有失败返回固定错误，不回显凭证或库诊断正文。 |
| RN-014 | claims为profile_id、iss/sub/aud/jti、整数iat/nbf/exp、order_id/session_id/seller_id/device_id/resource_id、十进制字符串resource_lock_generation/terms_revision、terms_hash、environment_revision/kernel_environment_digest、manifest_ref/manifest_hash、scope、hard_deadline、mode/privacy。aud只允许一个预配置端点ID；只支持GPU_RENTAL/STANDARD。时间无宽限，nbf≤iat，exp≤hard_deadline的Unix秒下取整。 |
| RN-015 | Expected全部来自独立的当前原会话/端点批准状态及授权记录：TokenDigest必须匹配原rental_access_grants.digest（不能现场散列收到的Bearer后自取信任）；issuer/subject/audience/grant、原C2C元组、代次、terms/hash、环境/清单及硬截止逐项相等。过期、撤销、代次/环境/terms更换均不能只凭旧JWT通过。scope仅INVOKE/QUEUE_SELF/CANCEL_SELF/EXPORT_SELF，不给shell、RDP、主机管理员或任意节点安装权。 |
| RN-016 | Issued只允许TakeCredential一次，JSON及普通格式化仅输出安全元数据/固定遮蔽文字；数据库/幂等/事件只能存safe_claims、kid及token摘要，不存Bearer或可还原它的JWS签名。原grant提交后才可由响应写出首次凭证；响应丢失不得把旧Bearer存进可重放响应。 |
| RN-017 | Signer/Verifier复制外部钥材，关闭后拒绝后续操作；签名钥与内容钥分开。Go清空缓冲不被描述为不可恢复内存保证。Verified只保留安全claims/摘要，Allows同时要求当前时间有效；验JWT不产生资金资格、GPU票据、可用证据或成交事实。 |

## 持续控制确认与持久水位

| 编号 | 约束 |
|---|---|
| RN-018 | 控制profile `P11_RENTAL_CONTROL_ED25519_1`是元数据签名，decision只允许ALLOW/STOP；绑定原grant及token摘要、order/session/seller/device/resource、generation、terms/hash、环境/清单hash、hard_deadline、sequence、issued/expires和issuer_key_id。不得把它当新预算、付费附约或内容密钥。 |
| RN-019 | 签名消息严格按下方字段次序，以ASCII字段各加LF；签名外置canonical base64url。窗口identity为SHA-256(message完整字节 + signature字符串 + LF)，与JSON排版无关；原传输报文SHA可另存，意义不混用。控制签发钥必须与原grant的受信kid一致。 |
| RN-020 | expires严格大于issued，间隔最多45秒，且不能越过原JWT exp及hard_deadline；节点拒绝未来issued。普通HTTP Ack不产生执行活性。现有10秒D上报规划不改变，尚未注册新控制HTTP操作/复用任何未经更新的Ack结构。 |
| RN-021 | Window.Request先用SaveAnchor原子持久化当前序号，再允许外发；同一未确认请求重试仍用原序号。只有同序号、同grant/terms、原独立pin核验通过的新签名确认才推进窗口；重复已接受identity不重写、不重置计时。 |
| RN-022 | Anchor使用`P11_RENTAL_CONTROL_ANCHOR_1`，保存原grant摘要/session/generation/terms、requested/accepted水位、reply identity和明确stopped布尔。严格codec拒绝重复、未知字段、大小写别名、null、非canonical计数；codec本身不加密、不落盘、不提供防回滚证明。 |
| RN-023 | 恢复永不恢复旧ALLOW计时器；先持久写大于上次requested的新序号，旧已接受或未确认回复都不能恢复执行。水位到uint64上限关闭；磁盘提交失败/未知将内存窗口永久关闭，不能重新NewWindow冒充新会话。原加密owner journal、独立水位和物理门闩尚须接通。 |
| RN-024 | 有效期以签名绝对expires换算剩余时长，并在time.Now携带的Go单调时钟上锚定；另检测墙钟回拨。过期、当前Expected不符、STOP或本地Stop均不能被迟到新确认复活。Check只判断控制活性，实际入内核还必须检查scope、owner_session_id/代次、批准环境、原invocation inbox和串行执行槽。 |

### 原生端真实执行接线的调用顺序

1. 本人可信配置/界面先独立核实际安装包、GPU身份、环境/模型/recipe、原平台准备清单与connection/issuer，再构造`LocalApproval`并调用`VerifyPreparation`。不得由网络响应自动批准这些值。
2. 原节点已显式初始化执行库及租赁journal、登记实际物理资源后，用`PrepareRentalSession`保存加密批准并占原槽。重复准备只恢复原Hold；无grant/控制时不可调用内核。
3. 用`AttachControl`查询原设备原grant安全metadata，核独立公钥pin与完整原JWS；`RefreshControl`保存请求高水位、实际签名HTTP、验原回复并提交共门闩。每次入口同时核scope/window/物理owner。
4. 通过真实认证输入路径得到原密文摘要和规范正文/素材，`BeginInvocation`先持久一次提交意图。实际内核适配器消费一次ticket后仍须重核原授权/环境/输入与停止截止；这段内核适配和watchdog尚待接通，不能因此打开执行。
5. 查询、取消、清子调用始终用原请求/后端ID；全部子调用清理结束仍保留租赁父占位。到期/撤权后停止全会话并核真实清理，再以原回执与平台进行独立确认；平台最终owner/预算释放尚待实现。

### 本机接线与所有权
