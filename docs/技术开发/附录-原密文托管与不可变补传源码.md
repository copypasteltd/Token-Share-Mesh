## 保存什么以及它能证明什么

本地托管保存一份已经封装的 **BINARY_STREAM_1 原密文字节**，使网络断线后能读取同一份文件继续发送。文件中没有裸 prompt、原始生成内容、内容私钥或明文摘要。AEAD 元数据日志另存原始 descriptor、文件随机名、状态、字节数及原签名清单。

这不是 `LOCAL_SEGMENTED_1` 解密后再分段加密的媒体缓存；密文范围复制也不是 secretstream 随机解密。它没有平台账户认证、上传/下载授权、执行租约、模型执行、可信 usage、买家签收或资金资格。`READY` 仅代表完整原密文通过签名、结构、长度与密文摘要检查。只有另行 `ConsumeStored` 完成私有认证、FINAL、清单、真实 EOF 及 INPUT 预检后，才可以把输入交给可信消费者；消费者仍需取得独立业务执行权。

普通显卡所有者仍可能通过进程内存等手段观察解密内容；本地文件保护和密文托管不构成增强保密证明。DEV-32 继续关闭。

## 原身份与持久边界

复用原节点私有目录、单写者 OS 锁和已解锁 master，不建立第二套身份或锁。先初始化原 endpoint anchor，再明确初始化 ciphertext custody。节点先持久化新的 `cipher_custody_id`，之后才建立 `cipher-custody.enc`；anchor 已有但日志缺失、损坏或归属不匹配时均失败关闭，不重新生成身份或恢复成空库。

元数据使用 AES-256-GCM。包装钥从原 master 通过独立 `P11_CIPHER_CUSTODY_WRAP_KEY_1` HMAC 用途派生，binding 同时绑定 profile、原 installation、原 endpoint anchor 和原 custody anchor。AEAD AAD 再绑定 profile/binding。每次保存使用新随机 nonce，私有临时文件 flush 后原子替换，再同步目录；提交结果不明即毒化当前 owner 并取消相关用途，重开读取磁盘原事实。

文件名只允许 `cipher-object-<32位小写hex>.bin`，并与 `custody_<同一hex>` 精确配对。不会接受调用者路径、链接、任意文件名、未知文件或额外替换日志；未知对象和 `cipher-next-*` 残留保留并拒绝自动接管/删除，等待显式恢复方案。原生 Windows 继承本项目的私有 ACL 创建，Linux 使用原私有目录/0600；读取再核对原 root 内 regular file 和文件身份。

## 描述符不能由来包自授权

descriptor 从已确认的原合同和独立核验的本机/对端 bundle 推导，包含：

| 类别 | 绑定内容 |
|---|---|
| 原合同 | buyer、seller、order、job、attempt、fence、双方 endpoint、原模式与隐私 |
| 原协议 | API profile、public model、方向、用途、object、stream、epoch、原计算与传输期限 |
| 原密钥 | 原本机/对端 bundle hash、sender signing public key、recipient content public key 与 fingerprint、买家结果接收钥 |
| 原环境 | 原 kernel environment digest、local policy |
| 原预算 | data/wire/record 上限及固定 manifest expiry |
| 原来源 | OUTBOUND；或 INBOUND 加已经知道的原 manifest hash |

pre-header context 的 `stream_header` 必须为空，真实随机 header 只由原首次加密产生。descriptor JCS 摘要使用独立域，不把未信任 header 当原合同。任何原主体、模型、预算、期限、来源或 key version 改动均不能复用旧 handle。

## 原始写入和中断恢复

| 原状态 | 行为 | 重开后 | 是否再次调用 producer |
|---|---|---|---|
| 不存在 | 先预留完整 wire 上限并保存 WRITING，再创建文件和加密/导入 | 看原日志 | 首次一次 |
| WRITING | 原 owner 尚在写入；同对象重复返回 pending | INTERRUPTED；读取原部分文件大小，保留完整预留 | 否 |
| INTERRUPTED | 保留原部分文件和配额，不对外发布 | 保持中断 | 否 |
| READY | fsync、关闭并重开完成同原清单的无钥检查，之后提交 READY | 保持同一 handle/manifest | 否 |
| RETIRING | 已持久化退役；取消并等待真实读写退出，再删除原文件 | 可继续过期清理 | 否 |
| RETIRED | 原文件已删除，配额可归还 | 已过原期限的墓碑可压缩 | 否 |

一旦首次 WRITING 已落盘，失败、取消、文件满、私有输入预检失败、最终清单异常、提交未知或进程崩溃，都不能用同一逻辑对象重新加密。不能序列化/猜测/恢复 secretstream push 状态，也不能暗中重跑模型。需要上层明确失败或另行取得新授权上下文；本库不会自行签发新 epoch 或新执行权。

READY 的重复请求直接返回原清单，不读取传入 source，也不再执行 producer。导入的 READY 同样保留第一次接收的原清单。文件读取阶段仍会完整重新核验原密文，磁盘变化不能靠 READY 标记跳过认证。

## 补传与撤销

`CopyStoredRange` 用原本机身份的 `CIPHER_CUSTODY` 用途持有读操作；只复制 public bundle，不复制身份签名钥、内容私钥或买家签收钥。导入也使用该用途，撤销本机身份或原对端 pin 会取消关联在途操作。首发加密及实际消费仍由各自 SIGN_STREAM / OPEN_CONTENT 用途约束。

范围请求必须绑定原 descriptor、custody id、原 descriptor hash、原 manifest hash，偏移与长度须在已完成原文件内。先完整检查密文，再回到原文件起点，以 64 KiB 有界跳读/复制输出指定字节。未实现 seek-based 解密，不把发送成功当远端 ACK。目的端写入失败保留 READY，之后只补原字节。实际网络层必须另核当前原订单上传/下载 grant、远端已接受偏移及幂等性；本库没有开放的任意文件下载接口。

消费者/网络输入输出必须响应所属 context；本库能关闭自己持有的文件中断文件 I/O，不能强制中断一个无视取消的任意外部 Reader/Writer。关停必须等待实际调用退出，不能用超时返回冒充 join。实际 socket/管道的关闭权仍需接入后续传输 owner。

## 期限清理及父节点关闭

管理端 `cipher-expire` 使用实际 UTC 时间，stdin 不接受调用者指定的过期时间或 ACK。过期先提交 RETIRING，再取消目标 owner、等待真实退出、删除唯一注册文件、保存 RETIRED，最后压缩已过原期限的墓碑。原 descriptor 已到期，旧请求不能通过重新创建来复活。没有基于调用者 ACK 字符串的提前删除入口。

清理只有一个独立 control owner。两个数据操作都占用时，它仍可启动并取消两者；并发第二次清理返回 pending。文件删除或目录同步失败保留保守状态与配额；崩溃在删除与日志之间时，重开按同一 RETIRING 原文件继续，原文件不存在可作为幂等删除处理，不改写已知文件归属。

父节点关闭先同时向 key vault 与 ciphertext store 发出 BeginClose，再等待各实际 owner。不能先等待密钥用途，而让其内部文件读者一直等不到取消；也不能先释放根目录、OS 锁或 master。实际 join 完成后才清包装钥和父资源。本次不增加自动执行循环、内容 HTTP listener 或模型进程。

## 容量预算与入口

| 项目 | 源码预算；非实测 |
|---|---|
| ciphertext 总预留 | 显式 policy，66 MiB—512 MiB；对象按完整 wire 上限预留 |
| 对象数量 | policy 1—64；未过期中断对象仍计数 |

| 文件复制 buffer | 每次至多 64 KiB；不加载整段媒体或另复制模型 |
