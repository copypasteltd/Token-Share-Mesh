# 原生输入加密与首租约原子准入（R017）

本附录承接 R016 原调用准备，定义当前实现和后续接口的边界。适用三种原生文本请求：Chat Completions、无状态 Responses、Messages；仅 `PLAINTEXT / STANDARD`。它实现内部服务库，没有挂载公开模型接口，没有把客户内容发送到显卡、手机或第三方模型。

执行主体仍是 C2C 个人卖家的自有闲置设备；平台不能跨卖家自动转单。小程序 React/Taro、Web React/Vite、NB04 新粗野主义、具体手机型号和按小时或输入/输出分别 M token 的定价继续有效。部署、HTTPS、可观测性继续延后。

## 编号约束

| 编号 | 必须满足 | 实现与限制 |
| --- | --- | --- |
| EI-001 | 公开请求保持 OpenAI/Anthropic 原生形状 | 内部 `Request` 接受可信 preflight 元数据和原请求键；不要求 SDK JSON 携带私有订单/支付/设备字段；入口挂载待办 |
| EI-002 | 输入必须实际验证，不能信任上传者给出的 READY 或摘要 | `core.Preflight` 复用转发的严格解析器；核对精确原字节摘要、模型、方言、stream、最大输出；不支持字段直接拒绝 |
| EI-003 | 输入正文不超过 256 KiB、最大输出 1—32768，受原合同更小上限限制 | Responses 明确 `store:false`；不扩展工具、媒体、跨方言转换和 Sub2API 代码提取 |
| EI-004 | 本轮加密只保护明文模式数据库落盘 | AES-256-GCM；平台应用进程有解密能力，执行端收到明文后所有者也可能看到；不能标记 PLATFORM_BLIND、LP 或 PE |
| EI-005 | 密文使用随机 12 字节 nonce 和 16 字节认证标签 | 数据库 bytes 是原文长度；`input_ciphertext` 长度为 bytes+28；nonce 与 ciphertext/tag 连续存放，不把 nonce 当秘密 |
| EI-006 | AAD 绑定不可变上下文 | 固定域、买家、订单、job、asset、密钥版本及 UTC 截止；job 已固定原路由和原 key；不能换对象/买家/上下文复用 |
| EI-007 | 摘要各司其职 | job 保存版本化 HMAC；原文 SHA-256 只在合法明文域瞬时使用；asset 保存密文 SHA-256，不把它当推理内容或实际 usage |
| EI-008 | 数据与状态同事务 | 原调用/整笔预算/次数、密文对象、QUEUED 和 InputReady 安全事件同事务；无跨文件系统窗口；不做网络/引擎/渠道 I/O |
| EI-009 | 准备和排队不占物理设备 | INPUT_PENDING/QUEUED 均不签发执行权、不占 GPU；输入不可用时签发整笔回滚 |
| EI-010 | 原输入只绑定一次 | 原键原正文恢复同一 job/asset/ciphertext；不重新加密；改正文、参数、key 冲突；缺旧钥失败关闭 |
| EI-011 | 密钥用途隔离并显式配置 | 输入钥 1—16 个精确32字节版本；独立 HMAC 和 Ed25519 issuer；拒绝同值复用；无默认开发钥 |
| EI-012 | 构造时复制，关闭只清理持有副本 | 不修改调用方配置；Close 不释放预算/owner；不声称 Go 全内存擦除、密钥调度抹除或进程保密证明 |
| EI-013 | 恢复必须保留旧版本 | 输入钥、HMAC 旧钥和历史 issuer 公钥分别管理；验证公钥最多16个（含当前）；生产秘密加载、轮换持久化和撤销恢复待接 |
| EI-014 | 已准备调用使用自己的原预算 | 当前原合同、用户/key/角色、资金、资格仍须有效；新调用次数或剩余新预算耗尽，不撤销该调用已经预留的整笔额度 |
| EI-015 | ExistingAdmission 不是执行授权 | 路由对外仍可显示 SUSPENDED；该内部字段只区分新调用容量与已有意图；签发还要检查原 RESERVED 预算、输入、资源与截止 |
| EI-016 | 只能选择原合同固定绑定的卖家设备 | 当前能力/发布/资格、ONLINE且45秒内心跳、接单策略、`ED25519_DEVICE_1`、IDLE全部满足；历史 LEGACY_UNVERIFIED 即使展示可见也不能执行 |
| EI-017 | 物理资源锁必须已明确存在且 FREE | 缺行属于未知；不补造 FREE；SKIP LOCKED 竞争只选原绑定资源；BUSY/STOPPING/CLEANING/QUARANTINED 或过期占用都不回收 |
| EI-018 | 全局资源代次与 job 内围栏分离 | 初次 job fence=1；原物理 generation 加1；当前 PostgreSQL `p11.counter` 为 signed bigint，上限9223372036854775807，达到上限拒绝，不回绕 |
| EI-019 | 不把端侧 uint64 能力冒称平台全范围支持 | 租约线缆、端侧SQLite按规范保留 uint64 十进制字符串；本 issuer 受已发布数据库 signed-bigint 范围限制，扩展需独立前向迁移与验证 |
| EI-020 | 首租约、owner、任务与持久投递意图同事务 | 原预算保持 RESERVED；attempt ISSUED、resource ACTIVE、签名 lease、元数据 manifest、job RUNNING、安全事件、durable task 一次提交 |
| EI-021 | 租期最多45秒并受原硬截止限制 | 签发使用数据库 clock_timestamp；硬截止取原 job、当前资金/路由/资格及输入最小值；当前仅首发，无续租或自动换 attempt |
| EI-022 | manifest 只承载执行元数据 | 固定原合同、seller/device/resource/capability、双围栏、环境与模型/recipe摘要、请求安全参数、输入密文引用/长度/摘要及截止；无 prompt、地址、路径、argv、密钥或上游凭据 |
| EI-023 | 签名使用既有执行租约 profile | `P11_EXECUTION_LEASE_ED25519_1` 固定顺序域隔离消息；issuer_key_id 仅存储审计，线缆不新增可自行选择信任的 keyId |
| EI-024 | 设备独立建立信任和本地批准 | 收件方必须从独立可信渠道获得 issuer pin、原计划及 KernelRegistry批准；禁止从收到的租约/随附不可信manifest复制Plan来自我验证 |
| EI-025 | 同原键恢复不延长或重新签名 | 仍有效且当前资格、原输入、预算、job/attempt和精确owner均匹配才返回原签名；过期、撤销或资格退出只返回原 ID 与 RECOVERED_UNAVAILABLE |
| EI-026 | 过期、取消和未知结果不代表停止 | 保留原预算、次数、物理owner、围栏、签名记录；不得因TTL重发/释放；真实停止/清理/成交资格生产仍需接通 |
| EI-027 | 提交确认是交付前提 | ReadyTx/IssueTx 返回的是未提交结果；调用方不得在事务内发送内容或执行命令。提交未知只能按原键原参数查询，不自动创建新请求 |
| EI-028 | SQL只做结构和原子性检查 | 009追加7列/1外键/2索引和守卫；真实执行PL/pgSQL回归另列。SQL不验签、不验HMAC/AEAD、不证明审批/付款/硬件真实性 |
| EI-029 | 原 SQL 与历史事实保留 | 001—008及端侧DDL字节不改；旧asset/lease默认为UNBOUND，新列为空；不回填授权/密钥/执行计划，不能原地改造成native记录 |
| EI-030 | 真实验收保持开放 | 已覆盖原生临时PG、Go密文认证/并发和真实SQLite元数据接线；真实内核、支付、手机/GPU、E2E互通、LP/PE、性能、独立安全评审和完整80/96验收未执行 |

## 内部调用流程

1. 上层保存原请求键和精确原字节；`core.Preflight` 提供瞬时摘要与安全参数。`invocation.New` 只创建准备服务；`NewExecution` 另接显式输入密钥和 issuer，未配置不开放执行。
2. `Execution.Ready` 按当前 scoped key 精确找到原已确认路由，遵守 `identity → 原订单写锁 → 路由/资金/资格 → 原job/预算` 的锁序。已有原意图和密文只恢复；新输入校验后一次加密入库。
3. `Ready` 不返回正文、解密钥或执行 token；返回原准备结果、asset ID、密文摘要、长度、截止和重放标志。当前借用既有 assets 表存小型有界请求，不代表媒体对象生命周期已完成。
4. `Issue` 重核当前同单 SETTLED/ALIPAY/ORDER及显式SANDBOX或PRODUCTION、无非失败退款、当前原资格与key范围、原整笔RESERVED预算。不同资金变更服务也必须锁同一父订单；不能用旁路退款SQL替代应用事务规则。
5. 读取并认证实际存储密文，重新执行原生校验，立即清理持有的明文缓冲；原始密文缺失、隔离、过期、密钥缺失或认证失败都拒绝。SQL形状READY不是可信输入。
6. 在原合同绑定集合中选一个当前原生设备和明确FREE资源，锁住其行；冻结双围栏与元数据manifest，计算typed JSON摘要，按已有Lease规范签名，同事务写齐聚合与投递意图。
7. `Issue` 只在提交后返回首签或原签；回执迟于签名截止时隐藏执行材料，仅保留原ID。接收端仍要在本地当时重新验签和检查截止。

```mermaid
flowchart LR
  A[原键与原生请求] --> B[当前身份与原订单写锁]
  B --> C[严格校验与原预算预留]
  C --> D[AES-GCM实际输入与QUEUED]
  D --> E[当前资格与原输入认证]
  E --> F[明确FREE的原生物理资源]
  F --> G[双围栏与45秒内首签名租约]
  G --> H[原子持久投递意图]
  H -.待接通.-> I[认证领取/独立批准/输入交付/真实内核]
```

## 数据与事件

| 位置 | 本轮变化 | 不能据此推定 |
| --- | --- | --- |
| assets | input_profile/input_key_version/input_ciphertext；一个native job只一份输入 | 大媒体存储、过期删除、密钥销毁已完成 |
| jobs | input_asset_id一次绑定，保留008全部原调用约束；初次owner不可替换 | E2E PREPARED/recipient和重封装已完成 |
| execution_leases | admission_profile/issuer_key_id/execution_manifest；首签内容不可重写，撤销不复活 | 生产issuer信任分发、续租、撤销通信已完成 |
| outbox v2 | RouteInvocationInputReady：job_id/asset_id/order_id/contract_hash | 包含正文或可下载地址 |
| outbox v3 | RouteInvocationAttemptIssued：job_id/attempt_id/lease_id/resource_id/resource_lock_generation/contract_hash | 执行端已经收到、停算或清理完成 |
| durable_jobs | DELIVER_EXECUTION_LEASE，去重键和target均原lease ID | 已存在投递worker或设备领取接口 |

manifest用强类型字段序列化后SHA-256；JSONB重排后恢复时重新解码为相同类型再序列化，不直接哈希JSONB文本。签名租约沿用原固定字段ASCII编码，与manifest哈希方法区分。两者都不是客户内容封装签名。

## 边界与后续开发顺序

先接生产秘密存储和独立信任/内核批准；随后实现设备认证领取、原owner核对、受限输入交付、停止/清理回执与租约续期/撤销通信，再连接实际适配器和可信usage。公开SDK Authorizer/Grant/SecretSource要复用同一原调用/原租约，不能只凭Preparation、ExistingAdmission或输入READY开通。实际tokenizer在模型prefill前检查manifest内原输入上限；preflight只校验字节/形状，不猜实际token或费用。

本轮没有新增下载明文HTTP端口，没有读取配置中的任意URL/路径，也没有将GPU指令写入manifest；设备领取与输入交付需要完整认证/防重放/锁序设计后实现。密文对象目前保留READY或QUARANTINED，禁止覆盖/删除；删除与钥生命周期需后续前向方案，不能宣称已实现及时擦除。

完整实现与56任务/222未收口子项见[本轮清单](../../dev/progress/R017-本轮实现与完整待办.md)，实际原始测试、失败开发记录与范围见[本轮验证](../../dev/tests/evidence/R017-验证报告.md)。所有合成SETTLED、READY、审批和设备记录只服务于临时原生数据库验证，不构成真实收单或开售依据。

## R018 原设备领取衔接

R018新增原设备签名领取原租约：35/93个控制操作、65表/664列/113外键。仅原设备ED25519证明可领取；原命令编号与header相同，010将其固定绑定原lease并和安全事件原子提交。每次包括重试都重新核原买方scoped key/route、原订单与同单资金、资格、完整已占预算、加密输入元数据、原owner/双围栏和原期限；不换单、不重签/续租。领取服务只有显式公钥，不解密输入、不确认实际执行或计费；DELIVER任务、预算和资源保持原状。设备独立公钥/批准计划、输入/manifest交付、宿主持久执行命令、真实内核/usage/渠道及E2E/LP/PE/租赁仍待。001—009及端侧DDL保持原字节，历史UNBOUND_CLAIM。

完整约束及未接线项见[附录-原设备签名领取与原租约交付.md](附录-原设备签名领取与原租约交付.md)。下文历史轮次的“尚无领取”保留当时边界；本轮只增加原签名元数据交付，不把历史节点或准备记录升级为可执行设备。

## R019 原清单与输入交付衔接

R019接通已领取原租约的执行清单和原始输入受限交付，当前37/95显式控制操作、65表/664列/113外键。INT-094/095先登记权威契约与固定编号；两个GET仅接受原签名设备，不隐式领取。每次读取沿同一原订单优先锁序复核原买方key/路由/同单资金/资格、完整已占预算、原设备版本、输入、物理owner/双围栏和原期限。独立交付服务无签发私钥，输入必须通过原AES-GCM/AAD、独立版本化HMAC和同档位Preflight，按原始字节返回。客户端用独立公钥、原订单/路由/模式及本机内核批准核验清单和租约，有界接收输入；不自动批准内核或提交模型。此为PLAINTEXT/STANDARD可信平台经认证连接交付，密文摘要不能当原文明文签名，不是E2E或卖方不可见。领取/读取均不ACK、不续期、不重派、不完成DELIVER任务、不计费/清锁。001—010及端侧DDL原字节保持；真实宿主持久命令、tokenizer/内核/usage/渠道、E2E/LP/PE/租赁和完整验收仍待。

新增DG-001—030见[附录-原设备清单与输入受限交付.md](附录-原设备清单与输入受限交付.md)。此前章节保留历史阶段边界，本附件只扩展认证明文交付，不宣告完整执行。
