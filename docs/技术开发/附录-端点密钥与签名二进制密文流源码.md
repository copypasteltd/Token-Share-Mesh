## 3. 密钥落盘、原身份与恢复

原 `node.Store` 已有的 OS 秘密根和单写者文件锁继续持有。新增可选 `endpoint_key_vault_id` 随原状态先持久化，再创建 `endpoint-keys.enc`。包裹钥用 HMAC-SHA256 从原 master 派生，域和绑定包含原 installation、原随机 anchor；不随 seller 配对内容改写。日志使用 AES-256-GCM，AAD 绑定独立 profile 和原 binding digest，原子替换并 flush。不存在第二套数据库、第二把文件锁或云端私钥保管。

先存 anchor 后建日志是故意的失败关闭边界：创建中断、日志丢失、损坏、身份不一致时，不自动初始化新钥冒充旧身份。重装或换端必须新身份和新独立核验；原买方钥丢失不能解旧结果，不能将同一任务重跑来伪造恢复。

每个 public bundle 自签 owner/endpoint/role/version、身份钥、内容接收钥、买方独立签收钥及规范 UTC 有效期。BUYER 必须有独立 receipt key；SELLER 不携带此钥。auth token、升级签名钥与以上密钥不复用。公钥、自签和传输完整性不能证明账号归属，原业务控制面仍须独立绑定。

| 有界项 | 上限 | 处理 |
|---|---|---|
| 本机历史 bundle | 32 | 拒绝继续新增；不能删除历史后重用 endpoint |
| 对端历史 bundle | 128 | 拒绝继续登记；不自动覆盖旧信任 |
| 加密日志 | 256 KiB | 保存前检查，失败后 poison 并取消用途 |
| 同时钥用途 | 2 | mutex 下计数，与 Close 的实际 join 同步 |
| bundle 有效期 | 90 天 | 过期不能新用钥，未承诺业务自动续期 |

以上是源码预算，尚无性能或资源占用测量结果。历史满额的显式归档/新身份流程仍需上层管理，不做自动压缩删除。

## 4. 独立信任、轮换、撤销和关闭

首次只接受 `OUT_OF_BAND`：操作者提供独立确认的身份公钥 fingerprint 与有界 verification reference。平台页面出现的指纹、自签本身、TOFU 或网络首次连接不能自动成为独立证明。CLI 接收核验声明，不替用户完成线下核验；双端 UI/二维码、平台账号确认与业务合同联核仍待接线。

轮换用旧身份钥签 `P11_ENDPOINT_ROTATION_1`，绑定旧 bundle hash、完整新自签 bundle 和原 recorded_at。owner/endpoint/role 不变，version 严格加一。新本机 bundle 与完整原 transition 同次 AEAD 保存，旧钥转 RETIRED；回复丢失后，用同一旧 hash 与同一 expires_at 取回原 transition，不生成第二组钥。对端保存原 rotation hash，重复提交必须是原记录及有效旧签名。

RETIRED 钥仅允许上层显式提供原 bundle hash 的历史原任务用途；不能据此换卖家、换隐私档或授权新任务。REVOKED 不可用。撤销先保存日志，再取消依赖本机/对端 bundle 的在途用途；取消是协作式，内部消费者及 I/O 必须响应 context。撤销返回不宣称已销毁所有在途副本，`Close` 才取消并实际等待所有 owned callbacks 退出，再清理持有的钥材料。

`Scope` 精确匹配 owner/endpoint/role/bundle hash/purpose，`PeerScope` 精确匹配独立 pin；两者都可显式允许原 RETIRED 版本。SIGN_STREAM 只复制身份签名钥，OPEN_CONTENT 只复制内容秘密，SIGN_RECEIPT 只对 BUYER 开放独立 receipt key。用途完成清理副本；Close 不能由其自己的 owned callback 同步调用，否则会等待自身，生命周期所有者应在外层关闭。

Node 关闭路径在释放 master/原根目录/OS 锁前关闭密钥库并实际 join。未来将 E2E 接进 Host 时还需统一取消顺序，防止内容 callback 与 Host 相互等待；当前没有声称完成这条执行链。

## 5. C、sealed、H 与签名顺序

1. 从独立确认的原合同构造 C：contract/order/job/attempt/fencing、双方主体和端点、买方结果接收钥、发送签名钥、接收内容钥、环境摘要、本机 policy、E2E/PLATFORM_BLIND、文本 API profile、purpose/direction/object/stream/epoch、传输期限及原计算硬截止。
2. 每对象产生随机 stream key 与 secretstream header；header 写入 C。INPUT/CONTROL 不提前填未知 `resource_id/resource_lock_generation`，也不填未来 delivery。执行时另核 ISSUED 资源双围栏，不能靠内容 C 获得 GPU 锁。
3. `context_hash = SHA256("P11/E2E/BINARY_STREAM_1/CONTEXT\0" || JCS(C))`。将 stream key、该 hash、stream header 和私有 profile 规范编码后 sealed 给原接收公钥。
4. H_unsigned 包含 C、sealed_key、sealed_key_sha256、signature_profile_id。身份签名消息为 `"P11/E2E/BINARY_STREAM_1/HEADER_SIGNATURE\0" || JCS(H_unsigned)`；生成 H.signature 后只对完整 H 做外层规范编码。
5. `header_hash = SHA256("P11/E2E/BINARY_STREAM_1/HEADER_HASH\0" || JCS(H_unsigned))`。签名、header_hash、context_hash 均无自引用。

接收方的 `Expected.Context` 来自独立原合同，stream_header 留空；除随机 header 外，H.C 必须逐字段完全相同。原发送公钥与接收公钥由调用方独立提供；不能从攻击者自带的 H 寻找信任根。先检查结构/规范编码/原身份/摘要/签名，再 unseal，继而核 sealed 内 C hash/header。PLATFORM_BLIND 只对平台隐藏内容，不承诺执行所有者无法高级取证；本地低门槛防读取路线仍需 LP/PE 全路径资格。

## 6. 二进制帧与内存边界

对象先写 `uint32be(header_length) || JCS(H)`；H 最多 16384 字节。后续每个记录为：

```text
uint32be(body_length)
uint64be(sequence)                       # 从 0 开始，严格连续
secretstream_ciphertext(
    type:u8 | flags:u8=0 | reserved:u16be=0 | payload_length:u32be | payload
)
AAD = "P11/E2E/BINARY_STREAM_1/RECORD_AAD\0"
      || header_hash[32] || body_length:u32be || sequence:u64be
```

body_length 包含 8 字节 sequence 与后续密文，不含自身 4 字节。payload 最大 65528，内层最多 65536；body 最大 65561，每完整记录最大 65565 字节。未知 type、flags/reserved 非零、长度不符、重放/缺序/倒序均拒绝。当前解码器不做乱序缓存，故不能把它写成已实现 32 条/2 MiB 重排或 4 MiB 整链共享预算。

| 记录 | 规则 |
|---|---|
| HEADERS=1 | 必须首条且唯一；只表达允许的协议元数据，无任意 header、token、URL 或文件路径 |
| DATA=2 | 非空；usage/error 后不能继续；prompt/结果不进行 JCS 重编码 |
| USAGE=3 | 仅 OUTPUT；`LOCAL_UNVERIFIED`，无可信 evidence；传输认证不能提升卖家自报计量 |
| ERROR=4 | 详情留在密文内；后续只可终止，不把正文带入公共错误日志 |
| END=5 | 本身必须 TAG_FINAL；含此前总记录数/DATA 数/字节数/明文摘要与 outcome |
| CANCEL=6 | 独立 CONTROL 流，HEADERS(CANCEL)→CANCEL→CANCELED END；控制编解码存在，组合层 SealObject 尚不开放此分支 |

非 END 只能 TAG_MESSAGE。END 的明文摘要只在密文中，不进入平台 manifest/索引。输入 DATA 最多 2 MiB、输出最多 64 MiB、密文对象最多 66 MiB、记录最多 131072；上层可缩小不可放宽。组合入口先验证 limit 后读 INPUT，防止 limit+1 溢出或提前分配越界。FFI 状态在独立原生小块分配，不建立 RAM 盘、虚拟机或第二份模型；Go 明文临时副本按用途清理，但不承诺垃圾收集器或管理员无法恢复内存。

## 7. 外层 manifest、前缀、输入屏障和期限

完整密文对象结束后生成独立签名 manifest：C hash、unsigned-H hash、完整对象 cipher hash/bytes、原签名 key id、expires_at 及 profile。`manifest.Hash()` 摘要完整含签名对象，不把自身 hash 填进签名材料。清单公开的是密文摘要，不是 prompt 或结果明文摘要。

`Reader.Next` 每次仅交认证过的记录；`Finish` 必须同时看到合法加密 END/TAG_FINAL、原签名 manifest、精确总长/总 hash 和真实对象 EOF。截断、尾随垃圾、清单错版都不能成为成功。`InspectOpaque` 只验证外层签名、顺序结构、预算和完整密文摘要，**不能判断 AEAD、私有 END、prompt 合法性或模型可执行性**。

组合层 INPUT/CONTROL 必须先有界聚合并完成 Finish，才调用任何内部消费者。INPUT 再用同一 `gateway/core.Preflight` 校验原 public model 与三个文本档位；只有 SUCCESS 能过输入屏障，不能先把认证前缀送进模型再等末尾报错。OUTPUT 可把逐条认证的前缀交给可信本机内部消费者，END 要等 Finish 后才交；这些前缀不能当最终签收、账务确认或可售资格。

传输 `deadline` 与 `original_hard_deadline` 分开：INPUT/CONTROL 不晚于计算硬截止；OUTPUT 可在原计算结束后补传，但不得超过硬截止后 30 分钟，且双方 bundle 有效期覆盖整个传输期限。manifest 到期不晚于传输 deadline，不额外加 30 分钟。组合层 context 同时服从原调用者取消、传输期限、原本机钥/对端 pin 的撤销/有效期。

这 30 分钟是密文格式的最大预算，不覆盖其他分支更短的业务交付期限，也不延长计算、重占 GPU 或改变旧结果交付版本。实际业务应取所有适用期限的最小值。
