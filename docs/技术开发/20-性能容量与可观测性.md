## 2. 协议有界资源

| 对象 | D上限/规则 | 超限动作 |
| --- | --- | --- |
| 标准JSON请求 | 2MiB，base64计编码后字节 | 执行/收费前413 |
| 媒体 | 单对象64MiB，配方可更低；解码4000万像素 | 拒绝/取消受控读取，不无限解压 |
| 单流缓冲 | 4MiB为单流各阶段共享配额，另有进程总池，不能逐阶段累加 | 传播背压，阻塞超时取消/查询原执行 |
| 密文帧/块 | 整帧128KiB、认证数据块64KiB | 拒绝，不截断伪成功 |
| 密文重排 | 32帧或2MiB取更严者 | 安全中止 |
| 资源槽 | 每物理资源1槽，双引擎/自用/租赁共用 | 未得当前锁不执行 |
| 截止 | 首包/空闲/总期限按SKU冻结，总期限不因重试延长 | 起流前标准错误，起流后方言错误或中断 |

头、工具参数和事件另受[07转发](07-统一协议网关与Sub2API改造.md)约束。最小验证关注边界、背压、取消、断流、旧代次和唯一资金副作用，不搭监控或承诺生产容量。

## 本方案的资源验收

新增原生隐私方案定义桌面新增活动内存≤96MiB、Android≤24MiB、CPU流加密和无额外模型副本等D预算；具体基准口径与目标见[完整方案](附录-低开销隐私执行完整方案.md)第8节。BINARY_STREAM_1是独立的待验证二进制档位，不由旧JSON帧Schema证明；LOCAL_SEGMENTED_1只用于本地完成对象的独立认证分段读取。这些是本轮功能资源验收，不恢复监控/可观测性或生产SLO，尚无实测结果。

## 加密格式的独立资源限额

上表128KiB整帧/64KiB认证块属于JSON_COMPAT旧外层。BINARY_STREAM_1使用≤16KiB建流头、≤65536解密后记录/≤65528 DATA正文、≤65565完整线记录；媒体64MiB明文/66MiB密文分别限制，LOCAL_SEGMENTED_1 manifest候选≤64KiB。4MiB为整流各阶段共享总额，重排窗口计入其中；分段LRU计入桌面/Android内容池，不再叠加一份。具体字节/END/重连/交付范围见[技术08](08-端到端加密协议与密钥实现设计.md)，未冻结/未实测。
