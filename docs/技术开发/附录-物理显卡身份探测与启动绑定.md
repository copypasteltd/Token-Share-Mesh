# 物理显卡身份探测与启动绑定

状态：R024 源码增量。适用 Windows NVIDIA 整卡、固定原生 llama.cpp 包；尚未构成正式安装器、生产挂牌资格或远程证明。R023 的 PIPE_3 验证为历史结果，当前私有握手升级为 PIPE_4；包格式仍为 PACK_1，但包内 profile 必须精确匹配当前实现。

| 编号 | 约束 | 当前实现与验收边界 |
| --- | --- | --- |
| GI-001 | C2C 原设备 | 所有者自行选择显卡；不得因容量、价格、断线或编号变化改用其他用户设备。 |
| GI-002 | 系统信任边界 | 信任本机系统驱动和独立固定的 worker/动态库；本机元数据不是防管理员伪造的远程证明。 |
| GI-003 | UUID | 使用规范 GPU UUID，拒绝空值、全零及 MIG 文本别名。 |
| GI-004 | PCI | Windows 当前档只接受零域，规范为 `0000:01:00.0`；SMI 的八位零域转为四位。未知域、总线/设备/功能越界拒绝。 |
| GI-005 | 物理摘要 | `SHA256("P11_PHYSICAL_GPU_NVIDIA_1" + NUL + canonicalUUID)`。不含 CUDA 编号或 PCI 插槽，避免同卡产生多个物理门闩。 |
| GI-006 | 放置变化 | 环境摘要同时绑定 CUDA 名、UUID、PCI；更换插槽或编号需重新选择及独立批准，物理摘要保持不变。 |
| GI-007 | 库存上限 | 最多 64 个设备；重复 UUID、PCI 或后端名一律拒绝，不折叠为看似可信结果。 |
| GI-008 | 元数据上限 | 后端名不超过 128 字节；UUID 40、PCI 16、型号 192；型号限可打印 ASCII；总显存 1 字节至 1 TiB。 |
| GI-009 | 可替换内核 | 固定包仍独立校验 worker、模型、模板及完整动态库白名单；探测不能下载或安装其他内核。 |
| GI-010 | 探测入口 | `p11-node gpu-discover --runtime-root <绝对私有路径>` 从标准输入读取包路径和独立 SHA256；请求上限 4096 字节，拒绝未知/重复/尾随字段。 |
| GI-011 | 只读权限 | 探测只返回元数据，`execution_enabled=false`、`qualification=NOT_GRANTED`；不注册设备、批准订单、开启共享或获取资源槽。 |
| GI-012 | 独立进程 | 使用当前固定 worker 的自有进程、定向匿名管道和已有进程所有权机制；不连接用户现有 LM Studio/ComfyUI。 |
| GI-013 | 无模型加载 | 探测验证文件摘要，但不映射权重、不创建推理上下文、不推理；大文件用有界缓冲读取，不整体复制到内存。 |
| GI-014 | 驱动定位 | Windows 只从 System32 加载 `nvcuda.dll`；包内禁止冒充驱动。本轮不增加 CUDA SDK 或 NVML 服务依赖。 |
| GI-015 | 元数据 API | 仅调用 Driver 的初始化、PCI 反查、UUID、型号及总显存 API；不创建 CUDA 上下文、不分配显存、不重置设备。后端加载自身可能进行驱动初始化，不能据此承诺零驱动开销。 |
| GI-016 | 后端对应 | 先读取所选 GGML 设备的 `device_id` PCI，再通过驱动反查该 PCI 的设备；不能假定 CUDA 序号、SMI 序号与后端序号相等。 |
| GI-017 | 分区限制 | 同时读取旧版与 v2 UUID；二者不一致即拒绝。当前不支持 MIG、vGPU 或多卡张量拆分；没有证明的分区不能入选本档。 |
| GI-018 | 探测协议 | `PROBE=6`：profile、commit、主库、注册库、基础库；`INVENTORY=135`：profile、commit、数量、设备记录；每帧最大 65536 字节。 |
| GI-019 | 记录编码 | 记录依次为后端名、UUID、PCI、型号和 uint64 总显存；字符串长度与整数沿用大端编码。禁止附带提示词、结果、路径诊断或密钥。 |
| GI-020 | 完整结束 | 库存必须为唯一完整帧，后接 EOF 和自有进程正常退出；尾随帧、异常退出、超时均返回未知，不采纳部分库存。 |
| GI-021 | 超时清理 | CLI 探测 30 秒；取消仅终止自有子进程并关闭自有管道，随后有界等待退出。未观察退出不声明清理成功。 |
| GI-022 | 启动选择 | `OwnerSelection` 增加 `gpu_uuid`、`gpu_pci`；GPU 层数大于零时必填且必须已规范化；显式 CPU 档三项 GPU 标识都为空。 |
| GI-023 | 环境 v2 | `P11_LLAMA_ENV_2` 域绑定包摘要以及依次声明的 GPUDevice、GPUUUID、GPUPCI、ContextTokens、BatchTokens、Threads、GPULayers JSON 参数。此哈希计算本身不是批准。 |
| GI-024 | INIT v4 | 原 profile/commit/三库/模型/模板/后端名后增加 UUID、PCI，再接上下文、批量、线程、GPU 层数；旧握手拒绝。 |
| GI-025 | 启动前复核 | worker 在选定 GPU 后、加载模型前重新反查真实身份；后端名、UUID、PCI 任一不符即 `IDENTIFY_DEVICE`，禁止 CPU 或其他显卡降档。 |
| GI-026 | READY v4 | profile、commit 后必须附实际设备记录；CPU 为全空记录及零显存。Go 侧独立校验与本机批准选择相等，再允许工作。 |
| GI-027 | 固定错误 | 旧 1—7 启动阶段保留；8 为 IDENTIFY_DEVICE、9 为 PROBE_DEVICES。只返回固定阶段及数值码；其他进程/管道错误统一为未知。错误不证明任务清理完成。 |
| GI-028 | 提供方透明 | `LocalInfo` 包含所选参数、实际 UUID/PCI/型号/显存及物理摘要；不含提示词、生成正文或 IPC 句柄。商业 UI 不应公开完整 UUID。 |
| GI-029 | 共享门闩 | 本地执行库已可用规范 UUID 摘要拒绝多资源别名；本轮不修改 22 份已发布 SQL。正式 Host 配置与挂牌审批仍须独立绑定该摘要，不得仅信任调用者上传的哈希。 |
| GI-030 | 资格边界 | 真实小模型测试证明本机绑定及有限协议行为；不证明全层卸载、30 轮性能、LP 隐私、E2E、可信 usage、结果 ACK、支付或完整产品可交付。 |
| GI-031 | 平台范围 | Linux 编译与纯逻辑测试单独记录；本轮 Linux 驱动反查、AMD、手机真实设备未实测，GPU 路径不得伪称已支持。Android 仍要求真实 LMA 二开和型号证据。 |
| GI-032 | LM Studio 保留 | 官方 CLI 默认使用用户目录指针并优先连接已有实例，单设 API 信息路径不能证明独立内核环境。完整 CLI/llmster/runtime 可替换封装继续待实现；不得改写用户 HOME、接管现有实例或用仅连接现成服务代替原要求。 |
