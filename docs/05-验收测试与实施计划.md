## 测试条件与证据

C2C同卖家重派测试要求该卖家拥有/合法使用并登记两台真实独立节点；跨卖家重选需另一位卖家。两位卖家各一台可以验证C2C成交和跨卖家重选，不能冒充同卖家双节点重派通过；完整演练需补足相应设备与授权。

覆盖Windows-ComfyUI、Linux-ComfyUI、Windows-LM Studio、Linux-LM Studio及至少两款不同系统/资源的Android真机；桌面至少两台真实物理GPU节点，可按已测组合轮换，不能同机双进程冒充物理故障切换。记录OS/架构、驱动/后端、模型/量化/tokenizer/运行时/配方哈希、区域与合同。全程原生，无Docker/WSL/虚拟机或Android模拟器；未有设备只能报未执行。

输入采用自有/授权提示词与图片；另有错误尺寸、超大图、路径穿越、未知模型、签名篡改和坏产物样本。准备支付沙箱与获准正式测试环境，分开标识；只有真实许可的上游可做订阅商用测试。所有故障注入针对本项目有权控制的测试进程/节点，不影响无关用户。

每次保存 order/job/attempt、token、规格哈希、seller/listing/支付/验收/佣金/卖家结算/到账引用、错误码和最终状态。基准测试与故障演练分别报告；对外生产完成率包含实际受理的全部任务及失败/超时，不用剔除困难任务美化指标。

## 必须完整演练的链路

以下1—5为明文固定任务基线；另外必须独立演练：加密端点核验/本地加密/回执与重派放钥，增强真实证明/拒放钥，租赁零费准备/起表/预算/故障截断/清理复用，以及四桌面组合和Android的本地文本/模型/流式/自用抢槽。不能只完成下面的ComfyUI链路就宣布80项通过。

1. 自愿卖家A自助挂牌 → 买家B确认A/价格/费用 → 真实付款 → A节点领取 → ComfyUI 生成 → 上传 → 平台验收 → 买家最终结算 → 下载 → 卖家应结净额与平台佣金 → 争议窗 → 获准个人卖家渠道结算到账。若没有实际第三方出款，只能报告“买家服务闭环通过”，不能报告整个双边平台已通过。
2. 初始节点失联 → 租约失效 → 同卖家披露的合格节点重派 → 新结果验收 → 原节点迟到 → 买家一次收费、唯一卖家结算/佣金。无同卖家备用则失败；跨卖家原单结束后新确认。额外计算按已约定责任分担，不自动平台保底。
3. 买家完成授权但最终结算未知 → 保留任务与产物 → 查原交易 → 成功后发权益或失败处置。不得在未知时让买家重买相同任务。
4. 取消与完成并发 → 条件更新确定最终分支 → 退款/交付与供给应付一致；重复通知、重复上传、服务重启不改变已确定结果。
5. 模型/许可被撤销 → 停止新售 → 检查在途可履约性 → 按原合同完成或失败退款 → 不用未经同意的模型替换。
