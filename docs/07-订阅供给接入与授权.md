## 业务模式与默认开关

个人卖家A保有上游账户，在取得允许该下游用途的许可后自主挂牌，向买家B提供调用服务；平台提供接口/撮合并按明确规则收佣金，不采购额度或先买入再销售。订单固定实际卖家、挂牌价和费用版，见[C2C规则](交易/C2C交易与市场规则.md)。不同供给可以是专门商业 API、明确允许的下游服务协议，或获得书面同意的订阅套餐。账户/密码/原始 key 不出售给买家，也不以更换 key、代理包装或多账号轮换来规避上游限制。

关于 MiniMax 的已核事实和地区边界见 [SRC-M01—M03](../../需求文档/00-共用规范/03-资料依据与待确认事项.md)。当前配置默认 `subscription_supply_enabled=false`。密钥可用、余额尚有剩余、供给者同意出售，只证明技术或主观意愿，不足以替代服务商允许这种用途的证据。中国站与国际站、Coding Plan 与后续 Token Plan 按实际购买合同分别审核。

## 准入资料与审批规则

每个供给申请必须含：供应商法定主体、服务地区与接口域名、产品/套餐 ID 和版本、账户购买主体、有效期、允许调用者/工具/用途、是否允许转供或为他人提供服务、并发/窗口/限速、数据处理位置、商用/输出权利、书面许可或正式条款证据、卖家承诺、平台协议和与买家的服务合同。

证据记录来源 URL/合同文件、版本或生效日期、适用主体/区域/套餐、审批人、结论、到期复查日。审批结果三种：APPROVED、NEEDS_EVIDENCE、REJECTED；只有 APPROVED 且证据仍有效才可上架。证据变更不自动适用于已售合同，若无法继续履约则暂停新单并退款/转入经买家同意的合法替代方案。

| 申请形态 | 审核处置 | 可开放能力 |
| --- | --- | --- |
| 普通订阅，未提供下游使用授权 | 待补证/拒绝该用途 | 不向他人转供，不能在市场出售 |
| 正式商业 API，合同明确允许平台目标用途 | 审核具体授权范围、数据和计量 | 在获准范围按请求或用量上架 |
| 指定套餐书面同意本平台服务模式 | 核对主体/地区/期限和技术约束 | 只开放许可覆盖的模型与调用方式 |
| 自用连接器，无第三方转供授权 | 可另设计供用户自身使用的工具 | 不算本市场已获准的转售货源 |

自用工具是可选独立产品方向，不能以“每个买家临时视作 A 的自用”绕开既定审核。

## 密钥部署两种形态

| 形态 | 优点 | 代价与需求 |
| --- | --- | --- |
| 供给者本地出站 Relay | 原始上游 key 不上传平台；供给者控制自用保留 | 需要设备在线，计量/可用量可信度较弱；固定上游域名、加密存储、签名任务、超时与回执核对 |
| 平台受控凭证库连接器 | 可集中限流/审计/查询回执 | 供给者明确同意托管，最小权限、加密、轮换、访问审计；仅访问批准服务，不接受任意 base_url |

对单一获授权上游，凭据部署按其合同选择其中一种；这不是省略明文平台网关或加密本地网关的理由，两类数据通路均在总需求内。两种方式都不能被当成“因此可以转售”的理由。上游 key 不出现在买家请求、错误、日志或前端配置中，普通 API key 与订阅 key 不互换使用。

## 双协议与本地转发内核

所有外部调用也通过已发布OpenAI/Anthropic入口；明文走平台Sub2API类网关，加密走买方本地/LAN加密程序、平台盲转、卖方本地解密及内置同类转发内核。卖方/上游可见范围须披露；在平台凭证网关解密的路径仍只能标明文。

Sub2API账户可登录/可转发不证明这种C2C转供已获许可；默认不能用全局账号池轮换跨卖家、绕并发或静默改模型。实际seller、授权、模型/协议/usage版本及预算绑定原合同，内核计量不直接变成第二套用户余额账。详见[协议与网关](协议/统一API与本地加密网关需求.md)。

## 可售能力与窗口

模式映射：明文可采用上表两种密钥部署；基础加密须买家加密到A的本地Relay，由其解密调用上游并加密返回，明确A和上游可见。平台凭证库若解密请求，则只能归明文，不能挂平台不可见标签。增强档外部API本版未开放，显卡租赁不用于转卖订阅额度。

Relay控制面、签名、窗口/usage回执可适配Windows/Linux原生设备；Android本地模型是ANDROID_DEVICE而非该Relay货源，不能默认手机持有上游订阅就已有下游许可。跨端协议见[多端矩阵](供给端/00-供给端能力矩阵.md)。

容量由模型支持、剩余额度、窗口有效期、供给者自用保留、已占用并发和上游实时可用性共同决定。每条 Offer 明确计量单位；只有供应商定义可转换且实测验证后，才能把某种额度折算为 token 或请求数。按模型/上下文变化的配额不能一概等价换算。

数据模型至少包含 provider、region、plan_id/version、authorization_id、service/model、window_type/reset_at、quota_unit、remaining/unknown、self_reserved、leased、concurrency_limit、rate_limit、usage_source、last_verified_at、expires_at。窗口可多个并存；最紧约束决定能否接单。

没有可信额度接口时，用保守限额与实际成功/限流回执估计，显示“可用量未验证”，不得宣传精确剩余库存。用户在其他工具自用会使余额下降，必须允许快速停供；以订单截止时间和实际可用量判断，不销售指望下一窗口重置但无法保障的服务。

## 执行、重试与流式边界

买家请求先匹配并确认实际卖家/挂牌，再冻结模型/上限/价格/佣金/许可。原单只派该卖家披露的端，跨卖家结束原单另确认新单。记录平台 request_id、上游 request_id、供给连接器、授权版本、请求摘要、usage 和结束原因。上游 429、窗口耗尽、账户停用、网络超时按原请求是否已执行区分处理；不因为没收到响应就无条件重发造成双成本。

固定请求价只适合明确的输入/输出上限，仍需测量成本。Token 计费要明确定义输入总量与缓存量是否互斥、输出 token、工具调用与 reasoning 等字段映射，按实际提供商合同处理。账单取整单位与时机写入 PriceVersion，不能悄悄将估算值换成更贵单位。

| 异常 | 必须实现的决策 |
| --- | --- |
| 上游超时但可能已完成 | 按 request_id 查询/核验；无证据不向买家重复记费，按卖家/买家/平台实际原因与事先明确规则分担，不自动平台保底 |
| 客户端关闭流 | 是否计入已实际交付部分由预先合同和真实 usage 决定；不能默认全量成功 |
| 最终 usage 缺失 | 暂记待核验，使用正式对账来源；本地估算标估算，未经约定不能直接扣款 |
| 超出授权预算/输出上限 | 尽可能终止；买家费用不得超过确认上限，超出风险按造成原因/合同和平台自身过错承担，不转嫁为买家超预算扣费 |
| 供给者撤销密钥/许可过期 | 停止新请求；在途按上游状态核验，不将未知算作已完成 |
| 故障切换换了模型/地区 | 未获买家同意不得替换；可失败退款，不偷换合同 |

流式接口可能在最终结算前交付不可撤回内容，故只有官方支付能力支持相应事前授权、预算控制和后续结算/失败处理时才能启用；图片下载权益的结算后领取逻辑不能直接套用。

## 卖家成交结算与退出

冻结卖家挂牌价、平台费用和渠道费承担；按可信请求/用量形成成交额，扣明示费用后计算卖家应结款，无双价采购模型。授权失效或未知usage不能假记已结算收益。供给者可降低未来可售量或退出，已受理请求按合同履行；不能因挂牌未卖出就要求平台回购配额或退还上游订阅费。

用户之间长期预订/能力包另需：准确期限、容量承诺、自用额度的是否可变、未使用量处理、到期不可结转、上游停服和违约补偿、税费和退回机制。未完成授权与财务安排前保持 P2-AUTH，不承诺所有剩余额度均可变现。

## 启用验收清单

必须完成 P11-T25—T27/T30：授权范围和失效开关、密钥保密、窗口边界/并发/自用争抢、429/超时/重复请求、流中断/缺 usage/预算上限、计费取整、实际卖家成交/佣金/渠道结算对账与退款。使用真实获准上游的受控请求核对，不把本地 mock 的 usage 当作供应商对账证据。

## 本地推理内核与授权上游分离

Windows LLM主路线为lms/llmster/runtime本地封装，Android为LMA二开；这些本地模型服务不以订阅转售许可替代自身引擎/权重许可。已有授权上游连接器继续作为独立供给种类，不将请求转到云端却记为用户本机计算。环境清单/当前授权及真实执行位置须一致。
