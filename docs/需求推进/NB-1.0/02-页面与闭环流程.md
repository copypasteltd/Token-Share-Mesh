# 页面与闭环流程

NB-RD02｜NB-R1｜2026-10-30。布局遵循[五页逐屏规格](../../../dev/design/新粗野主义-v1.0/04-五页逐屏规格.md)，下文补齐业务依赖。

## 1. 页面内动作

| 页面/动作 | 前置条件 | 成功后 | 失败、未知或恢复 |
| --- | --- | --- | --- |
| P01筛选/翻页 | 可匿名阅读公开市场；买家购买需身份 | 保留分类、模式、排序；稳定cursor加载下一页 | 旧数据保留采样时间；条件改变重置cursor；过期数据购买前重核 |
| P01查看服务 | 绑定listing_id、seller_id、revision | 按LLM或GPU进入相应详情 | 下架/离线/过价可查看说明，不能凭旧卡片下单 |
| P02连接网关并继续 | 本人可信程序、独立指纹核验 | 回到同一卖家详情，展示网关已验证；再进入合同确认 | 超时/错误身份保留预算草稿，内容不进入小程序；重连不触发购买 |
| P02确认服务 | 双价、模式、可见方、预算/期限及许可就绪 | 生成冻结报价，用户确认后才建订单/路由 | 价版或对端变更重新确认；资金/计量未就绪只读说明 |
| P03结束会话 | 本人活动session；明确费用截止和不可再执行 | 发同一幂等停止意向，显示停止中→清理中 | 超时显示状态待查；查原session，不新建会话；未知清理不显示可复租 |
| P03查看合同 | 订单存在、本人权限 | 原合同、附约、价费、隐私、准备/起表/截止可查询 | 数据暂缺保持订单号和待查入口，不拼接当前挂牌价 |
| P03联系卖家 | 本人订单、明确沟通权限与对方范围 | 打开订单关联沟通入口，只附必要订单元数据，内容/证据由本人选择 | 当前普通咨询接口未定义，不冒用createDispute自动发争议；未具沟通能力明确禁用原因，纳入GAP-NB06 |
| P04停止接新单 | 本人设备/挂牌、版本匹配 | 先禁新准入，保留当前任务；显示排空状态 | 若并发已有合法准入，显示尾单；无自动强停；冲突刷新 |
| P04编辑挂牌 | 本人草稿/未来价版，明确设备能力 | 保存草稿→资格预检→提交审核→发布 | 缺模型/许可/计量/资金/设备证据逐项显示，不能显示“已上架” |
| P04查看会话 | 本人设备当前有效session，seller角色 | 打开本人会话管理摘要；有买方角色另按本人订单授权进入 | 不因同页查看就获取买方工作区/正文/完整grant；无当前会话给空态 |
| P04添加设备 | 本人原生客户端已安装或查看安装指引 | 一次码/二维码配对→原生确认→探测与基准 | 码过期/已用/错账号重新生成；配对不自动下载模型或开启共享 |
| P05切换资源 | 选中实际listing与价版 | 右栏重置为该资源的模式、报价单位、卖家和可用动作 | 异步旧响应不覆盖新选择；GPU时长不带入LLM的输入输出用量 |
| P05确认租赁条件 | 有效资源、时长、预算、预计总额、佣金说明 | 报价预检→合同确认→订单资金步骤 | 只确认条件不写“已支付/已冻结”；过价重新确认 |
| P05查看合同 | 当前选中资源对应有效quote或已有本人order | 只读展示同版条款，未正式报价先显示“条款预览” | 资源切换使旧预览失效；未确认预览不能当已签合同 |

## 2. 三条闭环

### GPU租赁：发现到结束

1. 买方从P01或P05进入GPU详情，核对个人卖家、RTX型号/显存、能力环境、STANDARD隐私、单价、可租时段和规则。
2. 选择时长/预算；报价计算预计最大服务额，冻结seller、listing/revision、设备/环境、单价、佣金、期限、退款及就绪计时规则。
3. 用户确认，原子消费报价建立订单。实际获准的资金路径满足履约条件后才保留资源；付款页面返回只查原交易。
4. 设备准备，买方连接受控接口并确认ready。准备阶段零费；双方ready、资金与资源代次均通过后唯一进入ACTIVE并签发有截止的会话授权。
5. 租内经已批准OpenAI/Anthropic入口调用模型/媒体能力；图片/视频/音频/3D按profile而非任意节点执行。按确认可用区间累计时间，子调用不另售、不释放会话锁。
6. 买方结束、到期、预算不足或故障触发停止；先撤执行权并限定计费上界，真实停止后核最终区间，清理确认后才复用。账单/退款与设备清理分别展示。
7. 已确认可用租时可以收费，即使买方没有生成满意的作品；已证不可用时间不收费。未用预算不是默认可提现余额；有真实预收才按获准路线处理差额退款。

### E2E LLM：详情到可信调用

1. P02展示阿澄、摩托罗拉X30、协议能力、输入输出双价和基础档边界。买方在本机/可信LAN启动加密程序。
2. 一次性配对、核验端点指纹/程序身份和会话权限；平台页面只接收连接/能力摘要，不持内容钥。小程序无后台常驻能力时按已配对设备控制摘要运行，不要求直接长连loopback。
3. 核对模式、可见方、模型/profile、预算、期限和卖家；确认报价、订单及RouteContract。连接、配对和核指纹都不包含付款或自动购买授权。
4. SDK请求发给本地标准入口。程序核路由后创建INPUT_PENDING/PREPARED上下文，规范化公开上下文并加密内容，经平台盲转交付给固定执行端；通过输入/资金/容量门槛后才签执行租约。
5. 卖方解密程序调用内置转发内核和批准本地引擎；任务内容不进入提供方管理UI/普通日志/公开本机API。响应反向加密回买方；完整认证和终块校验后提供本地结果及签名回执。
6. 按实际可信usage汇总输入/输出账单。流断、usage未知、终块缺失或接受待查按原ID恢复；不伪造0或成功、不自动换卖家重跑、不退化明文。密文交付恢复不再次获得GPU执行权。

普通平台网页与小程序不提供E2E prompt编辑/输出预览/结果解密入口。原生可信程序可以展示买方自己的内容，提供方控制台仅看脱敏任务与资源状态。

### 提供方：设备到收益

1. 本人入驻并确认设备所有/使用权、所在地和收款主体。安装客户端时本人选择目录、引擎/模型及许可，知晓下载量/权限/共享范围。
2. P04添加设备生成配对意图；原生端确认身份并提交能力，实测模型、协议、资源与所需隐私路线。安装、在线、通过基准、已具备可售资格是不同状态。
3. 编辑草稿，选择允许的模型/媒体能力、三模式/隐私、小时价或输入输出M token价、未来时段、条件与平台费；明确确认后提交。核验未通过保持草稿/待审核。
4. 发布后只接符合本人已授权范围的请求。平台选择卖家已披露的合格端点；买方无安装节点/改模型环境/改执行权限权力。
5. 本人可停止接新单、等待排空、申请维护；紧急停止明确履约/赔付后果。内核替换需排空、校验、切换/回滚，不能在ACTIVE租期内无感更新。
6. 收益按成交额、佣金、渠道费、退款、预估净额、应结和实际到账分别显示。预估0.57不代表已结算、可提现或保底，异常只查原渠道和原合同。

## 4. 状态投影

| 维度 | 页面状态 | 事实来源/要求 |
| --- | --- | --- |
| 交易 | 报价中、待确认、订单已创建、取消、完成、售后 | 原订单及不可变合同，不用执行状态推导资金 |
| 支付 | 未支付、处理中、已支付、已取消、失败、待查 | 渠道确认与原号；预算不等于支付 |
| 执行 | 待输入、准备、就绪、执行中、停止中、已停止 | 当前job/session及代次；页面刷新不触发新任务 |
| 资源 | 可接单、忙碌、停止接单、排空、清理、隔离、离线 | 调度/实际清理ACK；无ACK不显示空闲 |
| 网关 | 未配对、待核指纹、未连接、已验证可用、能力不匹配、已撤销 | 本人可信程序的受认证摘要；“在线”不等于可执行 |
| 用量账单 | 估算、已确认累计、最终待核、最终确认、修订、待查 | usage/MeterStatement版本、证据水位和算法 |
| 卖家款 | 预估未结算、应结、争议暂缓、渠道处理中、已到账、待查 | 成交资格和渠道事实；不造钱包余额 |

停止操作立即禁止新调用；计费上界由后端确认的安全停止规则确定，不能用买方可修改的本地时间回填。网络超时保留“停止待确认”且不把等待直接当收费可用段。已停止/已清理/最终账单确认可以不同步出现。
