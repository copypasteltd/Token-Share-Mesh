# 计价、预算与账单衔接

NB-RD04｜NB-R1｜2026-10-30。承接[NB费用展示](../../../dev/design/新粗野主义-v1.0/05-计价单位与费用展示.md)，规定新售业务语义；旧SQL能力差距见GAP-NB01。

## 1. 统一单位

| 场景 | 新售显示/报价 | 真实数量 | 合同要求 |
| --- | --- | --- | --- |
| GPU租赁及租内媒体/LLM | ¥x.xx / 小时 | confirmed_billable_ms | 1小时=3,600,000毫秒，准备/已证故障/清理不计；租内调用不再收费 |
| 独立LLM服务 | 输入¥x.xx/M token、输出¥y.yy/M token | 原始整数token，必要时另列不重叠缓存/推理类 | 1M=1,000,000；模型/tokenizer/模板/缓存口径固定 |
| 时长选择 | 30分钟、60分钟等 | duration_ms | 这是购买时长，不是每分钟单价 |
| 历史订单 | 原合同单位与价版，必要时附精确等价说明 | 原始已确认计量 | 不迁改旧数据或倒算重收；历史文案可解释旧计价 |

0.1M token和30分钟都可以结算；不进位成整M/整小时。为比较不同服务不能将小时价与M token价混合按数字排序；LLM价格排序必须明确输入价/输出价或用户已知用量模型，不造无口径综合价。

## 2. 精度与公式

计价以CNY分和有理数计算，不使用浮点金额。合同冻结币种、分子/分母、计量基准、取整算法版本、平台费/承担和预算。数量/乘积溢出应拒绝，不溢出后截断；跨语言大数采用既有受约束字符串约定。

**GPU新小时语义：** 单价为`hour_rate_fen = n / d`分/小时，确认计量B毫秒，整单同价累计原始金额`n * B / (d * 3600000)`，最终按合同向上取整至分并受已确认预算限制。每次显示的当前金额是该累计口径的估值/已确认水位投影，不对每次心跳、每个子调用或每次续租单独取整收费。

**旧分钟价桥接：** 旧整数分/分钟R精确展示为`60*R`分/小时。新整数分/小时H只有`H % 60 == 0`时才能无损写入旧列`H/60`；否则拒绝旧适配，或完成有理费率/版本化计量迁移后才销售。用户不应收到“页面3.50元/小时、实际按0.06元/分钟”的隐性差价。原生迁移001不得直接改字节，需追加迁移与恢复验证。

**LLM：** 各类互斥原始数量`q_i`、M token单价`n_i/d_i`分，整单原始金额为`sum(q_i*n_i/(d_i*1000000))`，合计后按冻结算法取整一次。第一阶段D采用向上取整至分；输入输出都明确列价。免费组件显式单价0，未知组件不是0；未报价的计费类别不允许临时补收。缓存/推理若属于总输入/总输出先去重，并在批准profile中冻结，不因API字段多一项就收费两遍。

按量前必须有可审计usage来源。平台盲转不能从密文长度猜token；设备签名只证明来源，不自动证明自报数真实。计量不合格的新LLM挂牌关闭按量销售，不悄悄转换成固定请求价。

## 3. 预算、付款与执行上限

预算是买方可接受的最大授权范围，不是已付、已冻结、最终应付或已到账。应用内预算reserve也只是并发控制，不代表渠道冻结。报价必须同时显示预计服务额、预算、最长时长/最大输出和实际收付款状态。

GPU示例：3.60元/小时×30分钟=1.80元，预算5.00元只表示不得超5.00；不会因此自动允许83分钟。LLM预算依据最坏输入/输出上限和已有并发预留核准，在签发前做足够精度的最大费用校验；正在流式执行也受批准的max_output、deadline与有效预算约束，不能等超额后直接把账单截断并继续算。

付款仅使用现有已核实的Machine Pay/获准资金能力。没有个人卖家/退款/费用路径资格则不能正式收费；没有可退预算或适合未知最终量的能力则关闭该组合。不得为了满足UI而臆造冻结、verify后settle、自动token补扣或可提现钱包。

## 4. 统一算例

以下为需求夹具，5%只是示例费率且已含在买方单价内；渠道费未在这些例子另计，不代表实际通道免费。

| 场景 | 精确计算 | 页面结果 |
| --- | --- | --- |
| GPU报价 | 360分/小时×1/2小时 | 总额180分；佣金floor(180×500/10000)=9分，卖家171分 |
| P03当前累计 | 360分/小时×600秒/3600 | 60分；P04对应预估净额57分，未结算 |
| 同价不足一分钟 | 360分/小时×10,001毫秒/3,600,000 | 约1.0001分，整单向上取整2分；不意味着每次上报都收2分 |
| LLM累计 | 1,000,000输入×80分/M + 250,000输出×160分/M | 120分；可以是多请求累计，不宣称支持单次百万上下文 |
| 小LLM请求 | 输入1,000×80分/M + 输出500×160分/M | 原始0.16分，同单最终取整1分；分请求结算与同单累计不能混用 |
| 部分退款 | 原180分、退60分，最终保留120分 | 佣金由9变6分，卖家净额由171变114分；追加冲正差额 |
| 非整分钟小时价 | 350分/小时 | 旧分钟整数列无法无损表示，旧适配拒绝，不改成360分 |

整单定义必须由订单/RouteContract及账单窗口明确。已经最终关账的独立订单不跨单合并取整；同一授权多请求是否同单累计需在合同明确，不能由前端为凑算例随意合并。

## 5. 五种金额状态

| 名称 | 含义 | 允许展示位置 |
| --- | --- | --- |
| 预计总额 | 基于所选时长或用量上限的报价计算 | P02/P05/合同；明确“预计” |
| 当前累计费用 | 已确认用量/可用区间截至水位的累计值，可能修订 | P03；同时给采样时间/待核说明 |
| 最终应付/实付 | 最终账单和实际支付分别给出，不要求相等 | 订单/账单/退款页 |
| 卖家预估净额 | 当前合格金额扣示例/已冻结费用后的估值 | P04“预估服务收入/未结算” |
| 应结/已到账 | 正式成交资格与真实渠道状态 | 结算页；需真实事实，不能用估算替代 |

预算余额、待退款和卖家应结款均不做平台钱包。未知用量/资金显示待查；不能用0、空字符串或绿色成功图标掩盖。
