## 本轮明确的结果

1. 五张图的入口和按钮都对应具体业务状态。连接网关、确认合同、付款、就绪和真正停算是不同动作。
2. 新UI挂牌仅用小时或M token。第一阶段媒体按小时在受控GPU租赁中执行；LLM按M token分别报输入/输出价。旧固定作品/有界请求合同保留历史，不作为无可信计量时的隐式新售退路。
3. 补齐十个辅助界面和三条端到端用户流程。小程序负责交易控制，买方本地程序负责加密数据面，卖方原生客户端负责真正执行。
4. 定义六项契约缺口，分别归属既有DEV任务。R003追加新价格合同与前向002迁移，部分服务层已实现；尚未关闭任何整体缺口，没有把图中按钮当成已有HTTP接口。
5. 登记NB-R001—NB-R048，每项包含一个正向和一个反向场景，均沿用原80项F/T和56项DEV编号；运行验收一律NOT_EXECUTED。

## 权威关系与完成边界

用户最新要求优先。此增量负责五页所涉及的新售范围和业务语义；NB设计源负责视觉、布局与组件；[白皮书基线](../../白皮书/00-阅读导航与需求基线.md)保留80项功能的唯一编号；[技术文档](../../技术开发/00-技术文档导航与实施基线.md)负责工程合同；[开发细则](../../../dev/开发细则总表.md)负责任务拆分。

冲突按主题处理：小时/M token新售规则以本增量为准，旧合同依原价版结算；密码、资源围栏、真实清理和支付资格约束不能因设计简化而放宽。技术旧Schema/SQL尚未承接的项，明确列为契约缺口并禁止开启受影响收费组合。

本轮“完成”指需求已细化、可追踪、文档检查可复核；不是源码、真机、支付或密码验收通过。[核验报告](核验报告-NB-R1.json)只检查编号、引用、覆盖、状态和算例。
