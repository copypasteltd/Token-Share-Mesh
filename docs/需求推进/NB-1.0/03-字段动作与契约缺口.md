# 字段、动作与契约缺口

NB-RD03｜NB-R1｜2026-10-30。字段名为需求语义名，未登记为既有API字段的须通过权威契约修订承接，不能由前端拼成第二份交易事实。

## 1. 共享字段与来源

| 字段组 | 必需信息/校验 | 来源与展示规则 |
| --- | --- | --- |
| C2C主体 | seller_id、display_name、个人卖家公示、buyer_id、本人角色 | seller资格/订单绑定；换角色清理账号缓存；不得按卡片名称推断设备归属 |
| 资源与能力 | listing_id/revision、device_id、具体型号、显存/模型、engine、environment_digest、profile及证据状态 | 已批准能力清单；未知型号不替换成“Android设备”可售卡，卖方可补录后待核 |
| 服务政策 | service_mode、privacy_profile、可见方、disclosure_version、地区和能力约束 | 未来挂牌版与订单快照；STANDARD和PLATFORM_BLIND不合并 |
| 价格 | currency=CNY、计量类型、小时价或输入输出M token双价、整数/有理分、价版、取整版本 | 权威价版；所有换算精确；前端只做共享格式化 |
| 费用 | commission_bps、承担方、是否已含、渠道费承担与政策版 | 未定不能用演示5%代填；含佣金的买家总价不重复相加 |
| 报价/授权 | quote_id/expiry、terms_hash、预算、最大时长/输入输出、期限、路由scope、确认时间 | 服务端预检；用户确认具体terms；报价过期重新取价 |
| 网关 | paired_client_id、验证状态、fingerprint、协议能力、last_verified_at、撤销状态 | 受认证可信程序摘要；不含私钥、prompt、媒体URL或结果 |
| 执行与时长 | order/session/job、状态版本、started_at、hard_deadline、confirmed_billable_ms、水位、采样时间 | 当前有效代次与证据；UI倒计时仅估算，前后台恢复重查 |
| 用量 | raw_input_tokens、raw_output_tokens、缓存/推理口径、模型/tokenizer/模板版、source、verification_state | 缺失为unknown/null，不伪造0；含/不含子类先去重 |
| 账单 | statement_id/revision、估算/累计/最终性质、gross、commission、net、paid、refunded、settlement_state | 账单/渠道事实；同时展示时间和版本，迟到旧响应不能覆盖新版本 |
| 安全错误 | safe_code、request_id、是否可重试、状态待查标识、下一步 | 屏蔽原始上游包/敏感URL/内部栈；恢复查原ID |

公共市场只披露必要的具体型号和能力，不公开设备序列号、MAC、内网地址或原始硬件指纹。配对码、会话凭据、API key只在授权的一次展示场景可见，不进入URL、分析埋点或普通持久缓存。

## 2. 五页所需数据

| 页面 | 必须取得 | 禁止前端自行推导 |
| --- | --- | --- |
| P01 | 分页公开挂牌投影、卖家/型号、模式、价版、双价/小时价、资格和可用摘要 | “在线”直接推导可售；混合单价排序；隐私标签靠设备种类生成 |
| P02 | 原挂牌版、模型/profile、可见方、双价、预算草稿、可信网关状态 | 连接成功推导已下单/已付；平台从密文估算token |
| P03 | 原订单/会话、合同、有效区间账单、预算/截止、清理和资金独立状态 | 当前挂牌价回填旧单；本地计时直接收费；停止HTTP200等于已清理 |
| P04 | 本人设备/挂牌、资源政策、当前会话摘要、本人净额/结算投影 | 把别人的X30并入本人；gross当net；客户端安装当可售 |
| P05 | 市场比较、选中挂牌、报价预检/合同和费用 | 旧资源报价用于新选择；LLM输入输出两个价压成无说明“起价” |

异步结果以选择版本和实体版本双重核验；不能只取消前端请求就认为旧响应不会到达。普通数据可短期缓存且标时间；账号切换、撤销、停止或模式变更立即失效相关缓存。

## 3. 对接既有控制操作

下列INT编号已存在于[开发细则机器清单](../../../dev/contracts/development-plan-v1.0.json)，只说明归属，不表示接口已实现。标准AI数据入口仍由OpenAI/Anthropic profile约束，不纳入此控制操作表。

| 场景 | 既有INT / operationId | 约束及缺口 |
| --- | --- | --- |
| 公开市场 | INT-062 listServices | 按实际批准组合筛选；明确返回脱敏卖家/型号/双价投影，详情读取缺口见GAP-NB02 |
| 报价/订单 | INT-020 createQuote、INT-042 getQuote、INT-017 createOrder、INT-038 getOrder、INT-056 listOrders | 报价消费唯一；资金和执行均绑定原单；需要GAP-NB01价版 |
| 支付/退款 | INT-019 createPaymentIntent、INT-041 getPayment、INT-022 createRefund、INT-044 getRefund | 按既有Machine Pay适用能力；UNKNOWN查原号；没有新冻结/自动补扣接口 |
| 标准SDK路由 | INT-028 createRouteContract、INT-047 getRouteContract、INT-061 listRouteContracts | 固定seller/mode/privacy/profile/budget/expiry；新购买授权与普通重试分开 |
| 对端身份 | INT-043 getRecipient、INT-078 registerRecipient、INT-021 createRecipientRotation、INT-083 revokeRecipient | 只能承接收件身份，不能将其假称买方本地网关已完成配对；见GAP-NB03 |
| 租赁准备 | INT-026 createRentalSession、INT-073 recordRentalDeviceReady、INT-005 confirmRentalReady、INT-023 createRentalAccessGrant | 双方ready和资金/环境/围栏通过才起表；凭据一次显示 |
| 租赁运行/停止 | INT-046 getRentalSession、INT-045 getRentalMeterStatement、INT-084 stopRentalSession、INT-072 recordRentalCleanup | stop与cleanup是不同权限；买方不可代填清理ACK |
| 续租/导出 | INT-025 createRentalRenewal、INT-024 createRentalExport | 本人显式确认同价附约；导出受原会话授权与期限约束 |
| 提供方设备 | INT-018 createPairingIntent、INT-032 enrollDevice、INT-057 listOwnDevices、INT-035 getDevice、INT-089 updateResourcePolicy、INT-031 drainDevice、INT-082 revokeDevice | 原生确认、actor/owner/version；停新单与强停分别处理 |
| 提供方挂牌 | INT-016 createListing、INT-040 getOwnListing、INT-058 listOwnListings、INT-088 updateFutureListing、INT-085 submitListing、INT-063 pauseListing | 本人未来价版；当前ACTIVE合同不变；整机停止接单需GAP-NB05定义 |
| 收益/售后 | INT-059 listOwnSettlements、INT-050 getSettlement；既有争议模块 | settlement不等于活动订单净额，需GAP-NB04只读投影 |

## 4. 六项必须关闭的契约缺口

不在此文擅自增编INT/DATA或修改已执行迁移。下面明确交付要求和责任；实际改动先进入权威OpenAPI/SQL/编号登记并重建，而非让前端绕过。

| 编号 | 当前差距 | 必须形成的契约与兼容方案 | 承接任务 |
| --- | --- | --- | --- |
| GAP-NB01 | R003已增加NBPrice双价/小时合同、计算及报价建单；旧Price保留LegacyPrice，租赁表仍为整数分/分钟 | 继续完善租赁会话/续租/最终账单/预算/usage及旧报价读端。小时价精确适配或新有理价率存储，禁止静默四舍五入 | DEV-08/09/12/34/38、DEV-02迁移 |
| GAP-NB02 | 公开市场与详情未完整冻结个人卖家、具体型号、能力/价版投影 | 规定公开字段白名单、分页/筛选、单项按id+revision读取、未知型号/资格状态；明确复用listServices还是新增详情操作，再登记 | DEV-06/07/08/45/47 |
| GAP-NB03 | recipient身份不等于买方本地程序配对；小程序直接连loopback不可假设 | 一次性配对意图、本人程序确认、独立指纹和能力摘要、到期/撤销、账号绑定；控制摘要不得包含内容钥。平台经认证控制通道承接小程序，实际内容在本地/LAN；需真机验证 | DEV-29/30/45/47/53 |
| GAP-NB04 | 渠道结算列表不能直接提供正在执行订单的“预估收入0.57” | 权威只读账单投影：order/seller、statement版本、水位、gross/费/net、估算性质、渠道状态、修订/退款；无新增钱包或出款语义 | DEV-34/38/39/40/46 |
| GAP-NB05 | “停整机接新单”不能靠前端依次pause多个挂牌保证竞态安全 | 资源政策版本的原子准入关闭、与已准入lease/session的分界、幂等/恢复；界面显示排空中的合法尾单；明确updateResourcePolicy与drainDevice权威边界 | DEV-06/18/20/21/43/46 |
| GAP-NB06 | 五页未完整表达调用能力、动作与可售证据的关联；普通“联系卖家”无咨询契约 | 对profile/模型/媒体/隐私/计量/资金及UI动作返回资格与safe_reason，前后端共核；咨询与争议分离，后续冻结订单关联沟通的双方权限/通知/内容最小披露后再登记操作。无能力不假装发送，协议未知字段先拒绝 | DEV-07/09/26/27/45/47/49/52/56 |

六项缺口整体均未关闭；R003已推进项记PARTIALLY_IMPLEMENTED，其余为REQUIREMENTS_DEFINED_NOT_IMPLEMENTED，逐项登记源及[实施约束](../../技术开发/附录-NB价版与交易服务实施约束.md)记录范围。静态Schema或应用服务测试不能宣称页面及整套业务运行可用。

## 5. 幂等、权限和数据一致性

所有写动作由已认证主体发起；scope+owner+实体状态+版本同时核验。报价确认、创建订单/支付/退款/租赁、停止及配对消耗使用稳定幂等键；If-Match或等效版本冲突提示刷新，不能静默最后写胜出。网关重试或小程序前后台恢复不能扩大购买授权。

相同请求超时保留原id和键查询；改变卖家、模式、价版、预算或期限属于新确认流程。UI禁用按钮只改善体验，不能替代后端唯一性和资源门闩。资源/执行的双围栏、原支付号和追加式账证沿用既有规范。
