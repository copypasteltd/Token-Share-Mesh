# 范围与需求决策

NB-RD01｜NB-R1｜2026-10-30。

## 1. 产品与端侧分工

这是个人用户之间出售闲置设备服务的C2C市场。卖方决定设备、模型、允许的能力包、未来价格、共享时段、充电/温度/网络条件和是否接新单。平台匹配、维护合同和预算、执行准入及账证规则。买方决定实际卖家、服务、模式、隐私、预算、期限和是否接受报价。

| 端 | 第一阶段职责 | 不得暗示的能力 |
| --- | --- | --- |
| React + Taro支付宝小程序 | 市场、合同、支付控制、订单、设备摘要、挂牌、收益与本地程序配对摘要 | 小程序后台持续推理、代持E2E私钥、远程任意安装组件 |
| React + Vite Web | 资源比较、合同、开发者路由、复杂挂牌、受控管理 | 普通平台网页成为可信解密端或随意读取本机服务 |
| 买方本机/可信LAN程序 | 标准协议入口、独立核验对端、加解密、内容/结果、本地接受、转发内核 | 连接即授权付款、平台代恢复内容钥 |
| Windows/Linux提供方原生程序 | 设备配对、执行槽、组件管理、受控执行、计量、停止清理 | 小程序替代物理设备或无感升级正在履约的内核 |
| Android LMA派生程序 | 具体手机本地执行、标准协议桥、前台共享通知、充电/热条件 | CPU伪装GPU、APK外任意可执行代码热更新、整卡GPU租赁 |

Windows/Linux隐私LLM采用可嵌入llama.cpp原生worker及受控管道，LM Studio CLI/daemon/runtime作为可替换兼容分支；媒体为完整ComfyUI原生环境和有限白名单。执行内容对提供方UI隐藏，组件来源、安装、资源占用和收益状态对本人透明。普通本地防护不承诺管理员或高级内存分析不可见。

## 2. 三模式与新售组合

下表是需求设计范围，不是已开放商品目录。所有行还受许可、真实设备、协议、计量和资金资格共同约束。

此处“本阶段”指五张图优先承接的交易主链，不删除原F34/F35/F76的加密媒体等平台需求。未进入该主链的组合继续保留需求及默认关闭状态；只有计费/信任/协议/资金合同完整后才进入新的实现切片。

| 模式 | 本阶段新售组合 | 计价展示 | 内容处理 | 未验证时 |
| --- | --- | --- | --- | --- |
| PLAINTEXT 明文 | 桌面/手机LLM；上游仅获许可组合 | 输入、输出分别¥/M token | 平台转发域和执行域处理明文；UI按权限展示 | 无可信usage不销售按量服务，不换成隐藏固定价 |
| E2E 基础加密 | 本地/获准上游LLM + 买方可信程序 | 输入、输出分别¥/M token | 平台不持内容钥；执行设备/实际上游处理明文 | 未连接、指纹未核、协议不合格则不提交内容；不降明文 |
| GPU_RENTAL 受控显卡租赁 | 合格GPU提供的ComfyUI图像/视频/音频/3D及已批准LLM能力 | ¥/小时，确认可用毫秒结算 | STANDARD；受控API、模型和配方，不给shell/任意节点 | 准备/资金/独占/真实停清任一未满足则不执行 |
| 增强E2E、加密GPU租赁 | 独立远期/条件组合 | 沿相应基础单位 | 必须证明完整保护路径 | 默认关闭，不展示“硬件隐私已验证” |

模式描述信任和执行合同，不是主题色或设备类别。同一物理GPU可登记多种能力，但同一时刻所有引擎、模式、自用共资源门闩；不能用多个挂牌绕开占用。

**媒体按小时的落地决定（D-NB01）：** 为避免创造尚无计量证据的“单次生成小时价”，本阶段媒体统一通过受控GPU租赁的会话可用时间计费。买方租期内发标准API请求，调用不再按图、视频件数或token叠加收费。按件合同仅作历史能力；今后若需明文/E2E媒体独立按时任务，须另定排队/预热/失败/交付各阶段计费和契约，不能把GPU忙碌时间直接冒作可收费时间。
