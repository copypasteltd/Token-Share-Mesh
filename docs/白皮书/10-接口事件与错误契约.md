# 控制接口、事件与错误契约

P11｜v3.0｜2026-10-29｜[OpenAPI草案](contracts/openapi-control-v3.0.json)为本项目自有控制面设计；兼容模型接口遵循冻结官方档位，支付/引擎实际字段由真实协议决定。没有服务已上线。

## 1. 分层与通用约定

模型/媒体：/v1/chat/completions、/v1/responses、/v1/messages与对应媒体子集。业务控制：/v1/p11。密文通道：由控制面签发限scope/有效期的channel引用，HTTPS/WSS承载自有帧；帧schema单列，不宣称OpenAPI描述了完整WebSocket状态机。

控制面Bearer凭据分买方/卖方/设备/后台权限，路由key不自动拥有账户/结算权限。写入提供Idempotency-Key；更新版本化资源同时比较expected_version/If-Match，重复同键不同输入409。渠道回调不强制私有header，按官方验签/去重适配，不能套自有模拟回调当接通。

分页使用opaque cursor/limit和稳定次序，默认20、最大100为D；无权限对象按404或一致拒绝隐藏存在性。日期UTC，钱为分，大序号规范字符串。返回request_id、资源版本、服务端时间和安全错误；所有示例为虚构ID，无真实凭据。

## 2. 接口组与权限

| 组 | 主要资源/动作 | 权限与关键检查 |
| --- | --- | --- |
| 身份/卖家 | seller applications/profile、api-keys、route-contracts | 本人或受控审核；原key只一次显示；自动购买范围明确 |
| 挂牌/目录 | services、seller/listings创建/读取/改未来版/提交/暂停 | seller归属、证据有效、版本比较，无静默旧价变更 |
| 设备/网关 | pairing-intents、enrollments、devices/capabilities/heartbeats/drain/revoke | 一次性配对、owner、设备scope，撤证不接新任务 |
| 报价/订单/支付 | quotes、orders、payment-intents、payments查询 | actual seller/contract/预算冻结，资金未知先查，不假定已到账 |
| 任务/产物 | assets/register/complete/transfer-grants、jobs/create/read/cancel/results | 输入归属/类型/大小、attempt/token、短时单对象访问 |
| 加密 | encryption-intents、recipients登记/读取/轮换/撤销/证据/挑战、envelopes、buyer receipts、cipher channels | 目录只有公钥不代替独立信任；端点绑定、签名/版本、防重放 |
| 租赁 | rental-sessions/create/get/ready/device-ready/renewals/stop/availability/access-grants/statement/cleanup | 双端就绪、预算、有效区间、撤权/清理后复用 |
| 执行端 | runner leases/claim、attempt progress/delivery/usage/cleanup | 签名租约、当前job token与跨job resource_lock_generation、seller/resource，重复不重跑 |
| 账/售后 | refunds、seller/settlements、reviews、disputes/appeals | 订单资格、原资金引用、选择性举证、最小必要权限 |
| 后台 | evidence、releases、feature-gates、settlement-batches/approve/submit、audit | 分权/复核/证据，不得强开无许可/无渠道组合 |

OpenAPI逐操作列request/response模型、认证、幂等要求及关键状态码。对象内只保留该调用必要字段；列表与详情不能泄露卖家KYC或其他买家订单。PUT/PATCH未来新增字段需有版本兼容策略，不默默忽略关键字段。

登录/会话引导需选择正式身份服务并按其真实协议实现；本草案的/me读取已认证角色，不把支付宝登录接口或OAuth流程伪造为已接通。短时对象URL是受权传输凭证，不进通知、日志和公开文档；E2E平台只发密文对象，解密端只在买方可信域。

## 3. 主要请求结构

QuoteRequest：listing_id/version、sku_id、service_mode/privacy_profile、public_spec、protocol_profile_id、budget_fen、desired_region；E2E无prompt/私密URL。QuoteResponse增加seller、contract_hash、费用/期限/证据与接受政策。合同引用只能来自当前授权主体，不能把他人quote_id换进本单。

JobRequest：order/version、stable caller key及deadline上界；明文引用已就绪input_asset_refs，E2E先引用encryption_intent_id建立INPUT_PENDING/PREPARED的job/attempt/token/recipient，再认证加密上传并POST当前envelopes及input_asset_refs。PREPARED无执行权且不占GPU，输入/封装、资金、许可及资源通过才ISSUED；端点改变须新上下文与买方重封。客户端deadline只能缩短合同上界，不能延长服务端计算期限；不接受任意workflow JSON/shell。ReceiptRequest的job来自路径，体内绑定attempt/token、delivery_id/revision、cipher_manifest_hash、decision、signer/key、signature、receipt_id；签名上下文还绑定合同，服务器核唯一合法决策，不只检查签名字符串非空。

RentalRequest：quote/指定device/env、max_duration_ms、confirmed_budget_fen、disconnect_policy；ReadyRequest引用双方连接/基准与版本，RenewRequest显式新预算/期限/价版及付款能力。UsageInterval含seq/start/end/source/evidence，不能自报任意未来区间。

ListingWrite：未来版本、设备集合、SKU/模式/地区、开放时段/容量、价格/费用承担及接单策略；expected_version防覆盖。SettlementBatchRequest只引用已合格不可变ledger IDs和实际payee，审核/提交分别角色，不接受任意收款账号/客户端应付金额。

## 4. 错误合同

| 业务码 | 控制HTTP | 客户端下一步 | 重试边界 |
| --- | --- | --- | --- |
| AUTH_REQUIRED / TOKEN_REVOKED | 401 | 本人重新认证/换有效key | 不用旧key无限重试 |
| SCOPE_DENIED / PRIVACY_MISMATCH | 403 | 选有权限的明确合同 | 不自动降隐私 |
| RESOURCE_NOT_FOUND | 404 | 查本人正确引用 | 不枚举他人ID |
| IDEMPOTENCY_CONFLICT / STATE_CONFLICT | 409 | 查原状态/重新确认版本 | 不换随机key重扣未知单 |
| ASSET_EXPIRED / QUOTE_EXPIRED | 410 | 重查权益或新报价 | 不自动沿旧价格执行 |
| INPUT_TOO_LARGE / TYPE_UNSUPPORTED | 413/415 | 缩小或改允许格式 | 不重复传原坏包 |
| CAPABILITY_UNSUPPORTED | 422 | 按已发布能力调整或另确认服务 | 不静默丢字段 |
| CAPACITY_LIMIT / RATE_LIMIT | 429 | 遵安全Retry-After并重新核授权 | 不绕限速/换账号 |
| CHANNEL_ELIGIBILITY_MISSING / EVIDENCE_INVALID | 403 | 对应能力不可售/补证 | 无证不能重试放行 |
| PAYMENT_UNKNOWN / EXECUTION_UNKNOWN | 409 | 查原transaction/request | 不重复购买/执行 |
| RECIPIENT_CHANGED / ATTESTATION_INVALID | 409/403 | 本地重新核验或停止 | 不静默换钥/降档 |
| CIPHER_INVALID / STREAM_INCOMPLETE | 400/502 | 拒绝接受，查原交付/故障 | 不补成功终态 |
| BACKEND_UNAVAILABLE / SERVICE_UNAVAILABLE | 502/503 | 按合同查询/有限同卖家恢复 | 不跨卖家池切换 |
| DEADLINE_EXCEEDED | 504 | 查终态/退款 | 不延长原预算/期限 |

控制面错误为error.code/message/retryable/request_id和安全details。OpenAI入口用其error结构，Anthropic入口用其type:error及error结构，request-id放适当头；内部P11原因以允许的code/安全message表达，不硬塞不兼容顶层字段。SSE已起流的错误按该方言，HTTP不能再改。402由真实支付适配按官方需要生成，不自造支付宝字段。

## 5. 事件目录与载荷

统一EventEnvelope包含event_id/type/version、occurred_at、recorded_at、actor/service、aggregate_type/id/version、correlation/causation、idempotency/evidence refs与最小安全payload；无prompt、钥、原始URL和完整上游包。生产者与订单归属核验，不能信任任意设备上传“PaymentSettled”。

| 事件族 | 典型事件 | 消费者/副作用 |
| --- | --- | --- |
| 资格/市场 | SellerApproved、CapabilityQualified、ListingPublished/Paused、LicenseRevoked | 目录/准入刷新，失效仅关受影响新售 |
| 合同/资金 | QuoteConsumed、PaymentAuthorized/Settled/Unknown、RefundConfirmed | 准入/权益/交易账，状态分别保存 |
| 执行/交付 | AttemptIssued/Expired、DeliveryAvailable、PlatformAccepted、BuyerAccepted/Rejected | 当前token/版本条件更新，唯一有效接受 |
| 密钥/证明 | RecipientRevoked、AttestationExpired、RewrapRequired | 停放钥/买方重新确认，不默认平台解密 |
| 租赁 | SessionReady/Started/Stopped、AvailabilityConfirmed、CleanupAck/Failed | 起表/截断/清理与资源锁，不能自动TTL复用 |
| 财务/售后 | TradeQualified、CommissionAdjusted、SellerSettlementEligible/Unknown、DisputeOpened/Resolved | 唯一账、渠道查单/冻结/冲正和申诉 |

事务写业务及Outbox，后台至少一次投递；消费者用event_id/聚合版本去重并幂等应用，乱序需要查权威状态。持久失败进入死信并告警/人工处理，不能无限重试支付副作用。资金/交付成功不通过事件重复产生第二账项。

## 6. 版本、签名和兼容

API path版本、协议档位版本、事件schema版本、工作流/模型版本、价费版本分别管理。签名必须绑定规范上下文和真实性验证，字段增删需明确canonical版本；禁止在未知签名版本下“尽量接受”。旧读端遇新枚举显示未知安全态，写端不接受未发布能力。

技术v1.0将尚未发布的Lease设计细化为同时签入resource_id/resource_lock_generation：job fencing_token保护同任务重派，资源代次保护不同job先后使用同卡的旧消息。PREPARED不分配资源代次、不签执行租约；正式准入才分配。此为设计契约补全，尚无产品消费者；实际profile冻结和跨端验证见技术文档。

Lease还固定capability/执行manifest引用及hash、not_before/issued_at/hard_deadline与单调lease_revision。progress响应ProgressAck的CONTINUE必须带新版本完整签名Lease；STOP/NO_CHANGE不带续约，不把普通Ack当续权。新旧版本/总截止/同资源代次均须客户端验证，网络失败在旧有效截止停止。

契约草案须通过引用/类型/必需字段/路由唯一性检查；真实SDK、密文互操作、资金和硬件仍需对应测试，JSON合法不能宣称整个接口正确。

## 内核绑定的契约细化

CapabilityWrite增加kernel_environment_ref/digest；Service与ContractSnapshot包含kernel_bindings，Lease增加kernel_environment_digest，内部适配命令的执行/恢复动作也要求该摘要。Rental环境修订和签名grant必须解析到不可变环境；续租不改内核。字段属于本平台控制/执行合同，标准OpenAI/Anthropic JSON仍不增加私有必填。失配在执行前拒绝/停新售；状态可能已执行时查原ID。
