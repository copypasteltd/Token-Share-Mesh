# 端对端加密、威胁模型与密钥生命周期

P11｜v3.0｜2026-10-29｜关联F32—F40、F52/F72—F76。协议结构为D，密码实现/独立评审/增强硬件为E；本文件不是已验证密码产品。

低开销完整方案（最新用户确认）：用户允许新增隐私档可嵌入LLM内核，LM Studio继续保留兼容。采用llama.cpp C API原生worker、ComfyUI私有管道入口、LMA内部JNI；买卖端加密/平台盲转，任务数据加密而模型保留原生加载，不使用VM/RAM盘/常驻第二份模型。输入准备和密文交付不额外占GPU锁，控制与大数据通道分离。内存/性能为待实测验收预算，完整链路、二进制协议、媒体、恢复及PE-01—PE-08见[完整实施方案](../技术开发/附录-低开销隐私执行完整方案.md)。当前尚未实现或通过设备/密码/性能验证。

本地隐私目标修订（2026-10-29）：用户将当前目标收敛为拦住初级/中级用户的日常查看与普通工具读取、增加本地拦截成本，不以高级内存分析为验收目标。首期推荐原生低权限隔离、任务级密文工作区及文件/日志/引擎API出口封闭；TEE/保密GPU不是此前提，普通VM只作可选评估。这是独立的本地防护策略，不新增服务模式、不把普通端改标ATTESTED_CONFIDENTIAL；原有硬件增强保留为独立远期能力。既有“基础档所有者可见”表示技术上仍可能访问，不表示默认向提供方展示内容。具体动作与LP-01—LP-14见[本地防护规范](../技术开发/附录-本地内容隐私防护与分级验收.md)，全部待实现/未执行。

## 1. 信任边界

| 对象/攻击 | 基础PLATFORM_BLIND | 增强ATTESTED_CONFIDENTIAL |
| --- | --- | --- |
| 正常平台存储/运维读取正文 | 内容不进入平台明文管线 | 同基础 |
| 平台主动换公钥/程序 | 独立端点确认、可核验发布/更新必需 | 还须买方策略的新鲜完整证明与受控放钥 |
| 卖方主机管理员读取执行内容 | 不防，须明确披露 | 必须在已证明威胁模型范围内阻止，不能由普通进程保证 |
| LAN网关管理员 | 网关是被披露且受信的处理方 | 网关解密本身必须进入保护区，否则不合格 |
| 上游API服务商 | 授权调用时可见，合同披露 | 本版增强不开放外部API |
| 时序/大小/参与者/必要账务元数据 | 可能可见 | 仍可能可见，不承诺匿名/无侧信道 |
| 买方被攻陷、主动泄露、拒绝服务 | 不由E2E完全解决 | 不因增强就消除 |

加密保护内容机密性/完整性，不证明生成质量、算力真实性、公平交换或设备管理员诚实。平台必须保留滥用元数据治理和有限风险机制，不能以不可见推导无责任/无风险。

## 2. 密钥角色

| 密钥/凭据 | 持有方 | 作用与禁止事项 |
| --- | --- | --- |
| 平台API/路由key | 买方本地或获准服务 | 身份/范围/预算引用；不是内容钥，不直接代表付款授权 |
| 设备认证/签名身份 | 卖方设备受保护存储 | 配对、租约/回执来源；不能用硬件序列号替代 |
| 内容接收公私钥 | 已确认执行网关/增强保护区 | 接收输入；平台不持私钥，不发给供给池 |
| 买方回传公私钥 | 买方程序 | 接收结果/流，私钥不上平台 |
| 对象/流内容钥 | 对应端点临时持有 | 每请求/方向/对象独立生命周期，密钥/nonce不复用 |
| 上游凭据 | 获准卖方连接器，或明文明确托管库 | 不给买方/平台普通日志；托管路径不能标平台盲 |
| 发布/更新签名 | 分权发布体系 | 验证软件来源，不能单独阻止被信任发布者恶意更新 |

平台不提供内容万能恢复钥。买方自有备份需端侧加密、主动选择并明确丢钥影响；不借云同步/崩溃诊断把内容钥放到平台。设备身份恢复不等于内容钥恢复。

## 3. 初次信任、轮换与撤销

首次确认实际卖家及网关指纹，可用独立证书链/独立渠道核对等已批准机制；仅平台签公钥目录不充分抵御恶意平台换钥。将seller、gateway identity、key_id、区域、环境/模型及privacy policy绑定到RouteContract和EncryptionIntent。

轮换优先旧钥签新钥与撤销状态核对；旧钥丢失则走重新身份确认，不静默接受新钥。撤销后不接受新输入/租约，已密封旧数据按原权限结束/失败处置；不能在平台后台替买方转封。增强环境更新、重启、调试变化、证明到期均重新验证。

## 4. 握手与输入

1. 仅公开规格生成报价，确认实际卖家/模式/预算并创建EncryptionIntent；意向本身不赋GPU执行权。
2. 买方验证接收身份，增强档验证challenge、measurement、公钥/策略和有效期；不通过不发内容钥。
3. 确认业务订单与资金条件后创建INPUT_PENDING任务及PREPARED尝试上下文，返回job/attempt/token、指定recipient和输入截止；此时没有执行租约，不锁GPU、不运行后端。待输入须受意向有效期/合同截止限制，超期按未执行处理。
4. 买方本地校验输入和政策，构造私密请求包（原始协议、正文、媒体/工具、私密元数据），将上一步上下文绑定认证加密；上传当前订单/attempt的密文对象并提交封装清单。流式请求先完成该上下文握手再发送认证帧，不向平台提交明文标准请求。
5. 平台复核意向/合同/当前token、完整输入或流授权、许可/资金/容量，原子准入后才把PREPARED转ISSUED并发执行租约。端点变化必须废旧上下文并由买方核验新端重封，不能拿旧密文直接换端。卖方先核执行权再解密，经端点内核执行。

同卖家换端需买方验证新接收身份/增强证明并重新封装或重加密；不能原样授权所有设备读取。买方离线无法放钥则按原期限结束，不转明文、跨区或跨卖家。

## 5. 密码与序列化设计

当前优先PoC统一为libsodium sealed box封装随机内容流钥、secretstream XChaCha20-Poly1305认证顺序记录、独立Ed25519签身份/上下文。sealed box不认证发送者，须独立身份签名及授权；HPKE仅保留为另一未来suite，不混用格式或向量。精确库版本、CGO/C++/JNI绑定及独立评审仍未冻结，不自行拼nonce。工程细则由[加密协议实现设计](../技术开发/08-端到端加密协议与密钥实现设计.md)统一维护。

签名/关联上下文采用明确版本、规范序列化；候选[RFC8785 JCS](https://www.rfc-editor.org/rfc/rfc8785)。签名前拒绝重复JSON键、非有限数、非法Unicode及未声明字段；大计数器采用十进制字符串或有界整数，不受JavaScript精度影响。正文原始字节在密文内，不能把可猜prompt明文哈希公开作字典索引。

关联数据绑定protocol/version、contract_hash、order/work_item、seller/recipient/key、attempt/token、direction、object/stream、delivery revision、epoch、sequence及终态承诺。上下文更改认证失败；上下文身份签名、AEAD完整性与交易执行授权是三种不同验证。

崩溃/重连只重传既有密文或使用新的安全epoch/钥，不从旧序号重新加密。持续状态写入失败时安全停止，不能冒险复用key/nonce。密码实现须有测试向量、随机性/nonce生命周期审查和真实多语言互操作，mock只用于状态分支。

## 6. 帧、终块与媒体

外层Frame包含版本、流/对象/合同/端点引用、方向、epoch、序号、ciphertext/hash、有限大小及期限；payload内区分HEADERS/DATA/USAGE/ERROR/END/CANCEL。内容状态、标准协议事件和详细错误均受加密，不把敏感厂商响应放外层reason。

每一帧验证身份/权限、上下文和完整性；乱序最多进入有限缓冲，超窗/重放/串单拒绝。END承诺最终序号/数量/摘要及完整/失败状态，缺终块不能标完整成功；关闭socket不替代END。取消也有上下文和权限，防止伪造终止别人的任务。

图片/视频/multipart/base64/附件/工具结果均保护；输出URL不能指向平台明文文件。买方可返回符合契约的base64，或本机/可信LAN短时受权解密端点；Range读取先认证分块与清单，不交付未经认证字节。平台能看到密文大小和必要计费数，不承诺隐藏流量特征。

## 7. 本地接受、用量与争议

买方验格式/尺寸/数量/模型契约、完整终态和必要usage证据，回执绑定合同、attempt/token、交付版本、密文清单、decision、时间与去重ID。接受与拒绝/取消/超时以服务端条件更新确定唯一结果。签名证明用户授权端发出了该决定，不证明主观质量。

无接受回执的固定任务默认UNVERIFIED及退款/释放，不生成成功佣金或卖家款。可能已解密而拒付的风险无法靠撤URL解决；挂牌前约定限额/反滥用/可接受损失。流式分段接受另有事前授权、累计回执和渠道支持门槛；没有就不临时按节点自报补扣。

争议可由买方选择性披露指定坏包/字段/截图，生成独立授权与证据副本；不交整批私钥，不强迫上传全部历史。未披露内容时平台只能裁定可验证的身份、时序和密文事项，不能伪称看过画质/提示词遵从。

## 8. 增强档准入

证明必须覆盖接收钥绑定、随机挑战、新鲜度、固件/驱动/安全调试状态、CPU/GPU/互联、工作负载/模型/内核、编码/日志/网络出口、有效期与撤销。买方策略或独立可信验证者决定放钥，平台不得同时具有绕过策略放钥和读明文的权限。

参考裸机保密方案也有受信租户/软件和硬件假设；[NVIDIA CBM](https://docs.nvidia.com/confidential-computing/bare-metal/dev/)存在不代表当前消费级节点合格。解密在普通主机、GPU之后普通编码器、第三方内容审核API或未保护日志任一处泄漏都不满足增强。本地禁虚拟化约束保持；依赖被禁环境的路线不实施。

## 9. 清理与事故

平台密文输入终态后24小时、结果默认7天；端点成功交付/会话结束1小时、失败/离线重连24小时补清为初拟上限。删除覆盖缓存、派生预览/日志、临时钥和恢复状态；备份有独立滚动清理。基础档不能证明恶意所有者没有私存副本。

疑似钥泄漏、换钥攻击、明文路由或证明失效时立即关闭相关新售/放钥，撤销/轮换身份，隔离证据，核在途与实际内容影响；通知和责任处理按真实事件/适用要求，不把事故日志再次变成泄密副本。

## 内核替换与增强档证明

基础档只对平台隐藏内容，lms/llmster/runtime、ComfyUI/Python/节点/编码及LMA二开进程的设备所有者仍可能读取明文。增强档须保护上述实际完整路径并将kernel_environment_digest及节点依赖纳入证明；替换或目录漂移使旧测量失效，重新验证后才能放钥，不能先升级再沿用旧证明。

## 10. 当前加密方案的完整落地约束

双端为买方本机/可信LAN网关与指定卖方受限服务。卖方的解密、BoundRelayCore、模型/编码器在受控本地路径中处理明文；平台只见合同允许的元数据与密文。提供方了解安装组件、版本、模型/节点、资源、状态、收益及停止权，默认不能从UI打开买方prompt/预览/原始日志。普通进程依然存在所有者攻击边界，本地日常防护不改标硬件增强。

| 方面 | 需求细则与异常处理 |
| --- | --- |
| 两个方向的钥 | 买方生成输入流钥、封给指定卖方接收公钥；卖方生成独立结果流钥、封给买方结果公钥。每attempt/对象/方向/epoch新钥，控制流/缓存/签名另分用途 |
| 独立信任 | 首次核实际seller、签名身份、接收钥/指纹和环境，不能只信平台目录；TOFU不证明首次没有换钥。买方回传钥同样防替换 |
| 平台无恢复钥 | 丢钥/重装只能恢复未来身份，不自动解旧结果；买方可主动选择端侧加密备份，不默认平台托管 |
| 轮换撤销 | 正常轮换提供旧身份签名链并核新政策；泄漏/撤销停新放钥/执行，原合同不自动重标；撤销无法收回已解明文 |
| 前向保密限制 | 本候选静态接收钥将来泄漏可能解旧sealed材料；不声称完整前向保密，升级成熟会话协议另行评审 |
| 签名与AAD | C摘要进入sealed私密载荷，身份签名覆盖完整unsigned流头H，H摘要与线记录长度/序号进入AAD；互不自引用 |
| 调度字段 | PREPARED的job/attempt/token/recipient用于事前加密；尚未知资源代次在ISSUED签名租约另核，准备不锁GPU、不运行模型 |
| 正文覆盖 | JSON/SSE/multipart/附件/工具/私有URL/详细错误和usage都加密；公开计费只独立最小证据，明文hash留密文内 |
| 终态与回执 | END记录本身用库TAG_FINAL，另核标准协议终态；SSE可实时给已认证前缀，最终接受仍需买方验收策略/决定及签名回执 |
| 计算与交付 | 真停算/清理后释放GPU；原结果密文可按原attempt/token、交付版及对象权补传/签收，不要求仍占卡，也不获新计算权 |
| 故障恢复 | 只重传原密文字节；丢push状态需有效授权的新epoch/钥/header，后端UNKNOWN先query，不重做推理或拼新SSE |

网络低开销候选BINARY_STREAM_1采用≤16KiB已签流头、8字节序号与有界二进制记录；解密后整记录≤64KiB、DATA≤65528字节，单流共享4MiB/重排32条且2MiB。JSON_COMPAT仍是单独旧外壳，新增档位须先补channel协商/版本契约、独立Schema及黄金向量，不宣称旧JSON Schema已覆盖。

LOCAL_SEGMENTED_1为独立本地存储档：每对象独立钥、1MiB段/每段新header和单消息FINAL、加密完整manifest、逐段认证、只读seek，无原地覆写。网络顺序流不能直接随机Range；买方完整顺序认证/终块与清单后由本人受权缓存提供。媒体64MiB为明文上限，低开销档密文对象66MiB、spool256MiB及设备总额另限；JSON2MiB仍含Base64，不放大原SDK请求限制。

静态身份钥由专用账号OS秘密存储保护；临时流/工作区钥尽量只留RAM，任务文件首次写盘前加密，公开模型/权重原生只读加载。不增加VM、整盘解密层、RAM盘、全片副本或第二份模型。正文TCP/WS/普通日志出口须按实际内核关闭；LM Studio兼容分支不借原生worker的隐私验收。
