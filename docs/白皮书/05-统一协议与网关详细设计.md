# 统一协议、网关与引擎适配详细设计

P11｜v3.0｜2026-10-29｜关联F28/F54/F59/F69—F80；继承[已确认网关需求](../协议/统一API与本地加密网关需求.md)。本文字段/映射为拟建协议合同，未运行SDK或网关。

低开销完整方案（最新用户确认）：用户允许新增隐私档可嵌入LLM内核，LM Studio继续保留兼容。采用llama.cpp C API原生worker、ComfyUI私有管道入口、LMA内部JNI；买卖端加密/平台盲转，任务数据加密而模型保留原生加载，不使用VM/RAM盘/常驻第二份模型。输入准备和密文交付不额外占GPU锁，控制与大数据通道分离。内存/性能为待实测验收预算，完整链路、二进制协议、媒体、恢复及PE-01—PE-08见[完整实施方案](../技术开发/附录-低开销隐私执行完整方案.md)。当前尚未实现或通过设备/密码/性能验证。

当前实现以[07协议转发细则](../技术开发/07-统一协议网关与Sub2API改造.md)和[字段/工具映射](../技术开发/附录-协议字段映射与兼容档位.md)为细化依据；A402头和模型JSON分离，三方言不能默认无损互转，支付宝小程序默认非流式/控制任务轮询。

## 1. 组件和权限分工

平台明文网关接收标准HTTP请求并在可见内容范围内校验/转换；平台密文服务只验证外层身份、租约、大小和信封，不调用正文解析器。买方程序提供本机/可信LAN兼容入口，持买方内容钥并加解密；卖方网关持执行身份和本地连接器凭据，在允许边界解密/执行/加密。

Relay Core抽象为协议入口、能力校验、合同准入hook、格式映射、后端适配、流式pump、取消、候选usage、脱敏错误九个模块。合同/支付/资源锁由本平台权威服务决定，内核不能自行轮换卖家、扩预算、完成资金结算。配置/更新/遥测和数据流隔离；普通日志默认没有正文。

Sub2API改造先冻结repo/commit、许可/依赖、模块图和补丁；协议/连接器可复用，余额充值/默认平台自营/全局池跨卖家failover/正文预览必须裁剪或禁用并验收。Android使用轻量模块或等价实现，不承诺完整中心Go服务及数据库可直接上手机。

| 档位 | 必需能力 | 条件扩展/拒绝 |
| --- | --- | --- |
| OPENAI-CHAT-TEXT | POST /v1/chat/completions，messages、model、已声明生成限制、JSON/SSE、正常/失败终态 | tools、视觉、JSON schema等需模型/适配器支持；未知语义参数明确拒绝 |
| OPENAI-RESPONSES-TEXT | POST /v1/responses，无状态input/instructions及已声明输出项、JSON/SSE | store/previous_response_id/background/厂商内置工具仅在独立实现时开放 |
| ANTHROPIC-MESSAGES-TEXT | POST /v1/messages，冻结version/认证、system、content blocks、max_tokens、JSON/SSE | thinking/cache/beta/多模态/工具按实际能力，签名不透明块不能伪造 |
| OPENAI-IMAGES | /v1/images/generations或edits的已冻结JSON/multipart子集 | 工作流/尺寸/数量/返回形式白名单，不把自有async路由冒充标准 |

## 3. 标准调用与合同解析

调用者使用普通Base URL、API key、模型及协议字段。平台/本地网关从已明确确认的RouteContract解析actual seller/listing、模式/档位、地区、模型/协议、价费/预算及自动购买范围，不需要在标准JSON中新增必填seller_id/service_mode。

处理顺序：接入鉴权→解析路由合同→协议/能力静态校验→预算/授权与seller资格复查→执行准入/资源→记录request/order映射→转发→按模式接受/候选计量→对应标准响应。加密内容校验在买方/卖方端；平台不能为上述静态校验解密，只核公开能力合同。

无配置、多个模糊配置、过期授权或请求与合同冲突均拒绝；API key有权限不代表可自动付款。402仅在真实官方适配路径需要时生成，标准SDK本身不一定理解支付挑战；需网页/本地程序完成购买确认或已有授权后再调用，不能宣称任意SDK原生支持A402自动付款。

## 4. 映射规则

| 语义 | 必须保留 | 拒绝条件 |
| --- | --- | --- |
| 身份/认证 | 入口Bearer/x-api-key/version等白名单，区分本地key/平台凭据/设备/上游key | 将调用者认证直接转其他域；不识别version/beta却继续 |
| system/developer/角色 | 原角色优先级、多个内容块顺序、模型实际语义 | 后端不能表达所需优先级；不能简单拼接字符串假装无损 |
| 工具 | tool call ID、名称、参数、并行索引、结果关联、选择策略 | 缺关联/参数不合法、不支持强制工具却丢字段；默认不执行宿主工具 |
| 终止 | 正常结束、长度限、工具请求、拒绝、超时和取消的区分 | 把错误转stop或为兼容补完成事件 |
| usage | 原始来源、模型/tokenizer、input/cache/output/reasoning包含关系 | 不真实的0/null/估算冒充必需计量字段 |
| 推理/思考块 | 入口有定义时保留真实性及不透明字段 | 改写/编造厂商签名，跨模型把签名当有效 |
| 上下文/状态 | 无状态完整输入，或确有权限的同买家/卖家/模型状态 | 跨卖家沿用会话、不支持store却假装保存 |
| 媒体 | MIME、字节、尺寸/数量、URL权限和输出契约 | 任意URL/路径抓取、不支持返回形式却悄改格式 |

temperature/max_tokens/max_output_tokens/stop/response_format等逐档位定义范围与映射。可忽略字段必须在档位显式声明不影响承诺；影响用户意图的未知字段在执行前拒绝。别名仅是公开映射，不能冒用官方模型品牌或偷偷换模型。

## 5. SSE与HTTP生命周期

OpenAI Chat的chunk/choices/delta与Responses的语义事件、Anthropic的message/content_block事件分别实现。内核处理多字节UTF-8、跨块JSON、空增量、并行工具增量、最终usage及标准结束原因；不能只取text字段。

尚未发送响应头时，失败返回对应安全HTTP状态/JSON。已发送SSE头后，只能发送该档位允许的错误事件或异常终止并保留查询引用；不能改写HTTP为另一状态，也不补message_stop/response.completed/[DONE]假装完成。链路close与正常生成完成不是同义。

本地HTTP断开触发带上下文的cancel，后端停止证据单独记录；连接关掉不保证计算已停。启用有界缓冲/背压、首包/空闲/总期限；达到上限按合同终止，不无限占内存。断线重连只重传已记录帧，不把重新生成拼成原流；标准SDK不支持续流时明确报中断。

## 6. 明文/密文transport

明文：标准请求→平台内核→绑定卖家网关/受控适配器→批准后端，响应走原路及必要验收。密文：标准请求→买方内核预检/信封加密→平台opaque relay→卖方解密/内核→后端，响应在卖方端加密，买方还原。

cipher relay只路由有权的order/work_item/attempt/recipient，不根据正文做格式转换、内容审核或token估算。公开错误与内部密文错误分离，厂商错误里的prompt/URL不能进入平台通用错误字段。高敏输入不写tracing baggage或支付附言。

建立加密上下文时先创建INPUT_PENDING任务和PREPARED尝试，取得job/attempt/token/recipient；此阶段没有执行租约且不占GPU。买方按该上下文加密上传/封装，全部资金/输入/许可/资源条件通过才ISSUED。端点变化先废旧上下文并由买方核验重封；具体顺序见[加密握手](06-端对端加密与密钥生命周期.md)，不能为“先上传还是先有attempt”省略认证绑定。

## 7. 幂等、重试与预算

持久关联caller_request_id、route_contract/order、attempt/token、backend_id、stream/receipt/usage。相同显式幂等键同输入返回已有状态/结果，不同输入409；只对scope内可证明的同一次调用判重。相同正文可能是两次合法请求，不以内容哈希全局去重。

SDK无稳定键时，高费用使用应配置关闭自动重试或由调用端显式提供稳定键；网关重试自身transport不新购。可能已执行/扣款未知时查原请求/渠道，不能再自动下单。跨卖家须确认新单，同卖家有限重派也不突破原期限/预算；已输出流的接收端变更不能透明拼流。

预算既控制max_output/请求尺寸，也控制有效授权、单请求/累计消费及并发。不可精确预估时采用公开上限；无法限制最坏费用的计量服务不开放。预估不会直接转正式扣款。

## 8. LAN、管理接口与发布

默认127.0.0.1/::1鉴权；LAN显式启用、绑定接口、HTTPS/配对/允许访问方/撤销，校验Origin/Host并限制CORS。管理接口不与推理key同权限，无通用CONNECT和任意base_url，目标地址/重定向/DNS变化防SSRF；后端允许列表由本人/许可配置，买方无法修改卖方目标。

发布包提供原生启动/停止、版本、端口冲突和证书/钥轮换说明；SDK配置样例只能含占位凭据/实际批准模型ID。新版先对固定合成样例回归，再按可售组合灰度，失败关单组合，不能让旧客户端把密文识别为明文。具体机器契约见[接口事件](10-接口事件与错误契约.md)。

## 新内核路线的协议约束

转发层不因CLI内核更新改变厂商语义；Windows LLM通过lms管理的专用本地API推理，ComfyUI四类媒体走批准配方，Android采用LMA二开的轻量转换。音频采用已批准Audio子集，音乐/3D使用明确声明的Responses结构化资产结果档位；未知字段或没有标准语义的请求执行前拒绝。所有路径核不可变环境，E2E不回送平台明文核心。

## 加密transport的完整合同引用

[技术08](../技术开发/08-端到端加密协议与密钥实现设计.md)统一双向接收钥/身份签名、规范流头/封装/AAD、BINARY_STREAM_1/旧JSON分档、终态/回执与故障恢复。平台不接正文/详细HTTP头/usage/ERROR，不导入端点转换；卖方核执行授权后在受限服务里完成语义转换，结果再加密给买方。channel协商/二进制Schema/跨端证据未完成不发布新档位。

标准SDK只改已披露Base URL/凭据/版本；不强制私有JSON字段。原SDK中断不无条件重购；原密文可按独立交付权限补传，不要求仍占GPU，也不获新推理权。买方完整认证后本地Range，网络流与本地分段缓存分别验证。

## R018 控制面领取实施状态

R018新增原设备签名领取原租约：35/93个控制操作、65表/664列/113外键。仅原设备ED25519证明可领取；原命令编号与header相同，010将其固定绑定原lease并和安全事件原子提交。每次包括重试都重新核原买方scoped key/route、原订单与同单资金、资格、完整已占预算、加密输入元数据、原owner/双围栏和原期限；不换单、不重签/续租。领取服务只有显式公钥，不解密输入、不确认实际执行或计费；DELIVER任务、预算和资源保持原状。设备独立公钥/批准计划、输入/manifest交付、宿主持久执行命令、真实内核/usage/渠道及E2E/LP/PE/租赁仍待。001—009及端侧DDL保持原字节，历史UNBOUND_CLAIM。

模型正文仍遵循原OpenAI/Anthropic档位。领取是设备签名控制操作，不向标准SDK增加私有模型JSON字段；完整CL-001—028见[技术细则](../技术开发/附录-原设备签名领取与原租约交付.md)。80项主验收状态不因该子集改变。

## R019 受限明文交付

R019接通已领取原租约的执行清单和原始输入受限交付，当前37/95显式控制操作、65表/664列/113外键。INT-094/095先登记权威契约与固定编号；两个GET仅接受原签名设备，不隐式领取。每次读取沿同一原订单优先锁序复核原买方key/路由/同单资金/资格、完整已占预算、原设备版本、输入、物理owner/双围栏和原期限。独立交付服务无签发私钥，输入必须通过原AES-GCM/AAD、独立版本化HMAC和同档位Preflight，按原始字节返回。客户端用独立公钥、原订单/路由/模式及本机内核批准核验清单和租约，有界接收输入；不自动批准内核或提交模型。此为PLAINTEXT/STANDARD可信平台经认证连接交付，密文摘要不能当原文明文签名，不是E2E或卖方不可见。领取/读取均不ACK、不续期、不重派、不完成DELIVER任务、不计费/清锁。001—010及端侧DDL原字节保持；真实宿主持久命令、tokenizer/内核/usage/渠道、E2E/LP/PE/租赁和完整验收仍待。

具体见[DG-001—030](../技术开发/附录-原设备清单与输入受限交付.md)；80主验收不因这两个原生控制GET改变。

## R020 本机内容适配衔接

R020新增持久原生执行宿主：独立issuer公钥与原订单/本机内核批准，原领取命令在网络前加密保存，丢回执和重启始终恢复原编号。清单/输入有界接收，正文仅在内存，通过显式InputAdapter交给原生一次提交监督器；旧receipt不能重送正文。清理状态只投影原执行账本的同lease/metadata凭证。损坏索引不能隐藏原命令，缺库/错绑定拒绝重建。Windows DPAPI/私有ACL复用，Linux仅交叉构建及既有钥环协议夹具。新增host-init/host-status，不自动安装或运行模型，execution_enabled仍false。只覆盖PLAINTEXT/STANDARD三文本profile，元数据加密不等于E2E或设备所有者不可见。真实tokenizer/内核、输出回传/usage/ACK/续期、支付渠道、LP/PE/租赁和完整验收仍待；37/95控制操作及65表/664列/113外键保持，旧SQL001—010与原执行DDL字节不变，新宿主SQLite独立首发。全部56任务/222子项及R016/R019慢元数据未证明根因风险保留，目标ACTIVE。

[EH-001—036](../技术开发/附录-原生执行宿主与内容适配接线.md)；三协议正文仍沿原请求规范，不添加私有模型字段，80项主验收不因宿主库存在而改变。
