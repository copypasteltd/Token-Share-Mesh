# 计费、支付、渠道结算与争议处理

2026-10-30新售计价以[NB-R1费用衔接](../需求推进/NB-1.0/04-计价与账单衔接.md)为准：GPU小时有理分单价/确认毫秒，LLM输入输出M token双价/原始整数token。R003新增NB_PRICE_1合同及报价/订单应用服务，Price以LegacyPrice与NBPrice互斥分支兼容历史；[实施约束](../技术开发/附录-NB价版与交易服务实施约束.md)列明已实现子集。租赁/账单/可信用量等GAP-NB01尚未闭合，未承接组合不收费；旧合同按原版保留。媒体先通过STANDARD受控GPU租赁提供，租内不叠加作品或token费。

P11｜v3.0｜2026-10-29｜关联F08/F09/F17—F21/F27/F39/F44—F46/F53/F61/F77。费率/渠道费用/结算日为H/E，金额公式为D设计；没有真实收费或到账。

本轮按[支付宝收单技术细则](../技术开发/13-支付退款账务与渠道结算.md)覆盖旧概括：当前Machine Pay采用precreate→402/amtPaymentLink→付款→Payment-Proof/verify→唯一履约；单笔≤50元、pay_before≤当前后12h。最新API的resource_id废弃/可选，本地原号绑定seller/服务/合同。不能臆造verify后settle、可退冻结或事后token补扣。即刻收直付创作者为候选，个人算力与平台费仍需资格；直收不得再次平台出款。

## 1. 资金权威和计量单位

实际seller与获准渠道收款关系绑定；平台提供佣金/结算证据服务，不以普通平台账户归集再个人转账代替C2C资金资格。不自建可转让/可提现钱包，内部应结记录不是现金余额。Machine Pay提供的按量收款方向不自动证明预算冻结、个人卖家分账/托管/出款已获准。[官方产品](https://aipay.alipay.com/products/machine-pay)。

CNY全部用整数分；协议数量保留原始单位、精度和来源。token种类明确互斥/包含关系，时长存毫秒，单价存有版本的有理数/最小货币单位，不用二进制浮点做资金计算。中间乘法使用足够精度/防溢出，跨语言JSON大计数器用受约束字符串，显示层才格式化元。

| 类型 | 形成成交的证据 | 不可作为正式计费依据 |
| --- | --- | --- |
| 历史固定图/视频/有界文本 | 原合同的唯一合格接受及最终收款；不作为本轮新售单位 | GPU忙碌/部分图/上传进度/未验收 |
| 可信用量服务 | 版本化usage、必要买方接受/回执及上限 | 卖方随意自报、不可核估算、丢失usage时猜数 |
| GPU租赁 | 就绪后确认可用区间/最终MeterStatement | 利用率、心跳次数、等待准备/清理、失联检测尾段 |

## 2. 价格和预算

挂牌价由卖家设置，费率/费用承担公示。报价冻结单价、数量/最大输出、计量版本、费用、最坏应收上限、取消/退款和期限；改未来价格不改旧单。自动购买授权有卖家范围、单笔/累计预算、次数及失效时间，撤销阻新请求但不伪造取消已交付用量。

初拟卖家侧订单佣金，没有默认买家附加费。正式commission_bps和channel_cost_owner未定，缺失时不能以示例值收费。最低费/小额合单/促销需显式规则与渠道支持，不因1分钱佣金不足就在后台补扣。

## 3. 计算与算例

历史固定任务依原冻结价与接受数量结算。新LLM各类原始数量q_i与每M token有理分价p_i，明确不重叠，整单累加Σ(q_i×p_i/1000000)，按冻结规则取整一次并受预算约束；缓存/推理含在总量先消重。无可信口径关闭新售按量，不隐藏切旧固定请求。

新小时价n/d分租费：`charge_fen=ceil(n*verified_billable_ms/(d*3600000))`；须在执行前及运行期间保证授权用量不越确认预算和期限，不能超额执行后仅把账单截成预算。同价续租累计一次取整。旧整数分/分钟按原价版精确适配；当前SQL只支持旧分钟同价续租，新有理小时价会话/续租仍待实现；变价须结束原会话确认新单，不把分段价设想当已支持能力。

初拟佣金：`commission_fen=floor(retained_qualified_gmv_fen*commission_bps/10000)`。部分退款重算最终保留成交额及佣金，追加差额冲正；不是在原全额上永久抽佣。

| 纯假设场景 | 结果/边界 |
| --- | --- |
| 成交100分，佣金20%，通道3分平台承担 | 卖家应结80分，平台佣金20分/通道成本3分；不是100分平台收入 |
| 同单退40分，其他费不变 | 保留60分，佣金12分，原佣金冲回8分；渠道可退部分按实际合同另记 |
| 租价30分/分钟，有效9分10秒，已付300分 | 应收275分、退25分，再按275分算佣金 |
| 成交1分，佣金15%向下取整 | 佣金0分，不能自动加隐藏最低费；平台仍可能亏变量成本 |
| 卖家承担费用超过成交款 | 上架前调整明确费用承担/可售门槛或拒售，不自动形成可外扣负钱包 |

这些费率/金额均为算例，不是当前真实价格或收益承诺。卖家净额未扣其电费、损耗、网络、税费及机会成本。

## 4. 支付适配与异常

适配器至少返回可履约凭证、最终结算凭证、收款归属、金额/币种/失效时间、原渠道交易号及可查询状态。真实接口字段由SDK/合同决定，白皮书控制面字段不是支付宝官方字段。通知验签、查询与重复回调必须核seller/order/金额，前端成功页不是证据。

| 情况 | 允许动作 | 禁止动作 |
| --- | --- | --- |
| 授权成功未最终结算 | 按获准模式执行并分别记状态 | 直接称实收/可提现 |
| 支付请求超时UNKNOWN | 查原渠道交易/限制新售，保留对象 | 立即再扣一笔或标明确失败 |
| 支付晚到能力已失效 | 核原合同可履约性，不行退款/释放 | 改卖家/隐私/价后直接执行 |
| 交付成功最终结算未知 | 保留结果/证据，查原交易 | 让买方重买相同服务、重复结卖家款 |
| 渠道不支持该用量/个人卖家 | 关闭对应新收费能力，沙箱标清 | 切成平台自营代售或普通私转绕资格 |

## 5. 账、对账与渠道结算

内部账采用不可变事件/分录，event/evidence/transaction去重。每笔交易分别追踪GMV、退款、佣金、渠道费用、卖家应结净额、实际渠道结算和平台补偿；按明确费用承担验证金额守恒。差异只能追加冲正/调整及理由，不允许后台直接改历史金额。

SellerSettlement状态为PENDING_EVIDENCE、DISPUTED、CHANNEL_ELIGIBLE、SUBMITTED、SETTLED、UNKNOWN、REVERSED、FAILED；FAILED仅在渠道/权威证据确定失败后使用，UNKNOWN不能当失败重出款。渠道结算/到账时点以真实产品定义为准。初拟观察/周结/最低额并未批准，正式周期、尾款、争议保留及最低费必须核渠道与用户权利，不能无限扣款。

渠道结算批次按seller_payee和合格证据构造，一个有效应结项仅进一个有效批次；制单与复核分权，出款前重查资格/退款/冻结。UNKNOWN查原batch/item，禁止重发导致双到账。每日对账保留渠道脱敏文件/查询证据、差异责任和处理时间。

## 6. 退款和责任

固定任务未执行取消全退，运行中以取消/接受竞态决定，无法完整交付依合同全退；可信用量与租赁按本类已履约证据，不能套同一全退按钮。退款申请不等于到账，原退款号查询；可退额不超过实际已收减已退/在途保留，不跨币种或扣他人款。

退款分别冲成交、应结卖家款、佣金及实际可退渠道费。已实际结算后的退款按渠道及责任处理，不从卖家外部账户擅扣；必要追偿/平台责任单列，未知不重复操作。平台营销退款与卖家违约冲正不能混在一起。

加密固定任务无接受回执默认UNVERIFIED/退款或释放，不造成功佣金/收益；卖方计算损失按公示合同处理，平台仅对自身过错或独立限额保障负责。默认不提供无限垫付和保底采购。

## 7. 争议SOP和时限

受理→核资格/冻结受影响应结项→收集合同/资金/时序/交付证据→区分技术规格/主观质量/资金/责任→双方陈述→有理由决定→渠道执行/冲正→申诉→关闭。不得冻结无关卖家或全部历史款。

客服初次响应/材料/决定/申诉时限列为待渠道与团队确认的配置，发布前须明确用户权益及超时升级；未知支付初拟最长7天进入有责任依据的处理决定/申诉，不把7天变成自动吞款。加密举证只要求指定可选副本，不索整批历史钥；证据不足时说明可裁定边界。
