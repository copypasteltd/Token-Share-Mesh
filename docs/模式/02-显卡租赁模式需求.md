# 显卡租赁模式：完整需求

P11｜v3.0｜2026-10-29｜关联 P11-F41—F48、F51—F56。目标是交付可用算力时间；当前仅为需求，未出租设备或接入计时支付。

完整深化与实施细则见[白皮书阅读导航](../白皮书/00-阅读导航与需求基线.md)和[80项逐项实施规格](../白皮书/15-需求逐项实施规格.md)。本文件保留快捷需求入口；v3.0新增详规、契约和追踪，不代表软件已实现。

C2C约束：设备由用户自愿挂牌，卖家自主定价/时段；订单绑定实际卖家，平台收明确佣金。同单只可在同卖家已披露设备内按约重派，跨卖家结束原单并经买家确认新单。资金与责任见[交易规则](../交易/C2C交易与市场规则.md)。

工作区内的模型/媒体调用统一经OpenAI/Anthropic兼容入口，由Sub2API类内核转给受控应用。子调用usage仅用于诊断/配额，不改变有效可用时长计费，不增加按张/token费用；标准租赁仍不自动获得加密。若未来启用加密租赁，需买卖端本地网关及独立验收，见[协议与网关](../协议/统一API与本地加密网关需求.md)。

本次供给内核修订：Windows LLM以lms CLI＋llmster＋可替换推理runtime封装；图像/视频/音频/3D以完整ComfyUI原生内核及有限节点白名单封装；Android基于LMA源码二开。Linux原生双引擎保留。详见[内核封装与替换规范](../技术开发/附录-供给端内核封装与替换规范.md)，当前均设计待实现，第三方许可/实机证据未取得。

## 产品定义和可用范围

供给为真实Windows/Linux＋GPU，支持ComfyUI、LM Studio/llmster的经测专用受控环境。同GPU两引擎共锁，买家下单选择允许集合中的一个固定内核环境；租内可切换其清单内批准模型/配方，换引擎家族或版本须结束清理后按新环境重新确认，不能沿旧grant热换。Android作为本地服务供给不在本版整卡租赁范围，不能把手机执行槽假称独占物理显卡。

买家租用一张明确设备身份的实体 GPU，在购买时段内独占一个受控推理工作区，可选择已上架的应用/模型/工作流和参数、反复调用、查看队列、取消自己的任务并导出产物。卖家将自己的连续可用时段自主挂牌，向买家交付，按确认成交额扣明确费用取得收益；不要求必须生成多少张图才算出租成功。

首个产品明确命名“受控整卡时租”。租赁对象包含 GPU 使用槽、最低经测 CPU/内存/磁盘配额、网络限额、环境/模型清单、API 工作区与清理服务，不是个人电脑管理员权限。买家不能远程桌面接管供给者、读取其他目录、任意运行 shell、pip 安装或上传执行自定义节点。此限制在下单前显示，不以“通用裸机”销售。

任意代码/训练/完整裸机控制可另立专用整机产品，必须单独解决系统接管、网络、软件许可、租户间隔离与恢复。普通 Windows 个人主机不能仅靠一个任务目录安全承载不可信任意代码。本次不调度 Docker/WSL/虚拟机，也不以这些环境实现隐藏的租赁隔离。

## 供给上架与独占规则

供给清单必须含：device/gpu_resource_id、GPU/显存与驱动、可用时段、是否兼做显示、实际基准、兼容环境、初始预加载模型、CPU/内存/磁盘/带宽边界、区域、隐私属性、卖家挂牌分钟费率、平台费率和渠道费承担、最长租期、准备超时、故障/强停补偿和清理策略。

优先使用供给者不用于显示或个人工作的专用显卡；无法可靠避开本机占用则不上架“独占”产品。一个 `gpu_resource_id` 同时只能处于服务任务、租赁准备、租赁活动、清理中的一种，租赁期间不接其他买家的任何模式任务，也不允许供给者自用计算。初期每节点只开放一个活动槽。

平台锁和客户端占用检查可以防自身超卖；无法对恶意电脑所有者证明绝对没有其他进程占 GPU。合同通过可信准入、占用异常检测、买家基准、争议和停供管理落实，不能把它宣传成硬件强隔离。供给者的自用保留设置用于决定是否出租整卡，不能一边保留半张卡一边出售整卡独占。

## 买家与供给者流程

买家：筛设备/环境/区域 → 选择最大租期和预算 → 阅读可见方/权限/故障规则 → 报价与短期占位 → 支付路径验证 → 准备环境 → 连接性和基准就绪确认 → 开始计时 → 工作区调用/取消/查看 → 明确确认续租或结束 → 最终时长/退款账单 → 获取已选择导出的结果。

供给者：审核与基准 → 配置连续可用时段、未来挂牌价/平台费用确认及环境 → 接受租赁合同 → 预留/准备 → 租期内保持在线且不自用 → 排空结束/异常强停 → 清理确认 → 待确认收益 → 争议窗与出款。普通“暂停接新单”不应中止活动租约；供给者强停需要显示买家损失和合同责任。

## 状态机和就绪验收

```text
REQUESTED → RESERVED → PREPARING → READY_WAIT_BUYER → ACTIVE
ACTIVE → STOPPING → RECONCILING → CLEANING → CLOSED
ACTIVE → FAULTED → RECONCILING → CLEANING → CLOSED
RESERVED/PREPARING/READY_WAIT_BUYER → EXPIRED/FAILED → CLEANING → CLOSED
```

另有独立支付/退款状态，不把 RESERVED 当成已到账、ACTIVE 当成已最终结算。

设备占位初拟 90 秒；付款/授权及准备期限由真实支付合同冻结，准备超时初拟 120 秒、买家就绪确认窗口 120 秒。占位与准备期间不对买家计 GPU 租时，不允许无限等待。初始要求的模型加载、连接探测和标准基准通过，平台与买家共同确认 `ready_receipt` 后，服务端下发开始凭证并记录 `started_at`；收到凭证前不放行买家工作任务。准备失败全额退款/释放授权，供给不计成功租时收入。

READY 需要同时证明：资源锁属于本会话、环境版本正确、资源预算达标、工作区端到端可连接、约定样例运行成功。仅“节点在线”“显卡型号正确”不算交付。买家迟迟不确认则释放资源，不偷偷开始计费。

## 计时、预算与账单

租时计量的是可用独占时间，不是 GPU 利用率或节点自报忙碌时间。ACTIVE 中买家闲置、正常排队、自己选择切换已支持模型所花时间计费；平台/供给故障不可用、初始准备、结束后的清理不计费。控制面使用可信时间与持久事件，客户端时钟只能辅助诊断。

初拟按分钟列价、按毫秒累计可确认的有效时段，最终以整数分只取整一次：

`买家应收分 = min(已确认预算分, ceil(分钟单价分 × 可计费累计毫秒 / 60000))`

计量区间不重叠、不可覆盖旧事件，重传去重；退款为已确认实付减最终应收。续租未改价时同一会话汇总取整，不在每次心跳、任务、断线或页面刷新时取整；变价续租需新价段和明确确认，各价段计费口径在合同写明。

纯算例：每分钟 30 分、确认最多 10 分钟/300 分；有效使用 9 分 10 秒，应收 275 分，若实际预付 300 分则退 25 分。该费率不是实价，无独立采购费率，卖家净额按最终成交额扣明示费用计算。假定某支付产品允许这种退款型预付也必须先实测；不支持则该计费方案不启用，不自建余额钱包或假称具备预算冻结权限。

平台与节点初拟每 10 秒确认可用性，保留单调序号、会话/token、上次确认点和累计有效区间。失联后，不把等待 45 秒租约超时的全部时间算成已证明可用：未确认区间先不计费，按最后有证据的确认点截断；买家可提出更早故障证据并复核。虚假遥测不等于独立性能证明。

## 工作区访问、断线与续租

每个会话有租户范围令牌，只可操作本会话队列、允许的应用参数和文件；令牌绑定设备、GPU、环境、期限和 fencing_token。底层 ComfyUI 仍绑定 loopback，经出站受限会话网关访问，不暴露公网 8188，不把完整本地 Web UI 或控制面管理权交给买家。

订单须明示 `keep_running_on_disconnect`。默认客户端断开后保留最多 60 秒以便重连，期间设备仍可用则计费；之后停止活动会话并按实际可用时长结算。买家可在预算内主动选择断线继续运行，直到已确认的时间/金额上限；关闭网页不是无限授权。无法可靠确认客户端存活时采用明确的会话心跳/恢复规则，不用 TCP 状态猜测意图。

显示剩余时间和预算，初拟提前 60 秒提示。续租由买家主动确认新的最大时间/预算，重新检查供给连续可用时段、价格、权限和实际付款能力。未确认不续租，余额或报价变化不自动授权加价。到期本地 Runner 和控制面分别限制新任务并停止本会话执行，重启/时钟回拨不能延长租约；断网不得自行延长。

若运行任务预计超出租期，默认在准入时提示并拒绝明显无法完成的任务；估计并非保证。买家选择在剩余预算内尝试时，必须看到到期会中止且不保证产物完成。不能因任务未完擅自延长收费。

## 故障、退款、节点更换

| 情况 | 租期/费用处理 | 交付或赔付 |
| --- | --- | --- |
| 准备/就绪失败 | 不起表，全退实付或释放授权 | 供给无租时应付，平台原因准备成本按合同单列 |
| 买家主动提前结束 | 到实际停止/撤权时结算已确认可用时间；停止延迟不额外收费 | 退未使用部分，不按整段原价收取 |
| 买家参数错误/空闲/自愿中止任务 | 环境持续可用的时间计费 | 不因没有产物退全部租时 |
| 节点掉电、驱动崩溃、供给者抢占/强停 | 可用时间截断，故障时间不计费 | 退未用部分；已损失产物/额外补偿按预先合同和责任证据处理 |
| 平台工作区不可达 | 从可证故障点停表，恢复须新就绪确认才续计 | 买家可结束；不强迫等待无限恢复 |
| 到期任务未完成 | 不再计费，按本会话停止规则处理 | 不保证未完成图/视频可恢复；下单前披露 |
| 支付/退款/计量未知 | 不超既有预算，不重复支付 | 查原流水、冻结相关应付，最终对账后展示 |

出租的 GPU 不自动变成另一台设备。故障默认结束原会话并出具时长账单；新节点需买家确认新合同、环境和数据去向。可迁移数据只在买家授权后转移，加密组合还需重新放钥，不承诺普通 ComfyUI 内存进度可无损迁移。

## 隐私、清理与复用

初始 STANDARD 档采用安全通道、平台受限网关和受授权处理；平台/供给者可能看到内容，不能用“独占”保证机密。后续 PLATFORM_BLIND 会话复用端对端基础档身份和加密协议，另完成会话测试；供给者仍可见。增强档租赁不在本版本可售组合内。

停止先撤销所有会话令牌并中止对应专用引擎任务；节点确认停止后清空输入/输出/模型临时缓存和工作区密钥，记录清理回执，才能解除 GPU 资源锁。失联或清理失败进入隔离，不能只因平台 TTL 到期就卖给下一个人。平台无法证明恶意主机没有私留副本，跨租户残留检测必须实际执行。

活动工作区提供明确磁盘配额；结束时可选择导出的结果按 7 天结果政策保存，其余工作区数据在线节点应在关闭后 1 小时内清理。离线重连先补清，未清理前禁售；合同最长清理处置初拟 24 小时，超时进入人工处理。用户自己的原有模型不误删；是否保留经许可的公共模型缓存单独列明，不保留私人输入。

## 核心验收

同时买入任务服务和租赁不得超卖；准备阶段账单为零；同会话多任务不按张重复收费；正常空闲计时而故障不计时；重复/乱序心跳、客户端时钟回拨、服务重启不改变预算上限；断线到期能停止而不无限续；故障更换设备须明确确认；清理前无法再出租；前一租户文件/队列/令牌不可被下一租户读用。独占与实际吞吐用真实设备验证，不能仅靠模拟心跳证明。

## 本次内核路线对本模式的约束

本模式下的执行环境由提供方主动选择并经平台批准，Windows LLM用CLI体系、媒体用完整ComfyUI/有限节点，Android用LMA源码二开。环境摘要进入合同/当前执行授权，既售任务或有效租赁期间不可安装节点/替换内核；更新先停新单/排空。基础加密仍对设备所有者可见，增强需覆盖全部实际组件的真实证明；Android整卡/默认增强限制不变。
