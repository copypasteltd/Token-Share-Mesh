# 端对端加密模式：完整需求

P11｜v3.0｜2026-10-29｜关联 P11-F31—F40、F48、F51—F56。两档均已纳入需求，当前没有已验证的加密实现或保密硬件节点。

低开销完整方案（最新用户确认）：用户允许新增隐私档可嵌入LLM内核，LM Studio继续保留兼容。采用llama.cpp C API原生worker、ComfyUI私有管道入口、LMA内部JNI；买卖端加密/平台盲转，任务数据加密而模型保留原生加载，不使用VM/RAM盘/常驻第二份模型。输入准备和密文交付不额外占GPU锁，控制与大数据通道分离。内存/性能为待实测验收预算，完整链路、二进制协议、媒体、恢复及PE-01—PE-08见[完整实施方案](../技术开发/附录-低开销隐私执行完整方案.md)。当前尚未实现或通过设备/密码/性能验证。

本地隐私目标修订（2026-10-29）：用户将当前目标收敛为拦住初级/中级用户的日常查看与普通工具读取、增加本地拦截成本，不以高级内存分析为验收目标。首期推荐原生低权限隔离、任务级密文工作区及文件/日志/引擎API出口封闭；TEE/保密GPU不是此前提，普通VM只作可选评估。这是独立的本地防护策略，不新增服务模式、不把普通端改标ATTESTED_CONFIDENTIAL；原有硬件增强保留为独立远期能力。既有“基础档所有者可见”表示技术上仍可能访问，不表示默认向提供方展示内容。具体动作与LP-01—LP-14见[本地防护规范](../技术开发/附录-本地内容隐私防护与分级验收.md)，全部待实现/未执行。

完整深化与实施细则见[白皮书阅读导航](../白皮书/00-阅读导航与需求基线.md)和[80项逐项实施规格](../白皮书/15-需求逐项实施规格.md)。本文件保留快捷需求入口；v3.0新增详规、契约和追踪，不代表软件已实现。

C2C约束：设备由用户自愿挂牌，卖家自主定价/时段；订单绑定实际卖家，平台收明确佣金。同单只可在同卖家已披露设备内按约重派，跨卖家结束原单并经买家确认新单。资金与责任见[交易规则](../交易/C2C交易与市场规则.md)。

本次要求加密数据面必须有买方本机/可信LAN程序，向应用提供OpenAI/Anthropic兼容入口；平台只中转密文，卖方程序解密后交内置Sub2API类内核执行并加密返回。网页只承担目录/合同/支付，不能用网页直传平台替代本地程序。SSE/工具/媒体/错误同样加密，增强档还须保护解密及转发内核，见[完整协议](../协议/统一API与本地加密网关需求.md)。

当前供给内核路线：Windows/Linux隐私LLM以llama.cpp原生worker封装，LM Studio的lms CLI＋llmster＋runtime保留兼容；图像/视频/音频/3D以完整ComfyUI原生内核及有限节点白名单封装；Android基于LMA源码二开。Linux原生双引擎保留。详见[内核封装与替换规范](../技术开发/附录-供给端内核封装与替换规范.md)，当前均设计待实现，第三方许可/实机证据未取得。

## 目标、用户与可见性

适合希望平台不保存创作素材、代码上下文、提示词和生成结果的买家。基础档须信任指定执行环境；本轮在此之上落实针对普通查看/日志/API/抓包/简单改包的本地防护，默认不给提供方UI显示正文。若要求对恶意主机管理员的强保证，仍须独立增强档，不能凭传输加密或隐藏界面获得标签。

| 信息/能力 | 买家 | 平台 | 基础档执行节点/所有者 | 增强档供给者管理员 |
| --- | --- | --- | --- | --- |
| 提示词、输入图片/代码、输出内容 | 可见 | 不可见 | 处理时可见 | 不可见，限已验证保护边界 |
| 明文内容密钥 | 本地管理 | 不持有、不托管恢复 | 执行时可用 | 不得取得，仅受保护执行端可用 |
| 付款、预算、公开 SKU、对象大小、时间和区域 | 本人范围可见 | 必要范围可见 | 履约必要范围可见 | 必要运维元数据可见 |
| 内容预检与规格验收 | 本地执行 | 只能核验公开约束、签名与回执 | 执行端落实政策 | 由批准且被证明的运行代码落实 |

密文大小、时序、所选模型、计费数量、参与者和错误码可能泄漏使用特征；本项目不承诺匿名、隐藏流量特征或消除所有侧信道。买家本机被入侵、主动泄露、恶意基础档执行者、服务拒绝也不由普通端对端加密解决。

## 基础档端点与客户端要求

供给端覆盖Windows/Linux隐私LLM原生llama.cpp worker、LM Studio CLI兼容体系与完整ComfyUI环境，以及Android基于LMA二开的原生模型适配器；文本/图像/视频/音频/3D按模型、配方、环境与设备证据分别上架。LM Studio/手机的本地模型不属于上游订阅转供，仍需引擎/权重许可；流式分块与计量按本页及多端专项独立验证。

GPU 服务端点是买家加密端与供给者 Runner。获授权 API 服务端点是买家与 A 的本地 Relay，Relay 解密后调用获准的上游；A 与上游服务商会看到内容，必须逐项披露。若在平台凭证库/网关解密再转发，即使到上游用了 TLS，也应归为明文模式。

买家网页可用于目录、订单和付款。本版加密数据面必须连接买方本地/可信LAN程序，不采用平台网页直传替代；对包含恶意平台发版/换钥的承诺，必须有用户能独立核验的本地客户端/SDK、发布物验证和独立端点密钥确认。产品须显示客户端保证范围，不能把两种前提混成同一个安全保证。平台签名的公钥目录只能证明目录来源，无法单独阻止平台自己换钥。

供应者设备认证密钥与内容接收密钥分离；内容密钥不得由平台生成或备份。首次使用通过已核验伙伴证书/独立渠道确认指纹等建立信任；后续绑定身份和密钥版本，轮换提供旧钥签名链及撤销检查；首次信任和恢复均明确显示。密钥突变、过期、撤销或不符预期时停止，不弹出默认继续的降级按钮。

## 输入、结果与流式协议合同

当前优先PoC为libsodium sealed box封装每对象/方向独立流钥、secretstream认证有序记录及独立Ed25519身份签名；sealed box本身不认证发送者。HPKE只保留独立备选suite，不混用字节格式；具体库/绑定/向量与独立评审未冻结，不表示推理直接处理密文。

每个输入对象使用新随机内容密钥；密钥只封装给已确认接收端。输出密钥独立，封装给买家公钥。对象上下文绑定 work_item_id、合同哈希、内容版本、方向、接收端/key_id、对象序号与分块序号；重试不得复用相同密钥/nonce 组合。签名清单把密文哈希、数量、总字节和身份/合同关联起来，防掉包、乱序、截断、跨订单重放。实现须通过库测试向量和独立安全评审，不能自创加密算法。

平台对象仓只存密文和不敏感清单；明文哈希放在密文内，避免对可猜提示词做公开字典比对。不产生明文缩略图、内容搜索索引、服务端预览、调试日志或崩溃上传。文件名、元数据和错误消息不得夹带提示词、本地路径或密钥。

流式 API 使用单独版本的双向加密分块协议，绑定流 ID/顺序/结束标记；重新连接不能复用 nonce，终块丢失不得显示完整成功。用量回执与流内容分离。基础LLM发布须具备本地还原JSON/SSE的双协议能力；各SKU的流式计量/预算和支付时序分别验证，获授权API另受许可门槛约束。文件交付先实现不能被宣称已完成全部网关范围。

## 报价、执行与故障流程

1. 买家选择公开 SKU、模式/档位、区域与预算，平台生成合同与 `EncryptionIntent`，给出一个已准入接收端身份及公钥。意向有效期初拟 15 分钟，不等于占用 GPU；不得把输入密钥发给整个供给池。
2. 买家确认身份；增强档还需按下一节完成证明。买家本地执行文件/参数预检，加密后上传。报价只包含非敏感规格；不得把 prompt 放进 `/quotes`、埋点或普通异常日志。
3. 输入密文就绪后建立初拟 90 秒支付准入，重新核验接收端、能力、授权与容量。任务租约才赋予节点取密文/解密执行的权限。端点参数或政策检查失败则按已披露规则失败处置，平台不能伪称已经在付款前审核过明文。
4. Runner 检查合同、执行授权和密文完整性，在本端/增强档保护区内解密、校验、执行。结果在离开端点前加密；编码器、缩略图、临时盘同样遵守该档位边界。
5. 平台核验有效 token、签名清单、密文对象完整性并发布 `DELIVERY_AVAILABLE`，这只表示可验证的密文到达。买家端解密并检查格式、尺寸、数量、完整性，发出签名接受或拒绝回执；平台不直接解码密文。
6. 按真实支付合同处理最终收款/退款，依据有效接受证据产生唯一供给应付。付款、传输完成、本地验收分别展示。

同节点恢复按原订单/上下文幂等处理。换节点必须由买家端重新确认接收端，再重新封装输入密钥或重加密；新接收端、新内容版本与新尝试绑定，旧租约撤销。不允许平台持有“万能恢复密钥”来自动重派。初拟买家补封装等待不超过 120 秒且不延长原履约总时限；买家离线无法完成则失败退款/释放授权，不能自动转明文或跨区域。

## 增强档：平台和显卡所有者均不可见

增强档的解密终点是受保护的执行环境，而非供给者普通进程。买家可验证的证明至少绑定：新鲜随机挑战、CPU/GPU及必要互联保护、固件/驱动、安全/调试状态、工作负载和模型/工作流度量、接收端公钥、有效期与撤销状态、允许的输出/网络策略。硬件证书真实不等于当前整条工作流安全。

买家或独立可信验证/密钥服务按买家策略验证，平台中转控制面不得同时拥有绕过策略放钥的权限。钥匙只有证明合格后才释放到绑定的保护区；证明超期、环境更新、重启、调试开启、度量变化或证明服务不可用时，拒绝新输入/停用对应能力，不能降级为基础档。

保护区必须覆盖 CPU 预处理/解密、GPU 通信/内存、推理、视频编码、磁盘缓存、结果加密与日志/转储；禁止向不受保护的插件、外部内容审核 API 或普通 FFmpeg 进程导出明文。需要外部处理时，整个声明必须重新评审并向买家明确改变可见方。

禁止本地 Docker、WSL、虚拟机的工作区约束继续有效。只研究符合约束的原生/专用整机路径；若某方案依赖被禁止环境，当前方案不实施。官方存在专用裸机保密计算路线，也依赖合格整机、租户接管和信任配置，不能把普通 Windows 上的 ComfyUI 壳等同于该能力。普通进程、DPAPI、HTTPS、文件加密、GPU 独占均不能代替上述验证。

候选硬件未指定，兼容性未证明，增强档默认不可售。平台管理员若仍能管理保护区软件并读取明文，同样不满足“平台不可见”。本版本增强档只规划本地 GPU 服务；外部模型 API 不自动获得该保证。

## 验收、支付与隐私争议

初拟本地验收窗口为密文可下载后 120 秒；实际窗口须被可用支付路径覆盖。默认策略：买家签名接受后才标成功；超时无回执转 `UNVERIFIED`，不伪造接受，也不以沉默证明内容合格，按合同退款或释放未结算授权。针对恶意拒收/频繁失联可限制后续接单，不能凭怀疑自行补扣。

退款型预付、可履约授权后结算等路径，只有实际支付产品支持且演练通过才选用；不假定 Machine Pay 能无限期持有预算。买家拿到密文且本地持钥后可能已解密，平台无法用撤销下载追回内容。加密不自动带来公平交易或算力真实性证明，平台须限定风险预算。

有签名接受回执时，按成功任务/可核验 API 用量计费。无接受回执不计成功成交结算，计算成本按买卖双方事先公示规则分担；只有平台过错或明确限额保障才产生独立平台补偿；不能把客户未验收强行计成成功服务收入。缺乏证据时的损失分担必须在上架前签定。

买家可只披露某个坏包、特定字段或脱敏截图供争议审查；需生成独立授权和证据副本，不上交整批历史密钥。拒绝披露时客服可判断身份、时序、密文完整性等技术事项，不能声称裁定了图像内容或提示词遵循程度。平台无后门解密入口。

## 内容治理、留存与退出

平台继续审核身份、许可、公开服务类型、预算、地区和滥用元数据；可解释的内容政策在执行端落实。基础档仅向愿意承担处理责任的可信准入端开放；增强档将政策代码纳入证明。若某服务必须平台人工看到输入而无法满足加密合同，则该 SKU 不开放此模式。

平台密文输入终态后 24 小时删除，密文结果默认 7 天；节点基础档成功交付后 1 小时内清理，失败缓存终态后 24 小时、离线重连后 24 小时内补清。增强档任务结束释放密钥并执行可验证范围内的清理；无法承诺硬件之外恶意系统绝无副本。交易凭据不包含内容密钥，按正式留存政策另存。买家丢失私钥无法由平台恢复历史结果，界面必须提前说明并提供本地备份指引。

验收至少覆盖：平台抓包/对象/日志无明文与密钥、端点替换拒绝、篡改/乱序/重放拒绝、重派需买家放钥、无回执处置、选择性举证、证明失效拒绝、CPU/编码等明文逃逸检查；增强档必须在真实合格硬件上验证，mock 只验证接口分支。

技术参考：[RFC 9180](https://www.rfc-editor.org/rfc/rfc9180)、[NVIDIA Attestation](https://docs.nvidia.com/attestation/)、[专用裸机模式及信任边界](https://docs.nvidia.com/confidential-computing/bare-metal/dev)。适用性与核对记录见[资料说明](../资料/三模式技术依据-2026-10-29.md)。

## 本次内核路线对本模式的约束

本模式下的执行环境由提供方主动选择并经平台批准，Windows LLM用CLI体系、媒体用完整ComfyUI/有限节点，Android用LMA源码二开。环境摘要进入合同/当前执行授权，既售任务或有效租赁期间不可安装节点/替换内核；更新先停新单/排空。基础加密仍对设备所有者可见，增强需覆盖全部实际组件的真实证明；Android整卡/默认增强限制不变。

## 当前端对端链路的发布要求

输入/输出分别由发送端生成独立随机流钥并封给对端确认公钥，平台无内容私钥/万能恢复钥；首次信任、轮换/撤销/恢复及静态接收钥不保证完整前向保密均需披露。PREPARED只提供加密绑定上下文，输入/资金/许可/容量通过才ISSUED；平台不核私密正文或AEAD，执行端本地检查。真停算/清理后释放显卡，原密文补传/回执按独立交付权限继续。

BINARY_STREAM_1与JSON_COMPAT分档，前者须新增channel协商/版本和真实互操作证据；END本身为TAG_FINAL且标准协议终态合法才完整。只补传原密文，丢状态不盲重跑，不把中断SDK流拼成新结果。买方完整认证后Range从本人缓存提供，LOCAL_SEGMENTED_1与网络流分别验收；64MiB明文/66MiB密文及有界缓冲均按冻结档位执行。

具体消息、AAD、sealed/签名、回执与E2E-01—20见[加密技术权威源](../技术开发/08-端到端加密协议与密钥实现设计.md)。本轮未实现/未测，不增加第四模式，也不恢复本地虚拟化、部署或可观测性范围。
