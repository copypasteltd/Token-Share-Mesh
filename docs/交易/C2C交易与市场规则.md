# 算力共享平台：C2C交易与市场规则

P11｜v3.0｜2026-10-29｜用户明确确认的商业定位。全体显卡和手机供给来自用户自愿挂出的闲置设备；当前均为需求，尚未产生实单。

完整深化与实施细则见[白皮书阅读导航](../白皮书/00-阅读导航与需求基线.md)和[80项逐项实施规格](../白皮书/15-需求逐项实施规格.md)。本文件保留快捷需求入口；v3.0新增详规、契约和追踪，不代表软件已实现。

## 1. 不可变的业务定位

卖家A拥有或合法使用闲置显卡/手机，自主决定共享时段、可售能力、价格和是否接新单；买家B向A购买模型服务或受控GPU时段；平台提供市场、规则、匹配、软件、计量、交易证据、信誉和争议处理，并按公示合同收佣金/服务费。

平台不购买设备或闲置时间，不买断用户额度，不建立自营供给池，不以平台为算力服务卖方向B再销售。个人卖家与买家可由同一账户分别担任，但同一订单不得自买自卖套取补贴或信誉。设备或接口可用不代表具备合法上架资格；自愿共享始终需要知情授权和明确退出控制。

技术上平台代为报价、调度、传输或核验，不改变已披露的卖家身份。平台承担其自身技术、资金接口、审核和规则义务；不因称为C2C而概括免责，也不默认替每个卖家承担所有设备故障损失。

完整范围继续包括明文、端对端加密基础/增强两档、受控整卡租赁，以及Windows/Linux＋GPU＋ComfyUI/LM Studio和Android真实执行端。增强能力只由有真实合格证据的用户设备挂牌；平台专用硬件供给不作为此C2C业务的默认补充。

## 2. 挂牌与自主经营

卖家自助注册并提交身份、设备使用权、许可与数据承诺、收款关系；经必要核验和真实基准后可挂牌，不把受邀企业供应商或平台采购合同设为个人参与前提。试点可限制参与人数、地区和已验证能力，但参加者仍为自愿报名的用户，不能用平台自营机器替代市场供给证明。

每个Listing记录seller_id、listing_id、设备/可选设备集合、模式/隐私、模型/工作流/量化/版本、真实基准、区域、时段、容量、排队与截止、挂牌价、接单策略、退款/争议和费用版本。两引擎和多种挂牌可以共享一个GPU，但不得被重复售出；手机按真实任务能力挂牌，不伪装独立显卡租赁。

卖家自行定价。平台可给参考价，或在卖家显式授权的范围采用自动定价；不得静默修改挂牌价、抽佣或已接订单。平台建议价不构成保底收入。价格/时段变更只影响未来订单；活动订单继续按原合同，暂停接单应排空，强停需展示退款/责任后果。

商品详情显示卖家身份标识及依法应公示的信息、设备/能力证据、最近按时交付率、样本量和观察期、价格/等待及隐私可见方。不得公开不必要的身份证号、家庭精确位置或私人文件。无历史数据明确标注新卖家，不生成虚构好评和收益。

## 3. 买卖合同与匹配

订单必须绑定唯一买家和卖家，以及listing/价格/费率/退款/隐私版本。平台服务协议分别约束平台与用户；服务交付由A与B之间的订单合同约束。支付、账单、界面和客服均可追溯同一seller_id，平台运营不能在已付订单内后台替换卖家。

买家可直接选择卖家，或要求平台按价格、时限、地区、模型和隐私匹配。自动匹配先确定实际卖家并向买家确认，再形成报价/付款；即使已有自动购买预算，也需有可核验授权覆盖实际卖家与合同，不能用空白“平台任意替换”掩盖交易对象。

初版每单只与一位卖家成交，不混合多卖家的部分结果或租时。在同一卖家预先披露的合格设备集合内，按原规格、区域、隐私和总期限最多一次重派；基础加密还需买家重新确认端点和放钥。卖家只有一台合格设备时，不假定总有备用节点。

跨卖家切换：原单按失败/取消/已用部分规则结束并退款或释放未用款，买家确认新卖家和报价后创建新单；两单相互关联且不得重复计费。自动重新购买只可在买家事先明确授权的总预算、候选范围和次数内执行。初版不实现隐式跨卖家履约迁移。

## 4. 收费、卖家收益与平台收入

成交总额GMV、卖家服务收入/净收益、平台佣金收入、支付通道费用、退款、补偿与实际到账分别记。GMV不是平台收入；卖家成交额不是平台采购成本。正式财务税务确认和开票责任须按实际主体/合同核定，不凭产品名称作会计或税务保证。

初版建议仅向卖家按订单收成交佣金，买家总价等于其确认的卖家服务价；具体佣金率尚未确定。任何新增买家服务费、固定费用或补贴均需下单前明示，不隐藏进用量或取整。渠道费由谁承担及是否可退亦须冻结，不能事后从卖家收益任意扣除。

建议计量规则：金额为整数分；以订单最终保留的合格成交额B为佣金基数，费率r为整数基点，`佣金分=floor(B×r/10000)`，整单累计一次计算。分期事件不逐事件另取整；部分退款后以保留基数重算并追加佣金冲正，不能每次单独计算退款佣金造成舍入差异。该方案须结合通道能力和正式费率再冻结，不能直接当现行收费。

`卖家可结算净额 = 合格成交额 − 平台佣金 − 明确由卖家承担的渠道费/依法代扣项 ± 有依据的调账`

`平台单位贡献 = 实现佣金及明确服务费 − 平台承担的支付/网络/存储/验证/补偿/反欺诈/变量客服与获客成本`

卖家净额还未扣卖家自己的电费、损耗、网络、维护和机会成本，不宣传为净利润。平台不承诺无人购买时保底收益、最低利用率或回收全部闲置时间。

## 5. 资金路径与结算

目标为通过允许此业务、卖家类型和资金流的持牌支付渠道，识别实际卖家/收款人并完成收款、退款、佣金及卖家结算。商户/子商户/个人收款资格、分账/结算、争议款处置及渠道费用均为待核事项；不假设单一平台商户的A402收款自动覆盖C2C个人卖家。

渠道若不支持该C2C服务类别或个人卖家，不把平台改成默认转售商来绕过；暂停相应收费试点，保留明确标识的开发沙箱。禁止先将所有用户货款收进平台普通账户，再用个人转账模拟已获准的市场资金结算；不自建可提现/可转让余额钱包或托管承诺。

内部SellerSettlement只记录渠道交易及卖家应结款/费用/退款证据，不是平台自有可支配资金，也不等于已到账。付款、履约、接受、争议、渠道可结算与实际到账分别状态化；未知先查原流水，不重复收款、退款、分账或出款。

初拟7天争议观察、每周结算和最低10元均是待核策略，须与获准渠道、用户权利、退出尾款和税费安排一致；不是平台无限扣留用户款的授权。结算前后退款，分别冲正卖家款、平台佣金和可退/不可退渠道费；无权直接扣外部账户。已经到账的卖家退款与追偿按事先合同和渠道权限处理。

## 6. 责任、故障与争议

| 场景 | 默认处理方向，具体须写入公示规则和订单 |
| --- | --- |
| 卖家设备不实/许可不匹配/自用抢占/主动强停 | 停新单；买家按未交付或不可用部分退款；卖家收益冲正/处置及申诉依规则，不自动由平台保底购买 |
| 平台调度、网关、错误扣款或规则执行故障 | 平台处理自身责任、退费和约定损失；平台赔付独立记账，不伪造卖家正常成交 |
| 买家撤销、输入不符或已用租时 | 按购买前已确认政策处理，不能把已交付合格服务或有效租时一律视为卖家过错 |
| 双方网络故障/原因不明 | 先保存技术证据、停止扩大费用和损失，按证据与争议流程决定，不凭某一方自报直接判定 |
| 加密无接受回执 | 不把密文到达当验收，不计成功成交结算；按现行期限退款/释放，卖家计算成本按事先约定的风险分担处理 |
| 发生跨卖家重选 | 原单与新单分开，实际卖家、价格和数据接收方须重新确认 |

不把每次成功上传后的未接受都转为平台采购补偿。只有明确的有限试点保障或平台过错，才按公示适用条件与上限支付平台补偿；其资金来源、触发证据、最高预算及申诉必须明确。其他情形由买卖双方事先确认的规则分担，禁止无限兜底或事后单方转嫁。

加密基础档执行卖家仍能见明文，明文模式平台/卖家可按授权处理，增强档需合格设备真实证明。用户身份经核验不代表端点绝对可信，评价高也不能替代增强档安全证据。平台不能因争议取得历史私钥或开设解密后门。

## 7. 信誉、市场治理与留存

自助个人供给、挂牌、定价、基本信誉/评价和投诉申诉属于C2C基础能力，不能整体放到以后“开放市场”阶段。高级反作弊、跨地区扩容可以分期。信誉仅来自真实订单与可核验履约：样本、周期、按时交付、退款原因、有效租时及争议分开；买家恶意拒收/拒付和双方关联刷单同样治理。

真实成交可评价，保留评论、卖家回复和申诉证据，不以付费删差评或平台自造评价营造信誉。违规内容/隐私信息按适用规则处理并留痕，不能把一切差评自动当违规。已撤销/退款/未履约订单的评价资格及展示方式须预先公开。

身份与资质核验、信息公示、平台规则、评价及必要处置等义务不能以C2C概括免除；个人是否须登记、税务/信息报送及具体支付资格按实际服务类型和经营情况核定，不默认所有个人免登记免税。[电子商务法](https://www.samr.gov.cn/zfjcj/tzgg/art/2023/art_d337c3291e8b40459ca03dea54395856.html)、[2025修正网络交易监督管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2025/art_4b47c79b8d994a42bba4835997688faa.html)

适用电子商务法时，必要商品/服务信息和交易信息自交易完成起至少保存3年；其他适用义务或合法保全要求更长时另行处理。订单合同、卖家/挂牌、价格/费率、计量/验收、支付结算和争议证据与原始素材分开保管；不能以3年交易留存为由把全部prompt、照片或内容私钥也保存3年。素材继续执行各模式的最小留存和清理政策。

## 8. 必须验证的C2C场景

卖家A自助申请→设备真实基准→自主挂牌→买家B确认A和费用→获准渠道支付→A设备履约→对应验收/租时计量→卖家应结款及平台佣金分账→获准结算到账→评价与争议。真实买卖双方及到账证据缺失时不报告C2C闭环通过。

必须拒绝：平台静默改价/抽佣、付款后换卖家、卖家挂牌他人设备、买家直改seller_id、退款后不退应冲佣金、把GMV全计平台收入、重复结算、平台普通转账替代渠道资格、评价刷单及无记录封禁。保持F01—F68并新增12项，共80项功能及同号主验收，通过现行F02/F07—F10/F16/F18—F21/F29/F30/F31/F53/F56等覆盖，见[功能](../02-功能需求与用户流程.md)和[验收](../05-验收测试与实施计划.md)。

## 协议网关不改变交易主体

双协议入口、Sub2API类内核及本地/LAN加解密只是技术通路，实际seller/listing、价格/费用、计量及获准资金路线继续绑定原合同。不能继承共享账户池跨卖家自动切换或充值余额收费；同卖家重试/跨卖家新确认、可信usage及租赁不重复收费见[协议专项](../协议/统一API与本地加密网关需求.md)。
