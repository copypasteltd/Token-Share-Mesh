P11｜技术v1.0｜需求v3.0｜2026-10-29｜未执行产品实现或验收。

本轮以[范围修订](../技术开发/附录-本轮范围与端侧选型修订.md)为准：小程序React/Taro优先、Web React/Vite；部署/HTTPS/运维和可观测性延后，历史相关模板不属于本轮交付要求。所有产品/真机/渠道实验仍未执行。

新增[成套技术文档](../技术开发/00-技术文档导航与实施基线.md)、SQL/接口实施映射、模块/开发任务/逐项需求追踪、内部适配器契约、默认关闭的配置样例、兼容验证矩阵及评审模板。需求仍为C2C、三模式/加密两档、多端与OpenAI/Anthropic标准数据入口，不增加默认钱包或平台自营供给。

在尚未发布的v3.0控制面草案中补全Lease必需字段resource_id/resource_lock_generation，并纳入签名上下文：job token防同任务旧尝试，资源代次防跨任务旧消息。由白皮书契约源数据生成；目前没有产品消费者，不将此称为向后兼容的已发布变更。正式冻结后再改必需字段须升级契约/profile并验证全部端。

补全Lease的capability/执行manifest引用和hash、not_before/issued_at/hard_deadline及lease_revision；progress从普通Ack细化为ProgressAck，CONTINUE携新的完整签名租约，STOP/NO_CHANGE不续权。客户端只接受同资源/尝试的更高有效版本，网络成功或普通确认不能延长执行截止。这仍是草案契约细化，无已运行旧版消费者。

密码实现优先评估成熟libsodium的sealed box/secretstream及独立身份签名。此为PoC方向，具体库版、封装/身份/向量/跨端/独立安全评审未通过；不能在白皮书中改成已批准密码套件。顺序认证流须先完整认证媒体到买方本地缓存才提供Range；未来随机分段须独立协议。

所有设计附件由项目scripts构建/核验。报告分别区分文档/JSON引用/SQL语法树/JS语法和真实数据库、设备、密码、资金的验收；后四类均未执行。原生环境约束与所有费用/资金/许可开关的门槛继续有效。

## 2026-10-29 供给内核路线修订

Windows LLM确定为lms CLI＋llmster＋实际推理runtime三层封装；Windows媒体确定为完整ComfyUI原生环境与图/视频/音频/3D独立能力包；Android确定为固定LMA源码二开。既有LM Studio桌面实例仅作显式兼容接入。Linux保留双引擎但独立做物理机验证。内核更新由提供方授权，受维护资源锁、排空、环境校验、能力复验和合格旧版回滚约束，不能接单时静默替换。

同一未发布控制面草案同步增加KernelBinding：CapabilityWrite必需内核环境引用/摘要，Service及ContractSnapshot必需允许的kernel_bindings，Lease/RentalAccess必需本次kernel_environment_digest。CatalogEntry补充KERNEL_ENVIRONMENT和NODE_ALLOWLIST类型，PublicSpec增加音频/3D的有限公开规格。技术适配命令的PREPARE/EXECUTE/QUERY/CANCEL/COLLECT/CLEANUP同样必需环境摘要；只检查schema不能替代授权、签名或实际进程身份核验。

新增内核环境/节点白名单schema和默认不可售策略；不可变环境载荷与准入/撤销状态分离，节点连同传递依赖在导入前校验。协议矩阵由8类扩为11类，增加Audio Speech、Audio Transcriptions和项目声明的Responses资产配方；协议用例由FW01—FW18扩至FW01—FW22，另有K01—K20内核验收设计。80项功能/80项主验收和56项开发任务的ID与设计状态保留。全部产品用例未执行，新增字段也尚无已运行消费者；正式冻结后变更须升级契约/profile并验证所有端。

权威源为[内核规范](../技术开发/附录-供给端内核封装与替换规范.md)、scripts/供给端内核数据.py、scripts/白皮书契约数据.py与scripts/技术开发数据.py，合订阅读器和机器附件由构建脚本重建。部署/HTTPS/可观测性继续延后。
