2026-10-29｜用户明确确认：标准C2C平台，显卡/手机均为其他用户自发为收益挂牌的闲置设备。当前没有实现、实单或设备验收。

## 已纠正的业务假设

平台采购服务后再销售、采购价与买家价双价账、默认平台自营/专用供给、只邀企业供应商、默认买断/保底购买及无条件失败计算补偿，均不作为现行产品依据。用户卖家自主报名、核验设备后挂牌/设价/设时段，用户买家购买，平台撮合/技术/规则服务收明确佣金。

三模式、两档加密及Windows/Linux双引擎、Android真实供给仍在完整范围。增强档只能在合格用户设备证据成立后售，不用平台专用硬件替代C2C供给；上游订阅许可仍独立门控。

## 需求同步

- 68项功能/68项同号主验收保留，仍全部设计/未执行；F29基本信誉/评价/申诉从P2调整为P0，P0=60、P1=3、P1-AUTH=3、P2=1、P2-AUTH=1。

- 重写[C2C可行性评估](需求可行性与商业风险评估-2026-10-29.md)；[旧评估](历史评估-v2.0错误交易假设-2026-10-29.md)及[v2.0待决项](v2.0需求变更与待决事项.md)标历史。

## 商用前待核

| 事项 | 具体待决与默认门槛 |
| --- | --- |
| 个人卖家资格/信息 | 身份、设备权属、必要公示、服务经营/登记/税费/信息报送适用条件；不因个人身份自动豁免 |
| 正式C2C资金路线 | 渠道是否允许此业务和个人卖家，实际卖家收款、佣金、退款与结算资格；未核准不收费，不改平台转售绕行 |
| 佣金与渠道费 | 费率/费用承担/取整/退佣/最低额/结算和退出尾款，均需公开后冻结；当前算例非实价 |
| 责任和限额保障 | 卖家强停、买家拒收、平台故障及未知原因的证据/损失分担/申诉；平台保障独立预算，无无限兜底 |
| 评价及市场治理 | 真实单评价资格、回复/投诉/申诉、关联刷单、必要处置，不能自造好评或付费删差评 |
| 引擎/模型/上游许可 | LM Studio具体发行物对外收费用途，ComfyUI/节点/权重/LoRA及订阅下游许可；欠证不分发/上架 |
| 真实供给和成本 | 自愿卖家设备真实基准、可用时段、按时率、冷启动/清理、费后收益及平台佣金贡献；无实测不预告挂机收益 |
| 加密与增强 | 基础档端身份/可信买家端/回执风险；增强完整原生硬件代码路径与放钥；无合格用户设备不开标签 |
| 多端/媒体与计量 | 四桌面组合、至少两Android真机逐模型/配方/模式验证，可信usage、租时及支付对应；开发目录不当通过 |
| 数据与交易留存 | 法定交易/服务信息留存和素材/密钥清理分离，按平台及买卖角色确定数据与内容责任 |

尚未确定费率、签约/商户及财务税务安排、机型/模型、发布工期；不把这些待决项当已获授权。旧技术边界中仍适用的安全/许可/真机条件继续保留；与C2C冲突的交易假设以v2.1为准。
