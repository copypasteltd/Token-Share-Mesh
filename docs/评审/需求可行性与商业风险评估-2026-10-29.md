## 1. 核心结论

**C2C闲置设备市场具有可研究的价值。平台不需采购/持有设备或保底买入时间，用户可以自主变现闲置资源；商业成立条件则是买家愿意向其他用户购买、卖家费后收益可接受、平台佣金足以覆盖自己的服务成本。** 这三项目前都未取得本项目实证。

评估重点应放在自主挂牌、双边匹配、信任/信誉、计量、资金结算、争议及用户留存。平台技术标准化、代为调度或验收可以服务C2C交易，但不能把实际卖家隐藏成平台“货源”，也不能把GMV全计平台收入。

三模式、多端和增强档继续保留。Windows/Linux GPU＋受控工作流适合作为首个需求和成交验证组合；Android需要真机证明；基础加密需要买家接受设备卖家可见；增强档需要用户端真实合格硬件，供给稀缺性更明显。未经许可的订阅或引擎服务仍不能默认挂牌。

## 2. 对上一轮评估的具体纠正

| 事项 | 现行C2C依据 | 直接影响 |
| --- | --- | --- |
| 设备来源 | 用户自愿共享其闲置显卡/手机 | 不以自营、购置机器或平台专用供给池作为默认方案 |
| 服务买卖 | 用户A向用户B提供任务结果/可用时段 | 每单明确实际卖家，卖家对约定服务承担对应责任 |
| 挂牌和价格 | 卖家自主决定能力、时段、价格和是否接新单 | 平台可建议价，不能静默定价；不把平台采购合同设为参与前提 |
| 平台收入 | 明确佣金及服务费 | GMV、卖家净额和平台收入分别核算，不使用买低卖高的双价利润模型 |
| 平台成本 | 软件、网络/存储、支付接口、验证、客服、反欺诈、获客及自身责任 | 不默认承担设备电费/折旧或所有失败计算；有补贴/赔付时真实入账 |
| 故障重派 | 同卖家披露范围内按约重试；跨卖家重新确认新单 | 不能把不同卖家当作可静默互换的统一后端 |
| 市场准入 | 用户自助申请，必要核验/基准及渠道资格 | 小规模试点可以限量，但个人挂牌/基本信誉不是后置方向 |
| 风险承担 | 卖家、买家、平台、未知原因分别取证处理 | 不把C2C当平台全面免责，也不无条件保底购买卖家失败产能 |

## 3. 需求必要性与市场成立条件

### 3.1 卖家侧：为什么愿意持续挂设备

GPU用户可能希望在不用电脑的时段、夜间或空档赚取增量收入；手机用户可能希望在充电和Wi-Fi条件下利用闲置窗口。平台减少各自搭公网服务、寻找客户和收款计量的工作，是合理价值假设。

但卖家考虑的不只是电费：模型下载/磁盘、整机保持在线、噪声/发热、电池/设备损耗、安装信任、自用中断以及客服时间都会影响留存。需要自主开关/时段、成本估算、透明费用、可查询到账及容易退出，不能宣传“挂上就有订单”“保证覆盖折旧”。

卖家尚未自愿完成安装、基准和挂牌时，口头说愿意共享不算有效供给。在线但没有可售时段、尚未加载所需模型、已被租赁占用或没有合格收款资格，也不能当即时产能。

### 3.2 买家侧：为什么向其他用户购买

可能场景包括短时反复调参、指定开源模型/LoRA/工作流、少量批处理、轻量本地文本服务或不希望平台读取正文的任务。买家要得到明确的规格、价格、时限、实际卖家、可见方和退款处理；省部署、省等待或综合价格优势需要真实验证。

买家面对陌生用户设备时，通常还会担心稳定性、质量、数据复制和售后。平台的价值是让这些交易更可辨认、更容易执行和追责。API兼容或接口统一不能单独证明买家愿意迁移；便宜也不能自动抵消数据与停机风险。

已有云GPU、推理API及闲置GPU网络是替代方案，可以对照同地区、同规格/模型、质量、等待、可靠性、流量和全部费用；不能用不同档位的标价宣称必然便宜。[Runpod产品/价格分类](https://www.runpod.io/pricing)、[Salad共享GPU产品](https://salad.com/salad-container-engine-community/)

### 3.3 最大商业挑战是可成交的供需密度

同一地区、模型/工作流、隐私档、时间和预算下，买家是否能匹配到足够可信的在线卖家，比总注册设备数量更重要。不同显存、量化、后台可用窗口和地区使供给碎片化；高价高配卖家不一定匹配轻量低价任务。

建议先围绕一个可复用SKU招募自愿卖家和真实买家，同时允许符合条件的个人自助申请。平台提供统一配方、真实基准和清晰费用，有助于降低买家选择成本；它不意味着平台成为算力服务卖家。

| 方向 | C2C中的价值 | 核心限制 | 建议验证 |
| --- | --- | --- | --- |
| 明文标准任务 | 用户卖家交付明确结果，平台协助预检和技术验收 | 卖家/平台可按约处理内容；文件合格不等于主观有用 | 首个许可清楚、能复用的图像/文本SKU，真实成交与退款 |

## 5. C2C商业账：佣金是否覆盖服务成本

### 5.1 三本账分别看

`买家支出 = 确认的卖家服务成交额 + 事先明示的买家费用（初拟无）`

`卖家应结净额 = 合格成交额 - 平台佣金 - 卖家明确承担的渠道/依法代扣项 ± 有依据调账`

`平台贡献 = 实现佣金及明确服务费 - 平台承担的支付/基础设施/验证/损失/客服与变量获客`

GMV不是平台收入。卖家应结净额不等于含电费/折旧后的净利润，也不等于已到账。实际税务/会计确认、结算和开票须按主体和合同核定；平台没有交易时不默认给卖家支付采购款。

### 5.2 纯假设的佣金敏感性

以下全部是假设，**不是当前费率、行情、真实成本或用户收益预测**。假设每可收费GPU小时有效成交3.00元，平台承担支付0.03元、基础设施/验证0.08元、平台自身损失/保障0.04元、变量客服与获客0.12元，合计0.27元；卖家无另外渠道代扣。

| 卖家侧佣金率假设 | 每小时平台佣金 | 卖家费后应结、未扣自有成本 | 平台扣变量成本后贡献 |
| --- | ---: | ---: | ---: |
| 10% | 0.30元 | 2.70元 | 0.03元 |
| 15% | 0.45元 | 2.55元 | 0.18元 |
| 20% | 0.60元 | 2.40元 | 0.33元 |

提高抽佣会提高平台单笔收入，但降低卖家回报、可能减少挂牌或促成绕平台；不能只从平台一方算最优值。少数高成本争议会迅速吃掉多笔佣金，小额文本/手机请求尤其要检查支付、网络和人工成本。

继续假设每月固定成本3万元，15%情景需要约166,667个付费GPU小时覆盖。若每台同等设备每月720日历小时、30%可收费利用率，约需772台等效设备；这是同一假设的规模换算，不是启动门槛、注册用户数要求或实际预测。此前基于平台买卖差价的463台算例已退出当前依据。

### 5.3 小单与供应者收益

按整数分结算、整单向下取佣的拟议规则，成交仅1分的订单在15%假设下佣金为0，平台仍有成本。可以研究同一卖家明确规格/预算的批量订单或透明最低订单额，但需买卖双方确认及通道支持；不增加隐藏费、不逐token重复取整、不自建钱包或跨卖家混账。

卖家期间经济收益需从费后实际结算中扣增量整机电费/网络、损耗折旧、维护和自用机会成本；现金增量可与含折旧经济收益分开报告。手机需要持续负载后的实测，不能只看瞬时速度或注册数量。

平台可以研究明确的可选技术服务，但不能用强制套餐掩盖提高抽佣；广告/会员/高级服务也不是已验证收入。优先证明真实佣金交易的贡献和双方留存。

## 6. C2C最关键的风险卡点

| 风险 | C2C下为何突出 | 应对和收费前门槛 |
| --- | --- | --- |
| 双边冷启动/供给碎片 | 有设备未必有相同时间/地区/模型的买家，搜索无结果影响复购 | 按SKU和窗口测匹配/成交，招募自愿用户，不以总设备数宣传可售容量 |
| 个人卖家信任与伪造 | 设备、性能、模型、usage和独占均可被恶意自报 | 权属核验、固定配方/基准、外部挑战、样本与异常识别，信誉不等于保密证明 |
| 自用抢占/关机 | 用户可随时需要自己的设备，长期承诺不稳定 | 自主可售时段、接单排空、安全停止；按责任退款/信誉/申诉，无无限保活或强占设备 |
| 任意代码危害卖家 | 陌生买家可攻击私人电脑/文件/网络 | 原生受控应用/参数/模型，拒绝任意节点、Shell、路径与内网抓取；权限和清理测试 |
| 用户数据被卖家复制 | 基础加密卖家仍可见，删除回执不能证明无另存 | 明确披露与接收方、最小数据、许可/合同；机密需求只在对应安全证据成立时接入 |
| 加密拒收/双方串通 | 买家可已使用结果却不回执，卖家又可索赔/刷保障 | 不假成功；公示损失分担、关联交易识别、限额和平台自身责任，禁自动无限补偿 |
| 非法/侵权能力挂牌 | 用户自行上传许可不代表目标用途合法 | 引擎/权重/LoRA/上游/素材分别审查；C2C不绕订阅或引擎限制 |
| 个人资金资格和错误清算 | 单一平台商户收款不证明可代全部个人卖家结算 | 获准渠道确认实际卖家、收退款/佣金/结算；不普通账户归集再私人转账，未过不收费 |
| 退款后的卖家款/佣金错误 | 全退或部分退后仍抽全额佣金、卖家已到账难追偿 | 保留基数重算整单佣金，分账冲正及未知查询，责任/追偿公开，不随意外扣 |
| 价格竞争/绕平台 | 抽佣太高用户可直接交易，太低平台难覆盖支持 | 透明费用及持续有用的计量/付款/争议/版本服务，用留存和贡献验证费率 |
| 评价操纵/封禁失当 | 卖家可刷单、买家可恶意差评，平台可偏袒 | 真实单评价、样本期、回复/举报/申诉留痕，禁付费删差评和无解释长期冻结 |
| Android产能不实 | 真机后台、热、内存和用户自用影响持续交付 | 逐机型/配方验证，用户可停、默认充电Wi-Fi，不许隐藏云回退冒充本地 |
| 增强档供给稀缺 | 普通个人设备不能靠软件获得完整保密能力 | 保留研发目标，只允许真实合格用户端；不能借自营设备假称C2C已成立 |

## 7. 平台责任与资金不能仅靠命名解决

《电子商务法》对平台及平台内交易设有身份核验、规则、必要处置、交易信息保存和评价等要求；个人用户参与并不自动免除平台相关义务。个人是否需要经营登记、税务/信息报送及实际收款资格还要按活动与适用规定确认。[电子商务法](https://www.samr.gov.cn/zfjcj/tzgg/art/2023/art_d337c3291e8b40459ca03dea54395856.html)、[网络交易监督管理办法](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/fgs/art/2025/art_4b47c79b8d994a42bba4835997688faa.html)

因此建议平台不预设自己对每次停电都兜底，也不宣称“双方私下交易、平台一概无责”。按卖家、买家、平台及原因不明分别取证，遵守适用义务和公示规则。任何保障计划须有真实来源、触发、上限和预算，不能把无限补偿包装成C2C标准功能。

Machine Pay官方介绍提供按量收款方向，但未证明本项目已获个人卖家C2C收款、佣金及卖家结算资格。应优先核实与此业务相符的渠道路径，不能为了完成演示切换成平台转售模式。[Machine Pay官方介绍](https://aipay.alipay.com/products/machine-pay)

数据处理、内容治理、生成标识和上游许可仍需逐模式落实；平台只见密文也有账户/交易等元数据。适用法定交易留存与原始素材清理须分离，不能为保存交易证据而长期保留所有prompt或私钥。

## 8. 下一阶段的C2C验证方案

1. 找10—15位具体场景买家确认任务、替代成本、愿付价格和陌生卖家/隐私接受度；另找自愿设备用户测试费率后的挂牌意愿与实际共享时段。口头意向不算真实需求或产能。
2. 至少两位独立自愿卖家自助申请、以各自设备通过许可/基准并挂牌；买家看到实际卖家、价格/费用、能力/评价样本。试点限量可以，平台自有设备和企业采购不能替代证据。
3. 先验证一个SKU；每设备/拟售图像工作流先做30次样本，独立演练同卖家设备恢复和跨卖家重选。Android、各桌面组合和加密档位不互相替代验收。
4. 正式资金资格具备后，至少3位独立买家产生真实成交，累计建议100个有效受理任务，报告全部失败/退款及初步按时成功目标≥95%；真实卖家到账与平台费用对账一致。小样本不等于市场或SLA已成立。
5. 建议至少观察两个自然周，核买家复购、卖家持续自愿在线及费后回报、搜索成交率、平台贡献与工单。只有促销或保证补贴才持续的供给/交易不能当自然市场成立。

继续条件：买家复购、卖家费后收益与控制感可接受、平台佣金扣全部自身变量成本后贡献为正，资金/隐私无阻断问题。停止或调整信号：没有可匹配需求、补贴停止即无成交、卖家频繁强停、支持吞噬佣金、不能合法给个人卖家结算，或必须偷偷换卖家/降隐私才能交付。
