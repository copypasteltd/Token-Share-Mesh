# ADR-R001 原生工程与密钥契约

状态：已采纳实现方向，实际验证见 R001 证据；目标仍为完整源码交付。

| 决策编号 | 问题 | 决定 | 不足/后续 |
| --- | --- | --- | --- |
| ADR-R001-01 | dev/tests 位于单 Go 模块 dev/src/go.mod 之外，不能直接成为该模块的测试包 | Go 测试源随模块内包或 dev/src/tests/integration 存放；dev/tests 保存跨端入口/证据 | 不添加第二个 Go 模块或复制源码以绕过 internal 边界 |
| ADR-R001-02 | ApiKey 接口有label/fingerprint/多route，SQL草案缺失 | 在权威DDL和初始迁移补字段，移除单route_id，应用事务核每条路由归属/状态/期限 | 数组不伪称有外键；调用时必须再次核合同/路由资格 |
| ADR-R001-03 | 幂等精确重放和secret仅首次展示冲突 | 数据库只存HMAC摘要和公开指纹；幂等只存公开key对象，重放不新建、不重显secret | HTTP适配返回409 SECRET_ALREADY_ISSUED及原key引用，响应丢失先查询/撤销 |
| ADR-R001-04 | 普通异常可能泄漏连接串/密钥或把未知提交误判失败 | 错误类型的公开字段与内部cause分离；不自动重试事务，提交未知要求按原业务号查询 | 后续各支付/执行适配仍须专门处理UNKNOWN，不能靠generic retry补齐 |
| ADR-R001-05 | 本机无Go/PG，且禁止虚拟化 | 下载固定Go和EDB原生PG到runtime，Go摘要核官方值；PG记录首个TLS下载摘要并固定后续比对 | PG未声称另有发布者独立摘要；不安装系统服务、不改全局PATH |
| ADR-R001-06 | 文档基线过去假定产品源码为空 | 冻结设计状态与源码实施状态分开，核验器要求完整56任务实施登记 | 取消“必须0源码”的历史交付断言，不放宽需求/接口/门槛核验 |
| ADR-R001-07 | 通用后台重试可能重复资金或推理 | 持久任务只开放查询/删除/补清/资格到期/元数据通知；代次CAS+有限重试+事务inbox | outbox发布器、真实消费者和受控死信重放仍待实现 |
| ADR-R001-08 | EDB原生工具初始化UTF8集群时不支持含中文的自身路径 | 临时SUBST别名只指向本项目；先确认本次实例关闭再撤销自己的映射 | 这是文件路径别名，不是虚拟机；失败时保留映射供按实例恢复，绝不撤销其他映射 |
| ADR-R001-09 | 仅检查错误码字符集仍可能把大写原始内容写入队列 | 持久错误只接受固定枚举；退避次数取数据库记录，不信任调用者传入计数 | 后续消费者须把上游异常映射到有限代码，不能保存异常原文 |
| ADR-R001-10 | 后续轮次生成进度会覆盖旧轮次的待办语义 | 每轮收口保留完整56任务快照；当前进度另由顶层tasks维护 | 产物/证据文件须真实存在，任务完成必须清空对应待办且有验证证据 |

权威API/SQL的修订均修改人工源并重建，不直接改生成契约。真实产品主验收不随本轮源码或局部数据库测试自动改变。
