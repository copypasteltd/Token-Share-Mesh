# 开发轮次执行规则

用户要求：每一开发轮次先完成该轮所有未定事项与 TODO 的完整代码，再集中测试、调试。当前 R026 仍是同一全量代码轮次；源码保存和提交不是另开一轮。

| 阶段 | 编号 | 必须完成 | 进入下一阶段的条件 |
|---|---|---|---|
| 范围固定 | CF-01 | 列出该轮所有需求、未定事项、TODO、依赖、生产入口和测试源码要求 | 保留完整编号，不用已完成模块替换原范围 |
| 完整开发 | CF-02 | 完成范围内全部业务代码、跨模块调用、实际依赖接线、失败恢复与测试源码 | 清单逐项都有完整实现；空函数、占位返回和未接入的模块不算完成 |
| 统一测试 | CF-03 | 集中编译、静态核验、单元测试、集成测试和端到端测试 | CF-02 全部完成后才允许开始；不以子模块完成提前开放 |
| 集中修复 | CF-04 | 汇总测试问题并一次性补齐本批修复及关联改动 | 修复清单代码完成后统一回归，不边写单模块边调测 |
| 轮次交付 | CF-05 | 反馈实现编号、完整未完成编号、真实测试结果及剩余限制 | 未测试不写通过，源码检查点不写整轮完成 |

当前门槛为 `CODE_FIRST / DENIED_UNTIL_ALL_IN_SCOPE_CODE_COMPLETE`。完整范围继续为既有 56 个任务、222 个子项；DEV-55 明确延后，DEV-32 无真实证明时关闭。尚未完成的生产代码、实际依赖与测试源码全部保留。不得将本次局部源码保存重新命名为一个已完成的开发轮次。

代码阶段允许阅读、编写、代码格式化、文档生成和已授权 Git 源码保存；不执行编译、测试、核验器、数据库迁移、内核、模型、设备、APK 或浏览器验收。代码静态阅读中发现的遗漏可直接修改。格式化和源码保存不作为测试证据。

全部工作仍在本项目路径下完成。不调度本地 Docker、WSL、QEMU、虚拟机或模拟器。进入后续获准的统一验证阶段后，如使用浏览器，结束时关闭不用的标签页。
